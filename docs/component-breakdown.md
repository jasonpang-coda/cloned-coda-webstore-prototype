A reference for front-end engineers picking up or re-implementing this prototype.
Pairs with [`motion-tokens.md`](./motion-tokens.md) (motion system) and

## 1. Stack & conventions

| Aspect | Choice |
|---|---|
| Framework | Vue 3, `<script setup>` SFCs |
| Build | Vite 5 |
| Styling | Plain scoped CSS per component + global design tokens (CSS custom properties). **Tailwind 3 is installed but the components use hand-written CSS + tokens**, not utility classes. |
| Responsiveness | **CSS Container Queries**, NOT viewport media queries (see §4) |
| State | Singleton composables (`useAuth`, `useCheckout`) for cross-component flow state. `App.vue` holds demo data. No Vuex/Pinia. |
| Icons | `@material-symbols/svg-400` via `MaterialIcon.vue` (CSS mask + `currentColor`) |
| Colors | OKLCH for action yellow + bonus text + SKU card border + HDR tokens; sRGB hex for UI chrome |
| Directives | `v-ripple` (global, `src/directives/vRipple.js`) — click-point ripple on all interactive buttons and card divs |

**Conventions**
- BEM-ish class names scoped per component (`.sku-card__amount`, `.sheet__banner`).
- Motion uses **animation longhands** (`animation-name`/`-duration`/`-timing-function`), never the shorthand — a comma-containing easing token breaks shorthand parsing.
- Animate only `transform` / `opacity` (GPU). No animating `width`/`top`/`left` on hot paths.
- Token CSS is imported in `main.js` as **JS imports** (not `@import` in `style.css`).

## 2. Page composition (`App.vue`)

```
App.vue
├── DeviceToolbar          ← iPhone / Samsung / Responsive switcher (prototype chrome)
└── DeviceFrame            ← renders the chosen device shell; .device__screen scrolls
    ├── #overlay slot      ← non-scrolling overlay layer (z-index 40)
    │   ├── CategoryNav    ← z-0  (sticky bottom L3 nav; persistent — below the transient overlays)
    │   ├── NavDrawer      ← z-1
    │   ├── SignInLoader   ← z-2  (mobile: app loader; desktop: QR)
    │   ├── Snackbar       ← z-5  (success toast; above all sheets; screen-bottom framed, viewport-bottom responsive)
    │   ├── CheckoutSheet  ← z-4  (ORDER SUMMARY; bottom sheet mobile, centered modal on M+ responsive; hidden when the FCM Buy Now pilot below is on)
    │   ├── BuyNowBar      ← z-3  (FCM Buy Now pilot, `fcmPaymentSheet` flag — docked "Buy Now" strip, no scrim, page stays interactive)
    │   ├── OrderSummarySheet ← z-4  (FCM Buy Now pilot — Order Summary accordion + priced payment grid; BuyNowBar's BUY NOW promotes into this)
    │   ├── ItemSummarySheet ← z-4  (ITEM SUMMARY; bundle breakdown; morphs into CheckoutSheet on Buy Now. FCM: SKU info sheet via `config.itemSummary`, opened from a card's (i) icon; morphs into OrderSummarySheet on Buy Now)
    │   ├── ClaimGiftSheet ← z-4  (CLAIM GIFT / GIFT CLAIMED; gift-claim confirm + success views)
    │   ├── RegionSelectorSheet   ← z-4  (Select Region; search typeahead + continent columns; opens above the drawer)
    │   ├── LanguageSelectorSheet ← z-4  (Select Language; endonym list, active row check-marked)
    │   ├── SignInSheet    ← z-4  (SIGN IN sheet; no scrim; mutually exclusive with CheckoutSheet)
    │   ├── AccountPopover ← z-5  (YOUR ACCOUNT popover; no scrim; anchored below navbar)
    │   └── CommandConsole ← z-6  (dev `/` command palette; blurred scrim; floats above all overlays)
    └── NavBar             ← in-app top bar
    └── ResellerBanner     ← FCM only (v-if="isFilter") — compliance notice, full-bleed L3 surface
    └── <section id="cat-…"> × N, each: <Grid><Span size="…"> … </Span></Grid>
        1. StoryCarousel        (Span size="carousel")                       — no id (hero, not a category)
        1b. PlayerAccount       (Span size="content")        — signed-out only (v-if="!signedIn")
        2. BestSellerCard       (Span size="content")        id="cat-best-seller"
        3. BestSellerCarousel   (Span size="carousel" — header inset, list full-bleed)
        4. PromoBanner (countdown) + BundleSkuCard × 2        id="cat-bundle"
        5. GIFTS heading + GiftGrid → GiftSkuCard × 3         id="cat-gifts"
        6. PromoBanner + SkuList ("New Users Promo")         id="cat-new-users"
        7. SkuList ("CP", size="content")                    id="cat-cp"
        8. CategoryBanner + SkuImageList ("CP Deals" — new-user discount, image cards) id="cat-cp-img-newuser"
        9. SkuImageList ("Buy CP" — regular CP, image cards) id="cat-cp-img"
```

**Carousel sections use `size="carousel"`** — full **bleed** (edge-to-edge, no side padding) on XS/S phones, then centered 2/3 (8 of 12 cols) on M/L, same as `content`. Content sections (hero card, SKU lists, bundle) use `size="content"` (full width within the 12px gutters on XS/S, centered 2/3 on M/L). **BestSellerCarousel** is a hybrid: it sits in a `carousel` Span but pads its own header to the gutter (`.bs-carousel__header { padding-inline: var(--pad-m) }`, reset at ≥801px) so only the card list bleeds.

**Section ids** (`cat-best-seller`, `cat-bundle`, `cat-gifts`, `cat-new-users`, `cat-cp`, `cat-cp-img-newuser`, `cat-cp-img`) are the scroll-spy / scroll-to anchors consumed by `CategoryNav` (§7).

**Entrance cascade** — section `baseDelay` values:
`story 100 → account 180 → hero 250 → carousel 450 → bundle 550 → gifts 620 → promo 720 → cp 950 → cp-deals 1050 → buy-cp 1150` (ms). `CategoryNav` slides up last (~700 ms, `--motion-nav-enter`).

**Data** lives in `App.vue` (`stories`, `bestSeller`, `bestSellerCarousel`, `bundle`, `gifts`, `promoItems`, `cpItems`, `cpImageNewUser`, `cpImageRegular`, `categories`). Swap for API data in production. SKU items now carry an optional `rarity` (`mythic|legendary|epic|rare`) and `skuImage` (square product art, shown in the checkout thumb). `promoItems`/`cpItems` check `storeSkus.value?.promo` / `.cp` first (same override pattern as `cpImageRegular`) — a store can supply its own denominations via `skus: { promo: [...], cp: [...] }` in its store module, as Codashop does.

**Codashop's split-layout branch:** when `config.page.layout === 'split'`, the entire section stack above (from the story hero through `app__nav-gap`) renders inside `.storefront__col--main` instead of directly under `.device__screen`, with a sibling `.storefront__col--lead` holding `CompactHero` followed by `TrustBar` (gated on `config.identity`/`config.trustBar` respectively — both Codashop-only today). Section markup, ids, and data are otherwise unchanged. See [`grid-layout-system.md`](./grid-layout-system.md) for the wrapper CSS and the provide/inject `GRID_BARE_KEY` mechanism that keeps each section's own `<Grid><Span>` from double-nesting inside the split column. When `config.checkout.mode === 'inline'` (Codashop only), a `StepGamerId` section renders above the story hero and `StepPayment` / `StepZipCode` / `StepDetails` sections render after the catalog, all inside `--main`; `CheckoutSheet` is not rendered at all (`v-if="config.checkout.mode !== 'inline'"`) and `PlayerAccount` stays hidden via the existing `config.profile.showPlayerAccount` flag. When `config.page.catalogBoxed` is true (Codashop only), the New Users Promo banner + CP `SkuList` render inside a single bordered/rounded `.catalog-card` panel instead of two separate dividered sections.

### `TrustBar.vue` (Codashop only, `config.trustBar`)

Four-card trust-signal row — mounts directly after `CompactHero` in the sticky lead rail, at every breakpoint (previously it rendered as the first item in the wider main column; that placement is gone). Card 1 crossfades between publisher-logo pairs (`assets.content.publisherLogos`, chunked into pairs, `mode="out-in"` sequencing); cards 2/3 count up on mount via the new `useCountUp.js` composable (rAF, `easeOutCubic`, gated on `prefers-reduced-motion`); card 4 is a static payment-icons row (`assets.pc.*`). Below 801px of its own rendered width: a swipeable single-card carousel (pointer-drag + dot pagination + auto-advance). From 801px/1280px: a 2×2/4-up grid with column dividers.

**Self-scoped container query — the one exception to this repo's anonymous-`@container` convention.** `TrustBar.vue` declares `container-type: inline-size; container-name: trust-bar` on its root and queries that name internally (`@container trust-bar (min-width: ...)`), rather than relying on the shared `.device__screen` container every other component uses. This is required because the lead rail (~4/12 columns, ~400px at a 1280px frame) is reliably narrower than the screen — an anonymous rule would still fire its 2×2/4-up states off *screen* width. One consequence: those two states exist in the CSS but aren't reachable in the shipped page today (the rail never reaches 801px) — see `docs/grid-layout-system.md`'s Container Query System section and `docs/Handoff/trust-bar/README.md` §4.4/§7 for the full reasoning.

The 12px side inset below 801px (`--gap-grid-margin`) comes from the host wrapper (`App.vue`'s `.trust-bar-section`), not from `TrustBar.vue` itself — the component takes no side-inset prop and fills whatever box its host gives it.

`InfoTag.vue`'s delivery badge (card 3) uses its new `success` variant (`--bg-tag-success`/`--border-tag-success`/`--text-success-default`), alongside the existing `neutral` variant used by `CompactHero`.

ISO codes (`SG.svg` rather than `SG_-_Singapore.svg`) and expanded to full ISO coverage (~265 flags).

## 4. Responsive system (`Grid.vue` + `Span.vue`)

Container-query driven. `.device__screen` sets `container-type: inline-size`.

**Grid breakpoints:**

| BP | Container width | Columns | Gap | Pad-X |
|---|---|---|---|---|
| XS | < 641px | 8 | `--gap-grid-gutter` (8px) | `--gap-grid-margin` (12px) |
| S | 641–800px | 8 | `--gap-grid-gutter` (8px) | `--gap-grid-margin` (12px) |
| M | 801–1279px | 12 | 12px (Phase 3 — `--gap-grid-gutter-m` pending) | `--gap-grid-margin` (12px) |
| L | ≥ 1280px | 12 | 16px (Phase 3 — `--gap-grid-gutter-l` pending) | 16px (Phase 3 — `--gap-grid-margin-l` pending) |

**Token note (v0.29.0):** XS/S gap and XS/S/M pad-X now reference `--gap-grid-gutter` and `--gap-grid-margin` respectively. M/L gap + L pad-X remain hardcoded pending their own tokens (tagged Phase 3 in `Grid.vue`). ⚠️ The `carousel` Span's `-12px` bleed cancellation stays hardcoded — it must match Grid's XS/S `padding-left/right` literally.

**`Span` sizes:**
- `fluid` / `full` — `grid-column: 1 / -1` at ALL breakpoints (full width within the grid gutters). Used by NavBar.
- `content` — full width XS/S (inside 12px gutters); centered 8/12 cols (`grid-column: 3/11`, `max-width: 960px`) on M/L — **2/3**. Used by hero card, SKU lists, promo.
- `carousel` — **full bleed** on XS/S: `grid-column: 1/-1` + `margin: 0 -12px` cancels the Grid's side padding so the image reaches the screen edges end-to-end (width stays `auto`, so the negative margins expand it). On M/L (≥801px) it matches `content` exactly (centered 2/3, margins reset to 0). Used by **StoryCarousel** + **BestSellerCarousel**. ⚠️ the `-12px` is coupled to Grid.vue's XS/S/M `padding`.

### `src/composables/useWebPush.js`
Singleton (`globalThis`-pinned). Web Push opt-in state for the "post PWA installed" upsell surfaces (see `pwaInstalledState` above) — every surface binds the same `subscribed` ref, so flipping any one toggle updates them all.

| Export | Type | Description |
|---|---|---|
| `permission` | ref(String) | `Notification.permission` (`'default'` / `'granted'` / `'denied'` / `'unsupported'`) |
| `subscribed` | ref(Boolean) | Opt-in state, persisted to `localStorage` (`webstore:webpush`) |
| `justEnabled` | ref(Boolean) | Transient — `true` for 1.8s right after a successful enable, shared across every mounted touchpoint so their "just turned on" glow overlays play together off one timer |
| `isSupported` | computed(Boolean) | `false` when the Notification API doesn't exist |
| `isBlocked` | computed(Boolean) | `true` once permission is `'denied'` — the in-page toggle can't re-request it |
| `enable()` | async fn → Boolean | Calls the real `Notification.requestPermission()` — a genuine browser prompt, not a simulation (see the `simulateWebPushGranted` flag below for a dev bypass) |
| `disable()` | fn | Turns the in-store opt-in back off (can't revoke browser permission from the page) |
| `toggle()` | async fn | `subscribed ? disable() : enable()` |

The multi-store dev build never registers a service worker (`main.js`'s `__STORE_LOCKED__` gate), so there is no real `PushManager` subscription behind this — `subscribed` only tracks Notification permission having been granted once.

**`simulateWebPushGranted`** (boolean flag, `FLAG_DEFS`, console-only like `forceIosInstallSheet` — no toolbar UI) bypasses the real permission API entirely inside `enable()`, marking `permission`/`subscribed` granted directly. Exists because some browsers/sandboxes auto-deny `Notification.requestPermission()` with no real prompt ever shown, making the "on" state otherwise unpreviewable.

On every successful enable (real-granted or simulated), `enable()` also fires the existing global Snackbar (`useAuth.js`'s `showSnackbar()`) once, with copy from `strings.page.webPush.snackbarTitle`/`snackbarText` — reuses the house "big confirmation" toast pattern instead of a second mechanism.

### `src/composables/useDragScroll.js`
Click-and-drag horizontal scrolling for a scroll container, tuned for mouse. **Not a singleton** — call once per scroller, passing its element ref. Used by `BestSellerCarousel` and `CategoryNav`.

| Signature | `useDragScroll(elRef, { momentum=true, threshold=6, onScroll })` |
|---|---|
| Returns | `{ isDragging: Ref<boolean>, stop(): void }` |

Pointer Events + `setPointerCapture` (the drag never "drops" when the cursor leaves the element); `preventDefault` on `pointermove`/`dragstart` kills native text-selection and image drag (the old mousedown approach let grabbing a card image start an OS image-drag — that was the "hard to drag" bug). rAF-batched `scrollLeft`, EMA velocity, frame-rate-independent momentum coast, and a >`threshold`px move suppresses the trailing click (so a drag never opens a card / fires a tab). Ignores `pointerType: 'touch'` (native pan-x). Pair with `cursor: grab` + an `.is-dragging` class (`cursor: grabbing; user-select: none`).

### `src/components/base/BaseSheet.vue` *(v0.62.0)*
The one surface owning ALL sheet chrome — scrim, frosted panel, slide-up/responsive-modal motion, Escape-to-close, bottom scroll scrim (`useBottomFade`) — extracted verbatim from what used to be duplicated across `CheckoutSheet`/`OrderSummarySheet`/`ItemSummarySheet`/`ClaimGiftSheet`/`SignInSheet`/`RegionSelectorSheet`/`LanguageSelectorSheet`. Every one of those sheets now mounts `BaseSheet`, supplying only its own content via slots.

**Props:** `open` (Boolean, parent's own singleton), `isMobile`, `ariaLabel`, `scrim` (default `true`; `SignInSheet` passes `false`), `dismissable` (default `true`), `sizeHint` (`'tall'` 85% / `'full'` 95% / `'compact'` auto+95%cap / `'content'` auto+85%cap / `'content-full'` auto+100%cap — a content step declares its own height policy instead of the shell hardcoding one), `contentKey` (identity of the current content — a step id; changing it while `open` stays true runs a measure→resize→cross-fade engine instead of a slide transition, the mechanism that makes `PurchaseSheet`/`ClaimGiftSheet` morph between steps as one persistent panel), `duration`.

**Slots:** `#header` (falls back to a `title` prop), default (body, projected into `.sheet__body-wrap > .sheet__body` — `BaseSheet` owns the single `useBottomFade` instance, not one per consumer), `#footer` (scoped: `{ canScrollBody }`, so a footer can hide a "view terms" link once the content it jumps to already fits on screen), `#pre-footer` (a banner that sits behind/above the sticky footer — e.g. the loyalty-earn ribbon), `#panel-overlay`, `#overlay` (for a nested modal that must escape the panel's `overflow:hidden` via `Teleport`).

**The resize + cross-fade engine:** on a `contentKey` change while open, measures the old height, cross-fades body/footer to opacity 0, measures the new natural height after `nextTick`, then animates `height` old→new over `--motion-sys-duration-slow`/`--motion-sys-ease-standard` while the new content fades in — deliberately no opacity manipulation on the PANEL itself, so growing/shrinking the box reads as one continuous surface, never a swap.

Shared between toolbar, command console, overlay, and panel without prop-drilling.

**(v0.79.0) Authored-token resolution — new `packages/inspect-kit/src/core/authored.js`.** Previously every Colour/Layout/Typography field was reverse-matched from `getComputedStyle(el)` — a value-based *guess* that's ambiguous whenever multiple tokens resolve to the identical value (extremely common; a component's actually-authored token could lose an alphabetical tiebreak to an unrelated one, e.g. `--x-text-header-default` losing to `--x-brand-google` because both happen to be pure white). `resolveAuthored(el, cssProp, { kind })` instead reads the REAL winning CSS declaration: walks `document.styleSheets` (recursing `@media`/`@container`/`@supports`/`@layer`, gating `@media` on `matchMedia` and `@supports` on `CSS.supports`), collects every `CSSStyleRule` whose selector matches the element (skipping `:hover`/`:active`/`:disabled`-style state variants and pseudo-elements), hand-rolls cascade resolution — `!important` → specificity (approximated: ids/classes+attrs+pseudo-classes/types) → source order, since `getMatchedCSSRules()` was removed from browsers and no specificity package is installed — and reads that winning rule's **authored** `rule.style.getPropertyValue(cssProp)` text (the literal `var(--x-...)` reference, not the browser-resolved value). Handles the shorthand caveat (`background: var(--x-bg-sheet)` can't expand into `background-color` at parse time because custom properties are opaque until computed-value time — a `SHORTHAND_FALLBACKS` map retries the parent shorthand property name) and multi-`var()` compound declarations (`border: var(--border-weight-default) solid var(--x-border-card-default)` — a colour/length "hint" regex picks the right one out of several). Inherited properties (`color`, `font-*`, `line-height`, `letter-spacing`) walk up `el.parentElement` when the element itself declares nothing. Resolved fresh on every pick (no cache — inspection is low-frequency enough that a sheet walk is cheap). `field()` in `inspect.js` now tries authored first (`source: 'authored'`, the definitive answer), then flags a genuine raw literal with no `var()` at all (`raw: true` — real un-tokenised CSS, a design-system lint signal), and only falls back to the old reverse-value guess (now tagged `source: 'inferred'`) when literally no CSS rule in the (optionally inherited) chain declares the property. `InspectorPanel.vue` renders the distinction: a solid token chip for `authored`, a dashed chip with a small "?" superscript for `inferred` (tooltip lists the other value-equal candidates from `alts`), and a "raw literal" badge (gated on the field's own `warnable` flag, so non-warnable fields like Font/Weight stay quiet) for genuinely un-tokenised values. Typography fields (Size/Weight/Line height/Tracking/Font) now resolve real `--x-sys-font-*` tokens, not just the `.text-style-*` class name. The host's `tierRank` config (`src/main.js`, added in this same release) still exists purely to improve the *inferred* fallback's tiebreak — it ranks the semantic-tier prefixes (`--x-bg-/-text-/-border-/-pad-/-gap-/-radius-/-size-`, legacy `--border-weight-`, non-`sys` `--x-motion-`) at 0, every other `--x-*` (extensions tier) at 1, then `--x-sys-*` (2) → `--x-palette-*` (3) → `--x-ref-*` (4) — so a guess never surfaces further upstream than it has to, though it's still a guess, never the ground truth authored resolution now provides.

**Token engine (fallback only, as of v0.79.0):** `@coda/inspect-kit`'s `createTokenMap()` (core) / `@coda/inspect-kit/vue`'s `useTokenMap()` (Vue wrapper, invalidates on the host's `data-theme` attribute changing via `MutationObserver`) — enumerates all `--*` custom properties from `:root`, classifies by kind (colour / length / duration / easing / motion-pair), resolves colour tokens to concrete `rgb()` via probe element. Reverse-matches computed values to the most semantic token per the host's `tierRank`. Exports `matchToken(value, kind)` and `matchMotionPair(duration, easing)`. Motion fields (durations/easings on animations/transitions) still only ever use this reverse-match — `authored.js` covers style declarations, not keyframe/transition timing.

**Helpers:** `@coda/inspect-kit`'s core (`packages/inspect-kit/src/core/inspect.js`) — `resolveComponent(el)`, `collectStyles` (+ `a11y`, `props`, `assets` in return), `collectAnimations`, `replayAnimation`, `formatSpecMarkdown`, `formatSpecJson`, `elementSelector(el)`, `describeNode`, `containerContext(el)`, `buildHoverOverride(el, pseudo)`, `applyPressedState(el)`, `applyDisabledState(el)`, `contrastInfo(textColor, bgColor)`, `collectProps(instance)`, `componentUsageSnippet(instance)`, `collectAssets(el)`, `assetName(url)`. **(v0.79.0)** `resolveAuthored(el, cssProp, opts)` from `./authored.js`. Each state applicator returns a cleanup fn. (`fetchComponentSource` is no longer part of the package — it was Vite-specific; the host now supplies the equivalent via the `resolveSource` config hook.)

## 11. Gotchas (don't regress)

1. **`@import` after `@tailwind` is dropped** → token CSS is imported in `main.js`.
2. **No comma-easing in animation/transition shorthand** → use longhands.
3. **Running border needs `overflow: visible`**; compact card uses `overflow: hidden` — keep mutually exclusive.
4. **`animation-fill-mode: both` + a static `transform` conflict** — the badge runs a `pop` (scale) keyframe on the outer element, so its text must NOT carry a static `scaleX`. The badge text now condenses via negative `letter-spacing` (also fixes the tag being too wide). Generally: don't put a static transform on an element that has a transform keyframe with `fill-mode: both`.
5. **Container queries require `container-type` ancestor** — that's `.device__screen`. Silently no-ops outside it.
6. **`snackbar-drop` keyframe** must include `translateX(-50%)` in every step or the snackbar jumps right on exit.
7. **`position:fixed` in overlay** — breaks when any ancestor has `transform`. The responsive overlay uses `position:absolute` instead; the NavDrawer panel still fills the viewport because the `device--none` wrapper is `min-height:100dvh`.
8. **Drag-scroll click-suppression** — `useDragScroll` swallows the trailing click after a >6px drag (capture-phase) so a drag-scroll never opens a card / fires a tab. If you add a new click handler inside a draggable scroller, test with a slow drag to confirm it doesn't fire. New horizontal scrollers should use `useDragScroll`, not a hand-rolled drag.
9. **`useCheckout.openCheckout()`** — no-op unless `signedIn` **or** `guestVerified` (a guest who entered a valid Player ID via `PlayerAccount`). SKU cards are intentionally inert until the account is identified.
10. **`container-type` traps `position:fixed`** — `container-type: size/inline-size` establishes a containing block for fixed descendants (same as `transform`). The `.device__overlay` deliberately has none so the desktop loader/checkout-modal/snackbar can pin to the viewport. Don't re-add it unless an overlay component needs `@container` (none do today).
11. **New display text must condense** — any Hitmarker text needs `transform: scaleX(var(--hm-scale))` (left/right/center origin per alignment), or it renders ~18% too wide. For a pill/badge **with a background**, condense an inner text span — never the box (scaling the box squashes its padding). Recurring regression: Bundle + CategoryNav both shipped too-wide before this was added. See [`typography.md`](./typography.md).
12. **`v-ripple` on flex/grid containers** — the wave `<span>` receives `position:absolute; pointer-events:none` as **inline styles** in the directive, not relying on the CSS rule alone. This prevents a one-frame flash where the unstyled span participates as a flex item before CSS applies (repro: PC channel cards grew tall on click). Always set structural properties inline when injecting DOM nodes into flex/grid parents.
13. **`v-ripple` requires `overflow:hidden`** — the directive adds `fx-ripple` (which sets `overflow:hidden`) automatically. Do NOT add `v-ripple` to components that need `overflow:visible` for a border effect (e.g. `BestSellerCard` with `fx-glow-border--hdr` — the `::before` ring extends 1.5px outside the box and would be clipped).
14. **Module-singleton composables need ONE import specifier** — `useTheme` (and any composable that holds module-level reactive state) must be imported the same way everywhere. Mixing the `@/composables/useTheme` alias with relative `./useTheme` makes Vite's dev server resolve two module records, each with its own `current` ref: the toolbar's `setTheme` updates one copy (and writes `<html data-theme>`, so colours flip) while the content composables read another stuck on the initial store — "colours switch but content stays COD:M". `useTheme` now pins its state to a `Symbol.for(...)` on `globalThis` as a backstop; still prefer consistent relative imports.
15. **Screenshot capture strips frosted effects** — `useScreenshot` (modern-screenshot / foreignObject) cannot composite `backdrop-filter` (renders grey) or `mask-composite` (the gradient-ring `::before` floods the card with `--sys-colour-surface-l1-border`). The composable removes both during capture and paints a concrete `--bg-page` backing, so exports trade the live 1px gradient border + frost for solid dark cards. Don't expect pixel-perfect glass in the `.webp`.
16. **Inspector capture-phase gating** — `InspectorOverlay` blocks demo interaction via document `addEventListener(..., true)` (capture phase), not `pointer-events:none`. This lets the overlay intercept clicks before Vue's event delegation while leaving wheel/touch scroll intact and the toolbar/panel fully clickable. The demo elements themselves never get `pointer-events:none`, so CSS animations keep running. If you add new document-level capture listeners elsewhere, be aware the inspector's `swallow()` handler fires first when inspection mode is on.
17. **Dev chrome must never depend on a transparent store token** — `themes/ygodl.css` sets `--bg-page: transparent` (YGODL paints a fixed background-attachment art layer instead). Any dev-chrome surface using `var(--bg-page, #0c0e16)` goes see-through because the fallback is dead when the token is defined. Always use hardcoded literal colours (`#0c0e16`) for dev chrome backgrounds, and layer the store's page art on top if needed (see `StoryStage.vue`).
18. **Store-specific tokens belong in their theme file, not extensions.css** — `--ea-*` tokens (EA brand colours) live in `[data-theme="fcm"]` in `themes/fcm.css`; `--konami-*` tokens live in `[data-theme="efootball"]` in `themes/efootball.css`. `extensions.css` is for prototype-wide constants (platform brand colours, toolbar, haptic) that apply across all stores. Do not add store-specific tokens to `extensions.css`.

*Previously:* August 2026 · v0.59.3 — Hotfix: Vercel's `npm install` was failing on every project building this repo after v0.59.2's kit extraction, with `Permission denied (publickey)`.
