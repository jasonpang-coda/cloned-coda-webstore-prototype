# Release Notes — v0.102.0

**Date:** September 2026
**Milestone:** Style-guide drift-check harness + JSON-only spec.json for COD:M and FCM

---

## Highlights

- **A style guide can now silently diverge from the theme CSS that ships it — and something finally catches that.** New `npm run style-guide:check` diffs a `docs/style-guides/<slug>/spec.json`'s `codashop.brandLocked` block (the 7 ref-seed colours + brand fonts) against the live `src/tokens/ds/themes/<store>.css`, the same class of drift `figma-harness.mjs diff-tokens` already catches for Figma exports vs. the prototype.
- **COD:M and FCM now have a style-guide spec** (`docs/style-guides/codm/spec.json`, `docs/style-guides/fcm/spec.json`) — the repo's two live production stores previously had none at all (every other guide covers a reskin/pitch store). JSON-only per the request driving this release — no `guide.html` was generated, and no brand-voice narrative was fabricated: `generic`'s aesthetic fields are explicit `null` rather than invented copy, since no reference imagery was reviewed this pass.
- **Shared OKLCH↔hex conversion, one source.** Moved out of `figma-harness.mjs` into `tools/lib/color.mjs` so `style-guide-check.mjs` doesn't duplicate the extractor (see the design-harness skill's "no duplicate extractor" gotcha) — plus a new `colorsApproxEqual` tolerance compare, needed because an OKLCH round-trip can land a saturated seed color a few `/255` off its authored hex (COD:M's own `#FFE700` round-trips to `#ffe703`) even with zero real drift.

## Changes

### `tools/style-guide-check.mjs` (new)

- `node tools/style-guide-check.mjs <slug>|all|list [--theme-key <key>] [--spec <path>] [--json]`.
- Resolves each store's live theme tokens via `resolveTokensForStore` and compares against `codashop.brandLocked.ref` (7 colours) and `.typePrimitives.fontHeading/fontBody`.
- Fails loud on an unknown slug (lists known guides) rather than silently no-op'ing, per the design-harness gotcha on name-filter CLIs.
- Font comparison is substring-based (spec names the brand font; the theme CSS declares a full fallback stack) — an exact-match comparison would false-positive on every store.

### `tools/lib/color.mjs` (new)

- `oklchToHex`, `normalizeColor` — moved verbatim out of `tools/figma-harness.mjs`, which now imports them instead of holding its own copy.
- `colorsApproxEqual(hexA, hexB, tolerance = 4)` — new. Absorbs OKLCH round-trip rounding noise while still catching real edits (observed real drift in this repo's own specs runs 10s–100s of `/255` per channel, well outside the tolerance).

### `tools/figma-harness.mjs`

- No behavior change — `normalizeColor` now imported from `tools/lib/color.mjs` instead of defined locally.

### `docs/style-guides/codm/spec.json`, `docs/style-guides/fcm/spec.json` (new)

- Reverse-engineered from the live theme files (`src/tokens/ds/themes/codm.css`, `fcm.css`) and the shared system-constant tiers (`space.css`, `system.css`) — every `brandLocked` value is cited to a specific CSS line, not inferred from imagery.
- Both pass `style-guide-check` clean (0 mismatches).
- Notable fact this pass surfaced and documented: FCM overrides `--x-radius-control-full` to a true pill (999px) vs. the shared 2px system default — COD:M does not override it. First machine-checkable record of that brand difference.

### `.claude/skills/design-harness/SKILL.md`

- Added the `style-guide:check` row to the Quick Reference table.

### `package.json`
