# Release Notes — v0.104.2

**Date:** September 2026
**Milestone:** Sprint-retro ledger dedup — bounds ledger growth by distinct lessons, not session count

---

## Highlights

- **`retro-ledger.json` no longer grows one row per recurrence of the same lesson.** Raised during this session's own retro: as the ledger accumulates across many sessions, reading it before new work (per the `sprint-retro` skill's own step 0) gets expensive if every occurrence of the same mistake appends a fresh near-duplicate row. Recency-based truncation was considered and correctly rejected — an old lesson is exactly as valid as a new one, and dropping it re-exposes the exact mistake it exists to prevent. The real fix: dedup-on-write, so the ledger is bounded by the number of *distinct* lessons known, not by how many times each was independently re-learned.
- **`tools/retro.mjs --lesson` now warns before creating a near-duplicate.** A mechanical word-overlap check (category- and component-scoped) flags existing entries that look like the same lesson recurring — advisory only, it never blocks the write, since only Claude can judge whether it's genuinely the same mistake or a new one that happens to share vocabulary.
- **New `tools/retro.mjs --update <ID>`** merges a recurrence into an existing entry instead of appending a new row — bumps a `seen Nx` count, refreshes the timestamp, optionally refines the wording.
- **`SKILL.md` now recommends `--check <category>` over blind `--list`** for the routine "read prior lessons before new work" step — scoping the read to what's relevant to the current task, not dumping the entire ledger.

## Changes

### `tools/lib/ledger.mjs`

- New `updateLedgerRecord(ledgerPath, id, mutate)` — same lock + atomic-rename discipline as the existing `appendToLedger`, for in-place patches instead of appends.

### `tools/retro.mjs`

- `--lesson` computes Jaccard word-overlap (stopword-filtered, category+component scoped) against existing entries and prints a warning with matching IDs when a similar lesson already exists.
- New `--update <ID>` flag: merges any provided fields into the matching record, bumps its `instances` count, refreshes `timestamp`.
- `--list`/`--check` print the `seen Nx` count when `instances > 1`.
- New records now start with `instances: 1` explicitly.

### `.claude/skills/sprint-retro/SKILL.md`

- Step 0: prefer `--check <category>` over `--list`.
- Step 4: documents the warn/`--update` merge workflow and the dedup-not-recency rationale.

### `tests/ledger.test.mjs`

- 3 new tests for `updateLedgerRecord`: patches only the matching record, throws (not silently no-ops) for an unknown id, survives N concurrent writers updating different records without losing an update.
