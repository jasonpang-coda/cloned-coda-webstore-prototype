# Release Notes — v0.105.0

**Date:** September 2026
**Milestone:** Scrape-friendly handoff — deep-linkable URL state, static handoff routes, and a machine-readable manifest so an external agent can scrape the deployed URL instead of cloning the repo

---

## Highlights

- **Every meaningful app state is now one URL away.** `?theme=<store>&device=ios|android|responsive&orientation=landscape&overlay=<name>&sku=<itemKey>` reads on boot and writes back going forward — store, device, orientation, six named overlays, and now the checkout/payment sheet for a specific SKU. Raised because an FE engineer picking up a feature refused to clone the prototype repo and preferred to point his AI agent at the deployed URL instead — this makes that scrape cheap and accurate rather than fighting it.
- **The handoff package now ships from the deployed site itself.** `public/handoff/**` — staged specs, a discovery manifest (`index.json`), resolved per-store design-token JSON, and rendered per-state DOM dumps — is generated at build time and served from the same origin the storefront runs on, so a scraper never needs repo access to get the AI-readable spec, the token contract, or real markup.
- **Fixed a real bug:** `vercel.json`'s SPA rewrite was silently swallowing `/handoff/*` and `/llms.txt` into the `index.html` shell on Vercel — both existed in `public/` but were unreachable from a real deploy.
- **Checkout deep-linking resolves through a new SKU registry**, not a hardcoded catalog lookup — every SKU card family registers its synthetic `itemKey → item` mapping at setup, so `?sku=<key>` calls the exact same `openCheckout()` a real tap would, auth gate included (a gated store correctly no-ops rather than bypassing sign-in).

## Changes

### `src/composables/useUrlState.js` (new)

- Single owner of URL↔state sync for device, orientation, store, overlay, and SKU — replaces three separate ad-hoc readers/writers (`App.vue`'s device/orientation watcher, `useTheme.js`'s read-only `?theme=`, no overlay support at all).
- One merged `watch(...)` writes every dimension in a single `router.replace()` call. Two independent per-dimension watchers were tried first and shipped a real lost-update race (`router.replace()` is async, so a second watcher's `{...route.query}` spread could read stale state before the first's navigation landed) — caught live in the browser and fixed by merging into one writer.
- `OVERLAY_NAMES` is a closed set of six no-argument overlays (`signIn`, `account`, `region`, `language`, `pwaInstall`, `navDrawer`); checkout/giftClaim/itemSummary/taskGiftClaim are excluded from that set since they need data the URL has no slot for — checkout gets its own `?sku=` mechanism instead (see below).

### `src/composables/useSkuRegistry.js` (new)

- `globalThis`-pinned key→item-getter map. Every SKU card family (`SkuCard`, `BestSellerCard`, `BundleSkuCard`, `HeroSkuCard`, `ProdHighlightedSkuCard`, `SkuImageCard`) now factors its inline `openCheckout({...})` object literal into a `buildItem()` function, registers `(itemKey, buildItem)` at setup, and unregisters on unmount.
- `useUrlState` resolves `?sku=<itemKey>` against this registry (deferred a microtask past mount, same pattern as overlay-open) and calls the real `openCheckout(item, key)` — verified live for both the sign-in-gated sheet (COD:M) and the un-gated Buy Now bar (FCM, cold page load, no sign-in).

### `src/App.vue`

- Removed the inline device/orientation URL-sync block in favour of one `useUrlState({ device, isMobile, figmaCaptureStep })` call.
- Download-banner section gained `data-component`/`data-state`/`data-token` attributes matching its handoff spec's documented state names 1:1 (`bg_image_present/absent`, `badges_in_banner`/`badges_above_value_props`, `badge_image`/`badge_text_pill`, `pwa_row_visible`).

### `scripts/stage-handoff.mjs` (new)

- Wired as a Vite `buildStart` plugin (`vite.config.js`, every `--mode`) — stages the AI-readable filenames only (`AGENTS.md`, `README.md`, `component-breakdown.md`, `motion-tokens.md`, `haptic-tokens.md`, `typography.md`, `spec.md`, `spec.json`) from each `docs/Handoff/<slug>/` into `public/handoff/<slug>/`, never the interactive VitePress playground sites' own scaffolding.
- Generates `public/handoff/index.json` (every staged feature, its spec/state/DOM-dump URLs, a content hash) and `public/handoff/tokens/<store>.json` (resolved semantic/space/text-style/extensions token values per store, reusing `resolve-css.mjs`'s exact cascade resolver — cross-checked byte-for-byte against `token-cli.mjs resolve` for `--x-bg-sheet`/fcm).
- `public/handoff/` is now fully generated and gitignored — the two previously hand-committed flat files (`locale-selector-sheets.md`, `pwa-web-push.md`) are superseded by the generated directory tree.

### `scripts/dump-dom.mjs` (new)

- Reuses `tools/harness-render.mjs`'s SSR render path (StoryStage via Vite SSR + `@vue/server-renderer`) to write real per-(story, variant, width) HTML to `public/handoff/dom/<slug>/*.html`, for the five handoff-target features that already have a story (`trust-bar`, `best-seller-card`, `sku-card`, `region-selector-sheet`, `language-selector-sheet`). Run as a step of `stage-handoff.mjs`.

### Handoff-target components

- `TrustBar.vue`, `BestSellerCard.vue`, `SkuCard.vue`, `RegionSelectorSheet.vue`, `LanguageSelectorSheet.vue` gained `data-component`/`data-state` (and `data-entrance-delay-ms` on `SkuCard`) matching their `docs/Handoff/` spec's state-inventory naming exactly, so a scraped DOM node maps to a spec section without inference.

### `vercel.json`

- Rewrite exclusion list now also covers `handoff/` and `llms.txt` (previously only `assets/`, `manifest.webmanifest`, `sw.js`, `pwa/`) — fixes the SPA-shell-swallowing bug above.

### `public/llms.txt`

- Rewritten to point at `/handoff/index.json` and document the full deep-link query-param contract, alongside the existing per-feature AGENTS.md links.

## Verification

`npm test` — 55/55 pass. Clean `vite build` across every store (codm, fcm, codashop, tdr, zzz spot-checked). Live-browser verification: deep-link round-trip (`?theme=fcm&device=android&overlay=region` → correct store + device frame + open sheet, confirmed by screenshot), static routes (`curl`'d `/handoff/index.json`, `/handoff/trust-bar/AGENTS.md`, `/handoff/tokens/fcm.json`, `/handoff/dom/trust-bar/default-iphone.html`, `/llms.txt` — all real content, not the SPA shell), and checkout deep-link (COD:M sheet after sign-in, FCM Buy Now bar cold with no sign-in — both confirmed by screenshot).
