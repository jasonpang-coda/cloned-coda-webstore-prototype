# Release Notes — v0.113.1

**Date:** September 2026
**Milestone:** New `plans/` workflow for tracking future harness/DS implementation plans across sessions

---

## Highlights

- **New `plans/` directory** — a lightweight, committed alternative to a Kanban board for storing multi-phase implementation plans that aren't yet (or aren't only) a single-session task. Plain markdown, one file per initiative, indexed in `plans/INDEX.md` for a cheap pre-work scan — same "read before you start" discipline as `audits/retro-ledger.json`, but for plans instead of already-learned lessons.
- **`plans/ds-remediation.md`** — migrated from the previously gitignored `audits/ds-remediation-plan.md` (local-only, `audits/*`). Re-verified against current source at migration time: Phases 1–2 (mechanical token swaps, brand-token relocation) confirmed done; Phase 3 (off-scale tokens) unverified; Phases 4–5 (whitelabel de-branching, eFootball semantic adoption) confirmed **not** started — `SignInSheet.vue`/`PageSignInSection.vue` still branch on `flow === 'efootball'`.
- **`plans/pixel-diff-gate.md`** — the previously-discussed, not-yet-authorized "Plan 2" (a visual-correctness CI gate to catch layout/overlap regressions the existing render/crash and token-drift gates can't) is now recorded as a `status: proposed` plan with its open questions (baseline storage, re-bless workflow, CI runner rendering stability), rather than living only in chat history.

## Changes

### `.claude/skills/design-harness/SKILL.md`

- Added a Gotchas entry pointing at `plans/INDEX.md`, distinguishing it from the two retrospective ledgers (`audits/regressions-log.json`, `audits/retro-ledger.json`): a plan not yet executed belongs in `plans/`, a lesson already learned belongs in a ledger.

## Verification

No app code touched — docs/process tooling only. `npm test` unaffected (pre-existing 2 failures only, unchanged from prior release).
