# Release Notes — v0.114.2

**Date:** September 2026
**Milestone:** Formalizes the visual capture rig's manual capture loop into a reusable script, fixes the whitelabel violation `SignInSheet.vue:60` surfaced in v0.114.1, and re-verifies `ds-remediation.md` Phase 3 against current source.

---

## Highlights

- **The visual capture rig's manual loop is now a reusable script, not ad-hoc per-shot code.** `src/dev/captureHelper.js`'s `captureCurrentStage()` is the one-line browser-side call (reusing `useScreenshot.js`'s real-device-frame workarounds — ring-mask neutralisation, backdrop-filter strip, resolved page-bg — via three newly-exported functions instead of a second copy), and `tools/harness-capture.mjs save --from <file> --to <outFile> [--raw]` is the Node-side decode/write half. Verified end-to-end against a real manifest target (`info-tag`, codm/iphone): captured, decoded, confirmed a genuine 780×400 RGBA PNG via `file`. Deliberately *not* a headless-browser driver — this formalizes the existing human/agent-driven loop, it doesn't automate it away.
- **`SignInSheet.vue:60`'s disguised store-identity branch fixed.** The `flow === 'codm'` check looked like a per-flow distinction but wasn't: 6 other stores also set `signIn.flow: 'codm'` as an unused placeholder (all hide the button via `navbar.hideSignIn`), so the check only ever fired for the real COD:M store. Replaced with an explicit capability flag (`config.signIn.ctaCasing: 'uppercase'`, set only on `codm/store.js`) — zero visual change, verified via `harness test`/`harness:render` (both 12/12 and 6/6 clean) and live in the browser on both COD:M and FCM.
- **`ds-remediation.md` Phase 3 re-verified against current source, not executed.** Had sat at "❓ unverified" since the v0.114.0 migration. Found 3b (Grid responsive gutters) was already fully tokenised — no raw px left at any breakpoint. 3a and 3c are still open, but every file:line reference has been corrected: `CheckoutSheet.vue` no longer exists — it was split into `components/checkout/*.vue` and `components/steps/*.vue` at some point after the plan was written, and the raw px values it named had simply moved, not disappeared. A new, separate finding surfaced along the way: `Grid.vue`'s own docblock claims an L breakpoint (`≥1280px`) it doesn't actually implement — the L-tier tokens are only consumed by `App.vue`'s split-layout shell, not by `Grid.vue` itself. Flagged for a decision, not fixed.

## Changes

### `src/composables/useScreenshot.js`

- Exported `resolvePageBg`, `neutraliseRings`, and a generalized `makeOnCloneEachNode(pageBg, screenClass)` (previously hardcoded to `.device__screen`) so the library-viewer's capture stage can reuse the same clone-time workarounds as the real device frame, instead of a second copy.

### `src/dev/captureHelper.js` (new)

- `captureCurrentStage()` — the browser-side capture call. Reads `document.documentElement.dataset.captureSelector` (set by the library viewer in `?capture=1` mode), captures via `domToPng`, returns a base64 PNG string.

### `tools/harness-capture.mjs`

- New `save --from <file> --to <outFile> [--raw]` subcommand: decodes a captured payload to real PNG bytes and writes it to disk. Unwraps the Browser pane's auto-saved `[{type,text}]` tool-result shape by default, or treats `--from` as a bare base64 string with `--raw`. Fails loud on a missing flag or an unparseable `--from`.

### `tests/harness-capture.test.mjs`

- 5 new tests covering both decode paths, output-directory auto-creation, and the two loud-failure cases (13/13 passing in this file).

### `src/stores/codm/store.js`

- Added `signIn.ctaCasing: 'uppercase'` — the capability flag `SignInSheet.vue` now reads instead of branching on `flow`.

### `src/components/SignInSheet.vue`

- Replaced `labelStyleForFlow(flow)` (branched on `flow === 'codm'`) with a `ctaLabelStyle` computed reading `config.value.signIn.ctaCasing`, defaulting to regular casing when the flag is absent.

### `plans/ds-remediation.md`, `plans/visual-capture-rig.md`

- Phase 3 re-verification findings, Phase 4 closed out (all 3 de-branching items now done), and the new capture script documented against the plan that scoped it.
