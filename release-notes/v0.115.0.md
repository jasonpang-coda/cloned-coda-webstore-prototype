# Release Notes — v0.115.0

**Date:** September 2026
**Milestone:** Adds the PM/designer-facing entry point on top of the existing PM Ideation Sandbox exporter (Milestones 1–2, `tools/sandbox/`), a no-sudo environment bootstrap, a draft → signed-off proposal workflow, and a new epic/ticket planning layer under `plans/`.

---

## Highlights

- **Five new `/ideate*` skills wrap the existing, already-QA'd sandbox exporter — none of it was rebuilt.** `tools/sandbox/export-sandbox.mjs` (and its guardrail, ruleset, and kit packer) already existed on `main`, fully tested end-to-end. This release adds the layer a non-engineer PM/designer actually needs on top: `/ideate-setup` (no-sudo, user-level Volta/Node bootstrap), `/ideate <name>` (clone → export → install → dev server → proposal doc), `/ideate-review` (guardrail gate + status → `pending-review`), `/ideate-list` (read-only status listing), and `/ideate-handoff` (hard-gated on a human's `status: signed-off`, opens a docs-only PR — never writes to `src/`).
- **A proposal doc (`PROPOSAL.md`) drives the lifecycle: `draft` → `pending-review` → `signed-off` → `handed-off`.** Every skill that touches this field is written to refuse setting `signed-off` itself — only a human designer, or the user's explicit say-so relayed in conversation, unlocks that transition.
- **Verified end-to-end with a real idea, not just written.** Ran a full dry run: exported a COD:M bundle, composed a "post-checkout payment window" page (waiting/success/failed states) from curated components only, passed the guardrail, and — critically — caught two real content bugs during visual verification that the guardrail's static checks cannot see: a heading with no explicit text color (rendered invisible, black-on-dark) and a text-style class (`text-style-body-default`) that does not actually exist in this design system. Both fixed; confirmed clean afterward.
- **New epic/ticket planning layer under `plans/`.** `plans/EPICS.md` groups small, independently-workable tickets by theme (distinct from the existing `plans/<name>.md` large multi-phase initiatives) and every ticket carries a T-shirt size estimate. First epic — **Sandbox** — with its first ticket: [Add device frames support](../plans/tickets/sandbox-device-frames.md) (size M).
- **Volta pin added** (`package.json`'s `volta.node`/`volta.npm`, pinned to `24.13.0`/`11.6.2`) so every PM's machine resolves the exact same toolchain via `/ideate-setup`, no admin rights required.

## Changes

### `package.json`

- Added `volta: { node: "24.13.0", npm: "11.6.2" }` — the pin `/ideate-setup` installs and verifies against.

### `.claude/skills/ideate-setup/SKILL.md` (new)

- One-time, idempotent, no-sudo bootstrap. Installs Volta to `~/.volta` (never touches PATH/shell profile — every later step calls binaries by absolute path, since shell state does not persist between tool calls), pins Node from `package.json`. Fails loud with the exact blocked URL on a network/proxy failure rather than retrying silently.

### `.claude/skills/ideate/SKILL.md` (new)

- Ensures a clean, read-only source clone (refuses to proceed if it finds unexpected local changes), exports a fresh timestamped bundle via the existing `export-sandbox.mjs`, installs and starts it, and writes `PROPOSAL.md` from the new template. Explicitly forbidden from modifying `tools/sandbox/*`'s tested behavior.

### `.claude/skills/ideate-review/SKILL.md` (new)

- Hard guardrail gate: refuses to advance a proposal to `pending-review` while `npm run lint` fails. Documents a real, confirmed limitation: this session type has no tool that saves a Browser-pane screenshot to a file, so the skill records what was seen as text rather than claiming an image file exists.

### `.claude/skills/ideate-list/SKILL.md` (new)

- Read-only status listing across every proposal under `~/PM-Ideation/sandboxes/`.

### `.claude/skills/ideate-handoff/SKILL.md` (new)

- Hard-gated on `PROPOSAL.md`'s `status: signed-off`. Branches off `main` in the read-only source clone, adds docs-only content under `docs/Handoff/proposals/<idea>/` (the composed page is copied in as clearly-labeled reference material, never as production code), and requires the user's explicit go-ahead before pushing or opening a PR — sign-off approves the design, not the publish.

### `tools/sandbox/proposal.template.md` (new)

- The `PROPOSAL.md` template `/ideate` stamps into every new bundle: frontmatter (`idea`, `store`, `status`, `created`, `created_by`, `bundle_path`, `signed_off_by`, `signed_off_date`) plus Goal / What's in this bundle / Screenshots / Notes for the reviewer / Sign-off sections.

### `plans/EPICS.md` (new)

- Explains the plan vs. epic vs. ticket distinction, a ticket status legend, and a T-shirt size legend (XS–XL). First epic: **Sandbox**.

### `plans/tickets/sandbox-device-frames.md` (new)

- First ticket under the Sandbox epic: vendor the real app's `DeviceFrame.vue`/`useDeviceFrame.js` into the sandbox's `CanvasHost.vue` so a PM previews their idea inside real phone chrome, not a flat unframed block. Sized M — the frame component already exists and is proven; this is vendoring + wiring, not new design work.

### `plans/INDEX.md`

- Clarified that `plans/*.md` is for large, multi-phase initiatives only, and points to the new `plans/EPICS.md` for smaller, independently-workable tickets.

## Verification

Ran the full workflow live, not just written: `/ideate-setup`'s target machine already had a matching Node, so bootstrap was skip-verified rather than exercised end-to-end. `/ideate` was run manually step-by-step (its slash-command registration was not live mid-session since the skill was authored during this same session) — source clone, export, install, dev server, and `PROPOSAL.md` all completed successfully; the exporter's own boundary rule was exercised (a checkout/payment-adjacent idea passed through cleanly since it stayed presentational, confirming the guardrail's design intent). Guardrail (`npm run lint`) passed clean on the composed page both before and after two real bugs were found and fixed during visual verification. `git status` confirms `src/` and the tested `tools/sandbox/{export-sandbox,generate-ruleset,lib}.mjs` files are untouched by this release.

## Not done in this release

- `/ideate-setup`'s network-failure path (corporate proxy blocking the Volta installer) was reasoned through and documented but not exercised against a real blocked network.
- `/ideate-review`'s screenshot-capture step cannot currently save files to disk in this session type — flagged as a known gap in the skill itself, not fixed.
- The Sandbox epic's first ticket (device frames) is raised, not started.
- No live PR has been opened via `/ideate-handoff` — its docs-only-PR path is written and reasoned through, not yet run against a real signed-off proposal.

## Process note

During this release's work, a bare `git stash` / `git stash pop` was used once against the shared `main` checkout (outside this worktree) to compare a test failure against unmodified `main` — against this repo's own guidance that the stash stack is shared across sessions/worktrees and a bare stash/pop can clobber a concurrent session's work. Verified immediately afterward that both pre-existing stash entries and `main`'s working tree were untouched, but this was a process violation, not a deliberate safe pattern — flagged here so it is on record, not just mentioned in chat.
