# Release Notes — v0.116.0

**Date:** September 2026
**Milestone:** Bounded-autonomy retry loop for the design harness plus a morning backlog digest (scheduled via launchd), a ticket/plan reorg with a status-folder convention and epic-archive workflow, and FCM's end-of-category jump nav (with a `FilterDropdown` Teleport fix for a stacking/hit-testing bug it depends on).

---

## Highlights

- **The design harness gets a bounded-autonomy retry loop.** `tools/orchestrator.mjs` stays a pure, stateless verifier; the new `tools/harness-loop.mjs` decides DISPATCH (which subagent, with what brief) / SUCCESS / ESCALATE for one iteration, tracking retries per stage and escalating on a repeated identical failure or a cap. A live Claude session drives it via the Agent tool — the loop can decide, but only a session can dispatch. See `plans/EPICS.md`'s (now-archived) Harness Automation epic.
- **Found and fixed a real, previously-invisible bug while wiring the loop's structured failures.** `execSync` throws *before* its own `JSON.parse(stdout)` line runs on a real tool FAIL (the shelled-out tool correctly `process.exit(1)`s), which had silently made `orchestrator.mjs`'s explicit failure-message checks dead code — and hid a stale field-name bug where the `preflight` hard gate checked `parsed.hasFailures`/`parsed.totalIssues`, fields `preflight.mjs` never emits. The `preflight` gate had been silently passing regardless of real violations. Fixed via a `runJsonTool()` helper that recovers the tool's JSON from the thrown error's own `.stdout`; compounded to `audits/retro-ledger.json` as a durable lesson.
- **`--from-stage` lets the retry loop resume without re-running already-passed stages**, and a stage FAIL now carries a structured `failures[]` array (not just a prose message) so the loop can diff failures across retry attempts.
- **A morning backlog digest, scheduled automatically.** `tools/backlog-digest.mjs` reads ticket frontmatter under `plans/tickets/<status>/` and reports ready-to-pick-up tickets (smallest size first, dependency-aware), blocked tickets with their unmet dependency, stale in-progress tickets, and any folder/status consistency issue. Runs weekdays at 7am via a launchd agent (`scripts/backlog-digest-notify.mjs`) — a macOS notification with headline counts, full digest logged to `~/Library/Logs/CodaWebstoreBacklog/`.
- **Tickets are now filed by status, not just tagged by it** (`plans/tickets/<status>/<slug>.md`), with an epic-archive workflow (a closed epic's section moves to `## Archived Epics` once every ticket is done/abandoned) and a one-time migration of 7 already-drafted, mostly-executed `plans/*.md` initiatives into tracked tickets under 3 new epics (`harness-design-quality`, `ds-remediation`, `figma-token-sync`), each keeping its `size: XL` to flag that it's still plan-shaped content. `plans/INDEX.md` now points to `plans/EPICS.md` for current status.
- **FCM gets an end-of-category jump nav** (`CategoryJumpNav.vue`, double-gated behind `categoryJumpNav` flag + `config.nav.categoryJump` capability) — a dropdown at the end of each category to jump to any of FCM's many categories, wired into both `CategoryCatalog.vue` and the Gifts tab's bespoke markup in `App.vue`. Depends on a `FilterDropdown.vue` fix: panels deeply nested in FCM's split-layout storefront could lose real stacking/hit-testing against later page content even at maximum z-index — now teleported into the app's shared `.device__overlay` layer, with `panelBlur`/`panelOpaque` props replacing the `:deep()` overrides that stop working once an element is teleported out of its scoping ancestor.
- **New `DownloadBanner`/`StoreBadges` components** for app-store/Google-Play upsell rows (PWA-install and Web-Push variants), wired into `App.vue`.

## Changes

### `tools/orchestrator.mjs`

- Added `runJsonTool()`: recovers a shelled-out tool's JSON from `err.stdout` on a thrown `execSync` failure, instead of losing it to a generic "Command failed" message.
- Fixed the `preflight` stage's dead field-name check (`hasFailures`/`totalIssues` → `passed`/`count`, matching `preflight.mjs`'s real shape).
- `sweep`/`render`/`preflight` FAILs now attach a structured `failures[]` array to the scorecard (`{story,type,store,token}` for sweep, `{story,variant,width,locale}` for render, `{type,file,line}` for preflight).
- Added `--from-stage <id>`: resumes the pipeline from a named stage, marking earlier ones `SKIPPED`.

### `tools/harness-loop.mjs` (new)

- Router map (failed stage → subagent, per `.claude/skills/design-harness/subagents.md`'s three profiles), per-stage retry caps, failure-signature diffing (escalates on an identical repeat, not just a cap), and a mandatory full clean re-run before declaring success after any prior FAIL. Escalation appends to `audits/retro-ledger.json`; success-after-fail drafts a `compound.mjs --dry-run` preview for human approval — nothing auto-applies or auto-commits.

### `tools/backlog-digest.mjs` (new), `scripts/backlog-digest-notify.mjs` (new)

- Digest reads `plans/tickets/<status>/*.md` frontmatter directly (no dependency on `plans/INDEX.md`'s table). Notify script writes the digest to a dated log file and fires a macOS notification (`process.execPath`/absolute `osascript` path — launchd runs with no `PATH`, so a bare `node`/`osascript` call fails silently otherwise).
- `npm run backlog` / `npm run pipeline:loop` added. Scheduled via `scripts/com.codawebstore.backlog-digest.plist`, installed to `~/Library/LaunchAgents/`, Mon–Fri 7am.

### `plans/EPICS.md`, `plans/INDEX.md`

- Ticket-by-status-folder convention (`plans/tickets/<status>/<slug>.md`) and an epic-archive workflow. 7 already-drafted plans migrated into tracked tickets under 3 new epics, documented as a one-time exception (new `XL`-sized work still starts as a `plans/<name>.md`). `plans/INDEX.md`'s Plans table is now empty with a pointer to `EPICS.md`.

### `src/components/CategoryJumpNav.vue` (new), `FilterDropdown.vue`, `CatalogNavStack.vue`, `CategoryCatalog.vue`, `App.vue`, `src/composables/useFeatureFlags.js`, `src/stores/fcm/store.js`

- `FilterDropdown.vue`: teleports its panel into `.device__overlay` (falls back to in-place rendering where that layer doesn't exist, e.g. a bare component-library preview), with `panelBlur`/`panelOpaque` props replacing now-unreachable `:deep()` overrides, and JS-computed positioning that accounts for `DeviceFrame`'s scale transform.
- `CatalogNavStack.vue`: gained its own `mode` prop (`'scroll'`/`'filter'`) independent of `presentation`, so the flat nav row works whether every category is mounted (self-spying, scrolls) or only the active one is (emits `select` instead).
- `CategoryCatalog.vue`/`App.vue`: wire `CategoryJumpNav` behind the `categoryJumpNav` flag + `config.nav.categoryJump` capability (double-gate pattern), including the Gifts tab's bespoke markup which bypasses `CategoryCatalog` entirely.
- `useFeatureFlags.js`: new `categoryJumpNav` flag definition; `fcm/store.js`: `nav.categoryJump: true` capability.

### `src/components/DownloadBanner.vue` (new), `StoreBadges.vue` (new)

- App-store/Google-Play badge row, extracted as a standalone `StoreBadges.vue` so a store can render badges outside the banner too (`hideBadges` prop on `DownloadBanner`). PWA-install and Web-Push upsell row variants.

### `src/tokens/ds/space.css`

- Added `--x-pad-surface-xxl` (aliases `--x-sys-space-xxl`) — the padding scale's existing `s`/`m`/`l`/`xl` steps didn't have this size available.

### Comment-only path-reference sweep

- ~15 files (`useUrlState.js`, `story.js`, `LibraryViewer.vue`, `StoryStage.vue`, `SignInSheet.vue`, `Grid.stories.js`, `tools/{harness-capture,harness-render,figma-token-crosswalk}.mjs`, `scripts/export-handoff.mjs`, `src/dev/{captureHelper,figmaCapture}.js`, `docs/Handoff/components/sku-card/spec.md`, `tests/{export-handoff,figma-token-crosswalk}.test.mjs`) had stray comment references to the old `plans/<name>.md` paths updated to the new `plans/tickets/<status>/<name>.md` locations. No functional changes in any of these files.

## Verification

- Full test suite: 93/96 passing. The 3 failures (`export-handoff --story --verify` story-mode drift, `preflight` token check, `token-cli` audit) pre-exist this release and are unrelated to any change here — confirmed by running the suite against `main` with this release's changes stashed.
- `npm run build` — clean, no new errors (only pre-existing chunk-size warnings).
- `tools/harness-loop.mjs`'s dispatch/escalate/success paths and `tools/backlog-digest.mjs`'s ready/blocked/stale/consistency logic each have dedicated tests (10 new tests total), all passing.
- The launchd job was verified end-to-end under real launchd conditions (`launchctl start`, not just a manual `node` invocation) after the `PATH`-related bug was found and fixed — confirmed clean stderr and a correctly-written log file.

## Process note

This release's changes came from multiple concurrent Claude Code sessions sharing one working directory (not separate worktrees). Two coordination issues surfaced and were resolved by messaging the other session directly rather than assuming or reverting: (1) 7 plan documents unexpectedly appeared moved into `plans/tickets/` — confirmed as a deliberate, user-confirmed reorg, not a mistake; (2) the Harness Automation epic's section was moved to `## Archived Epics` by that same session, per a new epic-close rule it introduced — confirmed correct, no ticket files were touched by it. A third set of unrelated in-flight work (FCM nav, `DownloadBanner`, the `FilterDropdown` Teleport fix) from other sessions not directly coordinated with is included in this release at the user's explicit direction, after flagging the scope decision.
