# Release Notes — v0.116.1

**Date:** September 2026
**Milestone:** Fix for the checkout `?sku=` deep-link URL race, plus an auto-sign-in default for that deep link.

---

## Highlights

- **Fixed a URL race that dropped `?sku=` on load.** `useUrlState.js`'s SKU deep-link resolves the SKU registry one microtask after boot, so cards have time to register. But the URL-writer watcher runs `immediate: true` and fires synchronously, before that microtask — so it always saw checkout as not yet open and deleted `sku` from the URL right away. A new `pendingSku` flag tells the watcher to keep the original `sku` value while resolution is still pending.
- **A `?sku=` deep link now defaults to a signed-in demo user.** If the link opens while the user is signed out and not guest-verified, checkout used to no-op on the sign-in gate. It now signs in as `codayw` (the same default name `useAuth.js` already uses) so the payment channel sheet opens directly from the link, in any orientation.

## Changes

### `src/composables/useUrlState.js`

- Added `pendingSku` ref: true while the `?sku=` resolution microtask has not yet settled. The URL-writer watcher's SKU source reads it, keeping the original SKU value in the query instead of reading `sheetOpen`/`buyNowVisible` as false during that gap.
- On successful SKU resolution, if the user is not signed in and not guest-verified, sets `playerName` to `codayw` and `signedIn` to `true` before calling `openCheckout()`.

## Verification

- Manually verified in the browser: `?device=ios&theme=codm&orientation=landscape&sku=11600|$99.99` now opens the payment channel sheet directly in landscape, signed in as `codayw`, with `sku` staying in the URL.
