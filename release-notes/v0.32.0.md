# Release Notes — v0.32.0

**Date:** June 2026
**Milestone:** HeroSkuCard animated conic border + bloom halo; Responsive device default capability flag; StoryCarousel logo size + scrim tokens

---

## Highlights

- **Animated dual-comet conic border** — `HeroSkuCard` gains a spinning border ring using a `conic-gradient(from var(--angle), …)` mask-composite pseudo-element. Two comets (180° apart) orbit the card edge continuously. Colors are fully themeable via four per-store tokens; the Rogue Trader variant pairs imperial gold with warp-green VFX. Critical implementation detail: the conic must be written **inline** in the component, not wrapped in a CSS custom property — Chrome does not re-evaluate `var(--angle)` inside a nested custom property per animation frame.
- **Bloom halo** — `HeroSkuCard` now carries the `fx-bloom` class, painting an ambient light-bleed halo behind the card. The RT variant glows gold-to-warp-green.
- **Responsive device default** — a new `config.device.default` capability flag lets any store declare its preferred device frame on load. Rogue Trader (a PC game) sets `'none'` to open in Responsive by default; all other stores fall back to `'iphone'`.
- **StoryCarousel logo size + scrim tokens** — logo dimensions and the bottom content scrim are now per-store tokens. RT uses a 3× larger wordmark (192px × 660px) and fades the carousel into the void page background for seamless art-to-page blending.

## Changes

### `src/components/HeroSkuCard.vue`

- **Animated conic border (`::before`):** replaced the static `var(--border-sku-card-default)` gradient with a `conic-gradient(from var(--angle), …)` written directly in `background`. Geometry unchanged from the original proven ring: `inset: 0`, `padding: var(--border-weight-default)`, `linear-gradient(#fff 0 0)` mask layers, `-webkit-mask-composite: destination-out` / `mask-composite: exclude`. Added `animation: border-spin var(--motion-border-spin) var(--motion-sys-ease-linear) infinite`. Removed the hover `::before` background transition (the spinning animation supersedes it).
  - **Why inline, not a token:** `@keyframes border-spin` animates `--angle` via `@property` (`syntax: '<angle>'`). If the conic is assigned via a CSS custom property (e.g. `background: var(--some-token)` where the token contains `conic-gradient(from var(--angle), …)`), Chrome freezes `--angle` at its initial value when evaluating the outer var — the border renders but does not spin. Writing `conic-gradient(from var(--angle), …)` directly in `background` forces the browser to re-read `--angle` every frame.
  - **Dual-comet stop map:** comet 1 (primary) — `transparent 0–30°`, glow ramp `40–72°`, `transparent 88°`; comet 2 (secondary) — `transparent 210°`, glow ramp `220–252°`, `transparent 268–360°`. Glow/hot stops reference `--border-hero-card-glow/hot` and `--border-hero-card-glow-2/hot-2`.
  - **Mask idiom:** `linear-gradient(#fff 0 0)` used as a luminance mask (white = full reveal, not brand colour). Two layers — content-box and full inset — combined with `mask-composite: exclude` to punch out the interior and leave only the border ring.
- **`fx-bloom` class + `::after` override:** added `fx-bloom` to the root element. The global `.fx-bloom::after` uses `var(--fx-bloom-image)` for the halo source. Component scoped `::after` rule overrides `inset: -8%` (wider than the `.fx-bloom` default `-2%`) and sets `filter: blur(48px) brightness(1.05) saturate(1.1)` for a more prominent hero presence.
- **`overflow: hidden` moved from root to `__media`:** required so the `::after` bloom halo and the `--selected::before` expanded ring bleed past the card boundary. `.hero-sku__media` now carries `overflow: hidden` + `border-radius: inherit` for corner clipping.

### `src/tokens/ds/extensions.css`

## FX system notes (handoff reference)

### How `@property --angle` + `border-spin` work

`src/tokens/keyframes.css` registers the custom property and the keyframes:

```css
@property --angle {
  syntax: '<angle>';
  initial-value: 0deg;
  inherits: false;
}
@keyframes border-spin {
  to { --angle: 360deg }
}
```

`@property` with `syntax: '<angle>'` is required so the browser can interpolate the value. Without the registration, `--angle` is just a string — it can't be animated. `inherits: false` means each element that animates `--angle` gets its own independent clock (multiple border rings don't share state).

### Why the conic must be inline

When a `conic-gradient(from var(--angle), …)` is assigned to a CSS custom property and then consumed via `background: var(--that-property)`, Chrome evaluates the outer `var()` call once and substitutes the entire text value — at that substitution time `--angle` is frozen at its current value (`0deg` at frame 0). The browser does not re-evaluate the inner `var(--angle)` on subsequent frames; the gradient is baked. Writing the conic directly in `background` forces a live read of `--angle` every frame and the animation works.

This is the same reason `BestSellerCard`'s `.fx-glow-border--hdr::before` works — its conic is written directly in the global class in `effects.css`, not inside a token.

### Mask-composite ring pattern

The border-ring geometry used by HeroSkuCard (and BundleSkuCard / BestSellerCard) creates a ring by layering two full-bleed gradients and punching out the inner area:

```css
::before {
  position: absolute;
  inset: 0;                                    /* or inset: -1.5px for slightly expanded rings */
  border-radius: inherit;
  padding: var(--border-weight-default);        /* ring thickness = padding */
  background: conic-gradient(from var(--angle), …);
  -webkit-mask:
    linear-gradient(#fff 0 0) content-box,     /* reveal only content-box region */
    linear-gradient(#fff 0 0);                 /* then also the full box */
  mask: linear-gradient(#fff 0 0) content-box, linear-gradient(#fff 0 0);
  mask-composite: exclude;                     /* standard: XOR = shows only non-overlapping area */
  -webkit-mask-composite: destination-out;     /* WebKit alias for the same operation */
}
```

Result: the conic fills the entire `::before` box, but the mask punches out everything except the `padding` ring — only the outermost `--border-weight-default` pixels of the gradient are visible. The `#fff` colour is a luminance-mask value (full opacity), not a brand colour.

### Token override pattern for new stores

To brand the HeroSkuCard border ring for a new store, add inside `html[data-theme="<store>"]`:

```css
--border-hero-card-glow:   <primary comet colour>;   /* glow (dimmer) */
--border-hero-card-hot:    <primary comet colour>;   /* hot (brighter core) */
--border-hero-card-glow-2: <secondary comet colour>;
--border-hero-card-hot-2:  <secondary comet colour>;
```

To override the bloom halo:
```css
--fx-bloom-image: radial-gradient(ellipse … at …, <colour-1>, <colour-2>, transparent);
```

To scale the carousel wordmark:
```css
--story-logo-max-height: <px>;
--story-logo-max-width:  <px>;
```

To use a custom carousel scrim:
```css
--gradient-story-scrim: linear-gradient(180deg, transparent 30%, var(--bg-page) 100%);
```
