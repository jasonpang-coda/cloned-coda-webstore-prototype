# Release Notes — v0.34.0

**Date:** July 2026
**Milestone:** Bundled SKU breakdown opened up to Best Seller + regular image cards; Rogue Trader sharp-corner pass; module-identity bugfix

---

## Highlights

- **Bundle breakdown, everywhere.** The "what's inside" row of child-item tiles — previously exclusive to `BundleSkuCard` — is now a shared `BundleBreakdown.vue` component. `BestSellerCard` and `SkuImageCard` gained an `items` prop, so any hero or regular SKU denomination can also be shown as a small bundle.
- **Rogue Trader goes fully angular.** All radius tokens in the Rogue Trader theme collapse to 0px (full-pill badges kept at 999px), completing its grimdark/military aesthetic.
- **Fixed a module-duplication bug** that surfaced as "one store's styles applied to every store" — root-caused to mixed import specifiers for `useTheme`.

---

## Changes

### `src/components/BundleBreakdown.vue` (new)

- Extracted from `BundleSkuCard`'s inline breakdown markup into a shared, theme-agnostic component: owns the flex row, the `useDragScroll`-powered horizontal-scroll variant, and the `BundleItem` loop.
- Props: `items` (Array, default `[]`), `scrollable` (Boolean, default `false`). Emits `select`, forwarded from each tile.
- Renders nothing when `items` is empty, so a host can mount it unconditionally without an extra `v-if` guard duplicated at every call site... except each host still guards with `v-if="items.length"` to avoid an empty fragment-root warning.
- Hosts position it purely via class fallthrough (overlap margin / inset padding) — no visual defaults baked into the shared component.

### `src/components/BundleSkuCard.vue`

- Refactored to consume `BundleBreakdown` instead of inlining the tile row. Dropped the now-redundant `BundleItem` + `useDragScroll` imports and the local `breakdownRef`/`isBreakdownDragging` state.
- `.bundle__breakdown` trimmed to host-positional rules only (`margin-top: -20px` banner overlap, horizontal padding) — row/scroll/drag CSS now lives in the shared component.

### `src/components/BestSellerCard.vue`

- New `items` prop (Array, default `[]`). When set, a `BundleBreakdown` row renders as the first child of `.bestseller__info`, pulled up via `margin-top: -29px` (~half a `BundleItem` tile's 58.8px height) so the tiles half-overlap the bottom of the coin image.
- Tiles carry no background/backdrop-filter of their own — each `BundleItem` tile is independently opaque and already frosts itself against whatever's behind it, so the overlap zone shows tiles floating on the photo (same mechanism as the existing coin overlay) with no compositing seam. Below the overlap line the row sits on `.bestseller__info`'s untouched, full-height vignette + blur surface.
- `.bestseller__info` restructured to `flex-direction: column` (breakdown row, then a new `.bestseller__info-row` wrapping the existing title/price side-by-side layout).
- COD:M demo data (`App.vue`): the Best Seller card now ships a bundled example — an 88 CP coin tile + a bonus Strongbox tile.

### `src/components/SkuImageCard.vue`

- New `items` prop (Array, default `[]`). Renders a `scrollable` `BundleBreakdown` row below the SKU art.
- `.sku-image-card__breakdown`: `margin-top: -8px` + `padding-top: 8px` — `BundleItem` tag pills are `position: absolute; top: -8px` and would otherwise be clipped by the card's `overflow: hidden` (needed to contain the oversized background art); this shifts the breakdown's own boundary up by the same amount so the pill lands inside the card instead.
- COD:M demo data: the 160 CP "Buy CP" (best-value) image card now ships the same bundled example as the Best Seller card.

### `src/tokens/ds/themes/roguetrader.css`

- Collapsed every radius token (`--radius-control-*`, `--radius-input-*`, `--radius-container-*`, `--radius-thumbnail-*`, `--radius-badge-s`) to `--sys-radius-0`, replacing the previous angular-but-not-sharp `2px` default control radius. Full-pill badges kept at `999px` so status chips stay visually distinct from the now fully sharp-cornered containers/controls/inputs/thumbnails.
- Updated the theme's header comment to describe the sharp-corner treatment.

### Module-identity bugfix — `useStoreAssets.js`, `useStoreConfig.js`, `useStoreStrings.js`

- Normalized `import { useTheme } from './useTheme'` → `'./useTheme.js'` in all three composables (they previously mixed extension-less and `.js`-suffixed specifiers for the same file).
- **Root cause:** Vite's dev server keys modules by their import *string*, not the resolved file — importing the same module two ways makes it evaluate as two separate module records, duplicating any module-scope singleton (the active-theme ref) and desyncing theme from content. Surfaced as "COD:M styling applied to every store" after the `BundleBreakdown` refactor changed the module graph and exposed the latent split.
- Encoded as a standing rule in `web-store-whitelabel` §2a and cross-referenced from `web-store-tokens` §3 and both copies of `codm-web-store-fe`'s workflow checklist, with a grep gate (`grep -rnE "from '[^']*/use[A-Za-z]+'" src --include=*.js --include=*.vue`) to catch future mixed-specifier regressions.
