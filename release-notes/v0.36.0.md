# Release Notes — v0.36.0

**Date:** July 2026
**Milestone:** L1/L2/L3 + status surfaces promoted to the `--sys-colour-surface-*` namespace; TransactionCard shows "No charge Made" for failed transactions

---

## Highlights

- **Surface tokens are now sys-tier, with `:root` defaults.** `--surface-l{1,2,3}-{fill,border,border-hover}` and `--surface-{success,warning,failure}-fill` — previously orphan tokens authored per-store with no documented tier — are renamed to `--sys-colour-surface-*` and given reference `:root` defaults in `system.css` (seeded from COD:M). Every other store overrides them from its own `html[data-theme]` block.
- **TransactionCard now surfaces failed transactions clearly.** The Total Payment row renders for every state (not just fulfilled); a failed transaction shows "No charge Made" instead of a blank/omitted row.

---

## Changes

### `src/tokens/ds/system.css`

- Added `:root` defaults for `--sys-colour-surface-l{1,2,3}-fill`, `-border`, `-border-hover` (L1 only), and `--sys-colour-surface-{success,warning,failure}-fill`, alongside the existing `--sys-colour-surface-{page,panel,overlay,…}` family. Values are COD:M's — the reference surface set. Status defaults already retarget per store via the inherited `--palette-status-*` ramps.

### `src/tokens/ds/themes/{codm,tdr,roguetrader,fcm,efootball,ygodl}.css`

- Renamed every `--surface-l*` / `--surface-{success,warning,failure}-fill` definition and reference to `--sys-colour-surface-*`.
- **Relocated every surface declaration from the plain `[data-theme]` block into `html[data-theme]`** (specificity 0,1,1) — required now that `system.css` defines these tokens at `:root` (0,1,0) and loads after the theme files; leaving them in the plain block would silently lose by source order (the same class of regression `--radius-control-full` hit previously). Also promoted the `@media (dynamic-range: high)` HDR overrides in codm/tdr/roguetrader/efootball/ygodl to `html[data-theme]` for the same reason.
- `codm.css` defines no surface tokens of its own — it *is* the `:root` reference default. The other five stores keep their full per-store values (values unchanged, only relocated + renamed).

### `src/tokens/ds/semantics.css`

- Renamed all 16 alias-target references (`--bg-sku-card-default`, `--bg-card-default`, `--bg-nav`, `--bg-sheet`, `--bg-sheet-footer`, `--bg-snackbar-*`, `--border-sku-card-default`, `--border-sku-card-hover`, `--border-nav`, `--border-sheet`) to point at the new `--sys-colour-surface-*` names. No semantic behavior changed — the role layer, per-store re-tiering, and the sheet's L2-fill/L3-border split are all preserved.

### `src/components/PageSignInSection.vue`

- Fixed the one direct-primitive leak: `background-image` now reads `var(--bg-sku-card-default)` instead of the raw `--surface-l1-fill`/`--sys-colour-surface-l1-fill` token — components consume semantics only. No visual change (identical resolved value).

### `src/components/TransactionCard.vue`

- Replaced the `hasTotal` (fulfilled-only) gate with an always-visible Total Payment row. Failed transactions render a new `.txn-card__total-no-charge` label ("No charge Made") in place of the price; the dashed divider above the row now shows for every state.
- New `noCharge` string added to each store's `strings.page.transactions` copy block (`src/stores/{codm,fcm}/store.js`).

### `src/stores/{codm,fcm}/store.js` (demo data)

- Pending transactions now carry a `total` value (previously `null`), so the pending state has a price to show alongside the new always-visible total row.

### `src/components/TransactionHistoryPage.vue`

- Added bottom padding clearance (`--pad-surface-xl` + `--pad-surface-s`, 32px) below the transaction list.
