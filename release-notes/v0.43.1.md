# Release Notes — v0.43.1

**Date:** July 2026
**Milestone:** Comment isolation fix — internal (multi-store) build no longer shares comments with locked per-store deployments

---

## Highlights

- **Second isolation boundary: `deployment_scope`.** Comment isolation previously keyed only on `store` (the active theme). But the internal multi-store build (`sku-card-internal`, runtime theme switcher) and a locked per-store build (`sku-card-codm`) can both end up with `store: "codm"` — so a comment left on the internal build while showing COD:M was bleeding into the standalone locked COD:M deployment, and vice-versa. A new `deployment_scope` column (`'internal'` | `'locked'`, computed once per build from the existing `__STORE_LOCKED__` compile-time flag) closes that gap: every fetch and insert now requires both `store` and `deployment_scope` to match.
- **Realtime stays correct without relying on multi-column server filters.** Supabase Realtime's `filter` option reliably supports only one column-equality expression, so the server-side subscription filter stays on `store` (unchanged); a client-side check on `deployment_scope` is added before applying incoming INSERT/UPDATE events. DELETE events are let through unconditionally, since `payload.old` only carries the primary key without `REPLICA IDENTITY FULL` (not set) — safe, because removing an id that isn't in the current scope's local list is a no-op.
- **localStorage fallback respects the same isolation.** The no-backend dev cache key gained the deployment scope (`webstore:comments:local:<theme>:<scope>`), so local testing without Supabase configured stays consistent with the production isolation model.

## Changes

### `src/composables/useComments.js`

- New module constant `DEPLOYMENT_SCOPE = __STORE_LOCKED__ ? 'locked' : 'internal'`.
- `fetchForStore()` adds `.eq('deployment_scope', DEPLOYMENT_SCOPE)` alongside the existing `store` filter.
- `addComment`/`reply` row objects now include `deployment_scope`.
- Realtime `subscribe()` adds a client-side `deployment_scope` guard on non-DELETE payloads.
- `localKey()` now includes the deployment scope.

### Database

- New `deployment_scope text not null default 'internal'` column on `public.comments`, with a composite index `(store, deployment_scope)`.
- `insert` RLS policy tightened to also require `deployment_scope is not null`.
- Existing (test/setup) rows truncated as part of the migration rather than backfilled with a guessed scope.

### Docs

- `docs/comments-backend.md` — schema + migration SQL, updated isolation note.
- `docs/comments-schema.md` — `deployment_scope` column reference, worked examples updated to show both scopes.
- `docs/comment-mode.md` — isolation section extended; also corrected a stale "known limitation" note about nested-scroll pin tracking, which was already fixed in v0.43.0 but the doc hadn't caught up.
