# Release Notes — v0.44.1

**Date:** July 2026
**Milestone:** `@coda/comment-kit` rewritten framework-agnostic — Lit Web Component core + thin Vue adapter, plus a shadow-DOM interaction bugfix

---

## Highlights

- **`@coda/comment-kit` is now framework-agnostic (v0.2.0).** The UI is a native `<comment-kit-layer>` custom element (built with Lit), so it works in React, Svelte, Angular, or plain HTML with zero adapter — not just Vue prototypes. A thin `@coda/comment-kit/vue` entry preserves the exact `createComments`/`<CommentLayer>`/`useComments()` API the webstore already depended on.
- **Three-layer architecture.** `core/store.js` is a framework-free reactive store (subscribe/emit) holding all state, CRUD, realtime, and localStorage logic — ported verbatim from the old Vue composable with the reactivity swapped out. `elements/comment-layer.js` + `elements/pins.js` render the UI: panels/list/gate/banner/launcher in a **shadow root** (real style isolation from the host), while pins stay light-DOM children of the host's anchor containers (required for native scroll-sync). `vue.js` is now just a bridge over that shared store.
- **Fixed a shadow-DOM event retargeting bug.** Document-level capture listeners used to inspect `e.target` to distinguish "click on the host page" from "click on our own UI" — but events originating inside a shadow root get `e.target` **retargeted** to the shadow host element itself when observed from `document`. Since that host element lives inside a configured container (e.g. `<body>`), every click/keystroke inside the comment UI's own panels (identity gate, compose box, filters, edit/resolve buttons) was being misidentified as a host-page click and swallowed — silently blocking native focus-on-click. Fixed by checking `e.composedPath()` (which exposes the true origin across an open shadow boundary) before any host-interception logic runs. This was blocking nearly all in-panel interaction, not just the identity gate where it was first noticed.
- **Build step added.** The package now ships built (`dist/index.js` + `dist/vue.js`, Lit bundled in, `vue`/`@supabase/supabase-js` external and optional peers) via a Vite lib build. In-repo dogfooding still resolves package **source** directly (via scoped Vite aliases in the webstore's `vite.config.js`, not global `resolve.conditions` — which would also flip Vue's own build mode), so the local edit→test loop stays instant.
- **Webstore migration is import-path only.** `main.js`, `App.vue`, `DeviceToolbar.vue`, `CommandConsole.vue` now import from `@coda/comment-kit/vue` instead of the bare package — no other webstore-side change. Same Supabase table, same `store`/`deployment_scope` isolation, same `storagePrefix: 'webstore:comments'`.

## Changes

### `packages/comment-kit`

- Deleted: `src/useComments.js`, `src/components/{CommentLayer,CommentThreadPanel,CommentListPanel,CommentIdentityGate}.vue`.
- New: `src/core/store.js`, `src/elements/comment-layer.js`, `src/elements/pins.js`, `src/vue.js`, `vite.config.js`.
- `src/index.js` rewritten as the agnostic entry (`mountComments`, `configureComments`, `defineCommentElements`).
- `package.json`: added `lit` dependency; `vue`/`@supabase/supabase-js` are now optional peers; conditional `exports` (`development` → `src/`, `default` → `dist/`) for entries `.` and `./vue`; version 0.2.0.
- `scripts/publish-comment-kit.sh`: now builds the package first and ships only `dist/` + `sql/` + `README.md` + `package.json` to the `comment-kit` branch (previously shipped raw `src/`).

### Webstore (`src/main.js`, `App.vue`, `DeviceToolbar.vue`, `CommandConsole.vue`, `vite.config.js`)

- Import paths switched to `@coda/comment-kit/vue`.
- `vite.config.js` resolves the comment-kit entries to package source via ordered array-form aliases (dogfooding without a build step).

### Docs

- `packages/comment-kit/README.md` rewritten agnostic-first (Web Component quickstart, then a Vue section).
- `docs/comment-mode.md` file table updated to the new architecture (`core/store.js`, `elements/*`, `vue.js`).
