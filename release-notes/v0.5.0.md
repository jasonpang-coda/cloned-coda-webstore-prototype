# CODM SKU Card 3.0 — v0.5.0

**Responsive 2-column SKU section · guest Player ID lookup + donut loader · guest checkout** · June 2026

Two design-driven additions: a responsive layout demo and a working guest-checkout entry point.

---

## What's new

### Responsive stacked → 2-column SKU section (`SkuList.vue`, `App.vue`)
A new **NEW USERS PROMO** section appended to the end of the page (Figma `5147:23370`) demonstrates the responsive difference between layouts:
- **Mobile (XS/S):** cards stacked **1 per row**.
- **Tablet/desktop (≥ M, container ≥ 801px):** a true **2-column** grid filling the centered `content` span.

Driven by a new `layout` prop on `SkuList` — `'wrap'` (default, existing flex-wrap behaviour) or `'columns'` (explicit CSS grid switched at `@container (min-width: 801px)`). Reuses the existing `PromoBanner` + `promoItems`. Entrance at `DELAY_STACKED = 1000`.

### Guest Player ID lookup + donut loader (`PlayerAccount.vue`)
The Player ID input now runs a simulated lookup (Figma `5147:23613` loading → `5147:23555` result):
- On **blur** or **Enter** with a non-empty field, a **donut spinner** overlays the input and the border turns yellow for ~1.1s (`@keyframes spin` + new `--motion-spinner` token).
- On resolve, the instruction panel fades out and a **Player Card** fades in (reusing the `tab-content` transition), **reflecting the typed value** as the nickname (ID/level/rank are static demo data).
- Typing again cancels the lookup and restores the instructions. Empty + blur/Enter does nothing.

### Guest checkout unlocked (`useCheckout.js`)
`openCheckout()` previously no-op'd unless `signedIn`. It now also passes once a guest has a verified Player ID: a new `guestVerified` flag (+ `setGuestVerified`) is flipped true when the Player Card appears, and re-locked when the guest edits the field or the section unmounts.
