# Release Notes — v0.50.0

**Date:** August 2026
**Milestone:** FCM multi-level (intent/category/subcategory) navigation pilot, behind a runtime feature flag, plus real iOS/Android device status bars

---

## Highlights

- **New FCM-only multi-level navigation pilot** — L1 intent (Store / Loyalty & Rewards / Events) → L2 categories → L3 subcategories, replacing the flat category filter model with three variants a PM can flip between live: `stacked` (L2 + L3 rows), `dropdown` (one breadcrumb-triggered grouped select), and `flat` (a single row, every subcategory flattened, no L2). Toggled from the dev toolbar's store-scoped select or the `/` command palette (`useFeatureFlags` `FLAG_DEFS['fcmNavModel']`) — every other store is unaffected regardless of the flag's value, gated by a new `config.nav.multiLevel` capability that only FCM sets.
- **Every category and subcategory renders on the page at once** — no filtering/hide-show — so a player can discover Silver or FC Points by scrolling, not just by opening a menu. L2/L3 taps `scrollIntoView`; an internal scroll-spy drives the tab highlight and dropdown breadcrumb the other direction as the user scrolls.
- **New `CatalogNavStack.vue`** — the L2/L3 surface. Mounts in normal document flow right after the Best Sellers section (deliberately not part of this nav) and docks via `position: sticky`: visible inline until scrolled past, then sticks below NavBar's new L1 row, undocking again when scrolled back above it.
- **`NavDrawer.vue` now mirrors all three levels** for FCM — L1 as expandable groups, L2 children, and a new L3 tier per category — with hover/active feedback added across all three tab levels (previously text-colour-only).
- **Real iOS/Android device status bars** (`DeviceFrame.vue`, benefits every store) — the `safeTop` band above the screen, previously just reserved empty space, now renders actual time + signal/wifi/battery content matching each platform's convention (SF-Pro-ish "9:41" for iPhone, Roboto-ish "9:30" bottom-aligned for Android), with a researched blur/tint approximation of each platform's real status-bar material.
- **Fixed a docking bug the status bar exposed**: NavBar reports `--navbar-h: 0` while scroll-hidden, which previously let `CatalogNavStack` and the legacy top-subcategory bar ride all the way up to the device screen's true top — now that the status bar is real, always-visible content, that meant both bars docked *underneath* it. Fixed by clamping their offset to `max(var(--navbar-h), var(--safe-top))` everywhere, so no store's docked nav can render beneath the status bar again.

## Changes

### `src/composables/useFeatureFlags.js`

- `FLAG_DEFS` entries can now be **enum flags** (`options: [{ value, label }]`, `default` one of those values) alongside the existing boolean shape — read with the new `flagValue(key)`, set with `setFlag(key, value)` (validated/coerced against the registered options, falling back to `default` on a stale/removed value). `toggleFlag` stays boolean-only.
- New optional `stores: [...]` field scopes where a flag's *toolbar/console control* renders, without splitting the underlying value per store.
- New `fcmNavModel` flag: `'off' | 'stacked' | 'dropdown' | 'flat'`, scoped to `stores: ['fcm']`.

### `src/composables/useStoreCatalog.js`

- New `useStoreIntents()` — returns the active store's `intents` tree (`null` for stores that don't set one), mirroring `useStoreCatalog()`'s existing pattern.

### `src/stores/fcm/intents.js` (new), `src/stores/fcm/store.js`

- `buildFcmIntents(catalog)` wraps FCM's real catalogue as the "Store" intent and adds minimal "Coming soon" stub categories for Loyalty & Rewards and Events.
- `config.nav.multiLevel: true` — the only capability gate multi-level nav ever checks; every other store simply omits this key.

### `src/components/NavBar.vue`

- New L1 intent row (Store / Loyalty & Rewards / Events) inside the existing header — inherits NavBar's scroll hide/show for free and is counted in `--navbar-h` automatically. Full-bleed (cancels `Grid`'s side padding via negative margin), centred tabs, no underline — selected state reads through text colour + a background token alone.
- `--navbar-h-max` — a new, hide-state-agnostic companion to the existing live `--navbar-h`, published so scroll-margin/dock-offset consumers can reserve against NavBar's worst-case (visible) height rather than its transient state at the instant a jump began.
- Header's own `border-bottom`/`padding-bottom` drop to 0 when the L1 row is present (`.navbar--has-intents`), so the header reads as one seamless surface with L1 instead of a hard line and doubled gap.

### `src/components/CatalogNavStack.vue` (new)

- The L2/L3 surface described above. Publishes `--nav-stack-h` (own height + `--navbar-h-max`) for scroll-margin consumers.

### `src/components/CategoryNav.vue`

- New `variant="row"` (+ `level="l2"|"l3"`) — a static in-flow tab strip with no own surface/background/animation, used only by `CatalogNavStack` so two can stack inside its single frosted container. Row-variant tabs: bottom-edge indicator, full bleed, centred, unified L2/L3 padding spec, `min-width: var(--size-control-xl)`.
- Rebuilds its internal scroll-spy when the *set* of tab ids changes (not just on mount) — needed since `CatalogNavStack`'s L3 row swaps tabs to reflect whichever category is currently in view, without remounting.
- `.cat-nav--top` (the legacy subcategory bar, used by every store) now docks at `max(var(--navbar-h), var(--safe-top))` instead of `--navbar-h` alone — see the status-bar docking fix above.

### `src/components/NavDrawer.vue`

- New L3 tier (subcategories) under each L2 category, gated the same way as `CatalogNavStack`'s own L3 row (hidden for a category with only one, e.g. gifts/best-sellers).
- Hover/active states added across L1/L2/L3 (`--bg-indicator-neutral-subtle` hover, `--bg-indicator-neutral-default` + `--text-hyperlink-default` active), reusing the existing "indicator" token family rather than introducing new ones.

### `src/components/DeviceFrame.vue`, `src/components/MaterialIcon.vue`

- Real status bar content (time + `signal_cellular_alt`/`network_wifi`/`battery_full` icons, newly registered in `MaterialIcon.vue`) for both iPhone and Android device frames, clipped to the screen's own rounded top corners.
- Backdrop blur/tint approximating each platform's real status-bar material: iOS 10px blur + `rgba(0,0,0,0.18)`; Android 6px blur + `rgba(0,0,0,0.22)` (Android's own Material 3 guidance favours a gradient scrim over blur — the lighter blur value reflects that flatter convention).

### `src/components/CommandConsole.vue`, `src/components/DeviceToolbar.vue`, `src/components/FilterDropdown.vue`

- `CommandConsole`'s feature-flag command loop branches boolean vs enum flags (one `Enable:`/`Disable:` command vs one command per non-active option).
- `DeviceToolbar` renders a `.toolbar__select` for every enum flag scoped to the active store.
- `FilterDropdown` gained `groups` (grouped options with headers), `triggerLabel` (breadcrumb display instead of a static label), and a `--dropdown-w` custom property — all additive; existing flat/`TransactionHistoryPage` usage is unaffected.

### `src/tokens/ds/semantics.css`, `src/tokens/ds/themes/fcm.css`

- New `--bg-nav-selected` (default `transparent`) — the L1/L2/L3 selected-tab background, FCM-scoped to `--bg-indicator-neutral-subtle`. Replaces an earlier `--gradient-nav-selected` iteration (tried a hand-tuned HDR-glow gradient, then the literal Figma-generated radial-gradient recipe, before settling on the flatter indicator-token approach — see the token's own comment in `fcm.css` for that history).

### `.claude/skills/codm-web-store-fe/SKILL.md`

- New section documenting that `--safe-top` now renders real, permanently-visible status-bar content — not empty space — and the rule that follows: any top-pinned component must offset its own content below it, and anything docking beneath another sticky bar should derive its offset from that bar's *reported* live height rather than a fixed guess.
