# Release Notes — v0.52.2

**Date:** August 2026
**Milestone:** FCM multi-level nav: removed the dead L2/L3 nav bar for Loyalty & Rewards and Events (all presentations)

---

## Highlights

- **Removed the `'stacked'` nav-model variant from testing** — a round of internal testing called out `'stacked'` (L1 + separate, always-visible L2 AND L3 bars — three navigation layers on screen at once) as the weak variant. It's dropped from `fcmNavModel`'s selectable options so testers can't pick it; `CatalogNavStack.vue`'s `presentation="stacked"` implementation is left in the code, just unreachable, in case it's revisited. `'dropdown'` and `'flat'` remain available for a second round of testing. Any `'stacked'` value already persisted in a tester's `localStorage` falls back to `'off'` automatically (existing stale-value handling).
- **New generic `requiresCapability` flag-def option** — hides a flag's dev-toolbar/console control when the static per-store capability it depends on is turned off, so a control never dangles on screen doing nothing. Wired into `fcmNavModel` (`config.nav.multiLevel`) as the first user; same motivation as the existing `hideWhenLocked`, just keyed off store config instead of the build lock.

## Changes

### `src/composables/useFeatureFlags.js`

- Removed the `{ value: 'stacked', ... }` option from `fcmNavModel`'s `options` array.
- New `requiresCapability` flag-def field: a `(config) => boolean` predicate, documented alongside `hideWhenLocked`. Added to `fcmNavModel` as `(config) => !!config.nav?.multiLevel`.

### `src/components/DeviceToolbar.vue` / `src/components/CommandConsole.vue`

- Both flag-control renderers now also skip a def whose `requiresCapability` predicate returns false (`DeviceToolbar` newly imports `useStoreConfig`; `CommandConsole` already had it).

### `docs/fcm-components.md`

- Section 5 updated: `fcmNavModel`'s value union is now `'off' | 'dropdown' | 'flat'`, with a note on why `'stacked'` was removed and that its implementation remains in place.
