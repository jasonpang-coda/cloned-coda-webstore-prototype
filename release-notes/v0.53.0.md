# Release Notes — v0.53.0

**Date:** August 2026
**Milestone:** FCM multi-level nav: new bottom-docked L3 variant for S screens; legacy 'off' option hidden from testing

---

## Highlights

- **New `'flat-bottom-s'` nav-model variant** — same flattened L3 tab list as `'flat'` (every subcategory, no L2), but the dock is responsive: on S screens and smaller it pins to the **bottom** of the screen (the exact same stock `CategoryNav` `variant="bottom"` bar the legacy nav uses), falling back to `'flat'`'s top-docked row on M/L. Mounted in `App.vue`'s DeviceFrame `#overlay` slot, not nested inside `CatalogNavStack` — the latter lives inside `.device__screen`'s own scrolling content, where a fixed/absolute bottom bar would resolve against the full scroll height instead of the visible viewport.
- **`'off'` (legacy bottom-categories + top-subcategories nav) hidden from the picker** — testers can no longer accidentally switch back to it mid-test-round. `fcmNavModel` now defaults to `'dropdown'`. The underlying `!== 'off'` checks in `App.vue` are untouched, just unreachable via the toolbar/console.
- **Live-measured `--nav-stack-bottom-h`** reserves exactly the right space below the last section for the new bottom bar — 0 automatically on M/L, since the bar doesn't mount there at all.
- **JS-measured S/M breakpoint, not CSS `@container`** — `.device__overlay` (the `#overlay` slot) is a sibling of `.device__screen`, not a descendant, so it has no `@container` containment context, and deliberately isn't given its own `container-type` either (that would break `position: fixed` containment for the sign-in loader / checkout modal / snackbar sharing that slot). A small `ResizeObserver` on `.device__screen` (`App.vue`'s `isFlatBottomSmall`) drives the bottom bar's mount/unmount instead, rebuilt on every device-frame switch.

## Changes

### `src/composables/useFeatureFlags.js`

- `fcmNavModel`: removed `'off'` from `options`, default changed from `'off'` to `'dropdown'`; added `{ value: 'flat-bottom-s', ... }`.

### `src/components/CatalogNavStack.vue`

- `'flat-bottom-s'` presentation: identical top-docked row to `'flat'`, hidden on S screens and smaller via a new `.nav-stack--hide-s` class + `@container (max-width: 800px)` rule (this component's own containment context is valid — it's mounted inline inside `.device__screen`'s scrolling content).

### `src/App.vue`

- New `flatBottomTabs` computed (mirrors `CatalogNavStack`'s own flattened-subcategory computed) and `isFlatBottomSmall` ref + `ResizeObserver`.
- New `CategoryNav` (`variant="bottom"`) mounted in the DeviceFrame `#overlay` slot, shown only when `isMultiLevel && navModel === 'flat-bottom-s' && isFlatBottomSmall`.
- New `flatBottomNavRef` + `ResizeObserver` publishing `--nav-stack-bottom-h`; `.app__nav-gap` gains an `.app__nav-gap--nav-stack` modifier consuming it.

### `docs/fcm-components.md`

- Section 5 rewritten to document the hidden `'off'` option, the new `'flat-bottom-s'` variant, and the `@container`-vs-JS-measurement distinction between `CatalogNavStack`'s top row and the new bottom bar.
