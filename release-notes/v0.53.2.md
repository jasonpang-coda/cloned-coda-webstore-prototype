# Release Notes — v0.53.2

**Date:** August 2026
**Milestone:** Fixed the Best Seller card's HDR glow tokens (`--hdr-glow`/`-hot`/`-bloom`) so they alias the palette tier instead of hardcoded or missing literals, and derive their HDR boost via relative colour syntax instead of duplicating it

---

## Highlights

- **COD:M's running border/bloom now has real brand colours.** `--hdr-glow`/`--hdr-hot`/`--hdr-bloom` had no override in `codm.css` at all, so `BestSellerCard`'s ring fell through to an arbitrary global default gold with zero relation to COD:M's own yellow seed. Now aliased to `--palette-primary-{500,200,600}`.
- **FCM and efootball's glow tokens no longer duplicate their brand seeds.** Both stores previously hardcoded `oklch()` literals for `--hdr-glow`/`-hot` (and efootball's `--hdr-bloom`) that merely *happened* to match `--ref-primary`/`--ref-secondary` — a copy-pasted source of truth that would have silently drifted if either brand colour were ever retuned. Now real `var()` aliases.
- **HDR boost is now derived, not duplicated — using CSS relative colour syntax.** `oklch(from var(--source) calc(l * k) calc(c * k) h)` computes the boosted value directly from the same source token the SDR value aliases, rather than a second hardcoded literal. For FCM/efootball's `--hdr-glow`/`-hot`, the boost turned out to already cascade through for free (their `--ref-primary`/`-secondary` seeds are re-boosted in the same `@media (dynamic-range: high)` block) — only the tokens aliasing a mid-ramp palette step needed an explicit derivation. All multipliers for FCM/efootball were reverse-engineered from the *previous* hardcoded values, so rendered output is byte-identical to before; only COD:M gets genuinely new values (a first-pass default, flagged for a design pass in the handoff).
- **Caught a real CSS bug via a full production build, not just editing.** A doc comment reading `--ref-*/--palette-*` accidentally contained `*/`, prematurely closing the CSS comment and turning the rest into invalid syntax — `npm run build` failed with a real PostCSS parse error until fixed. Also verified all three affected store-locked builds (`codm`/`fcm`/`efootball`) and confirmed the relative-colour expressions survive esbuild's CSS minifier intact.

## Changes

### `src/tokens/ds/themes/codm.css`

- Added `--hdr-glow`/`--hdr-hot`/`--hdr-bloom` (SDR aliases to `--palette-primary-{500,200,600}`) and their HDR-boosted derivations inside the existing `@media (dynamic-range: high) { html[data-theme="codm"] { … } }` block.

### `src/tokens/ds/themes/fcm.css`

- `--hdr-glow`/`--hdr-hot` now alias `--ref-primary`/`--ref-secondary` (previously hardcoded duplicates); `--hdr-bloom` now aliases `--palette-primary-700`. Removed the now-redundant HDR-boosted `--hdr-glow`/`-hot` overrides (inherited for free); `--hdr-bloom`'s boost is now a relative-colour derivation.

### `src/tokens/ds/themes/efootball.css`
