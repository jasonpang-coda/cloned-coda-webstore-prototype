# Release Notes — v0.56.3

**Date:** August 2026
**Milestone:** FCM Buy Now pilot — capability-gate fix

---

## Highlights

- **Buy Now flow can no longer leak to other stores.** `fcmPaymentSheet` is a single shared flag (not per-store — see `useFeatureFlags`), and it now defaults to `true`. Without a real per-store gate, switching the active theme to COD:M, eFootball, or Codashop while the flag is enabled would have hidden `CheckoutSheet` there too (the mount condition only checked the flag) and replaced it with a `BuyNowBar`/`OrderSummarySheet` that could never actually open — breaking checkout entirely on every store except FCM.
- **Real fix: a store capability, not just a flag.** Added `config.checkout.buyNow: true` to FCM's store module — the same pattern as `config.checkout.loyalty` or `config.nav.multiLevel`. Every other store omits it, so the flow stays FCM-only regardless of the flag's value.

## Changes

### `src/stores/fcm/store.js`

- New `config.checkout.buyNow: true` — the capability gate for the Buy Now pilot.

### `src/composables/useFeatureFlags.js`

- `fcmPaymentSheet` gained `requiresCapability: (config) => !!config.checkout?.buyNow`, matching the `fcmNavModel`/`fcmSkuCardModel` convention (hides the toolbar/console control when the capability itself is off).

### `src/composables/useCheckout.js`

- `usesBuyNowBar()` now requires `config.checkout?.buyNow` in addition to the flag, so `openCheckout()` can never dock the bar on a store that hasn't opted in.

### `src/App.vue`

- The `#overlay` mount condition for `BuyNowBar`/`OrderSummarySheet` vs `CheckoutSheet` now checks `config.checkout.buyNow && isEnabled('fcmPaymentSheet')` instead of the flag alone — this was the actual regression, since it previously hid `CheckoutSheet` on every store once the flag defaulted on.
