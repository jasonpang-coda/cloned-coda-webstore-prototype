# Release Notes — v0.58.0

**Date:** August 2026
**Milestone:** Optional per-project Basic Auth gate for deployed previews

---

## Highlights

- **New `middleware.js` (repo root).** A Vercel Edge Middleware that enforces HTTP
  Basic Auth — the browser's native username/password prompt — in front of every
  request, before the SPA rewrite in `vercel.json` runs. Applies uniformly to the
  internal all-stores build and every store-locked build (`build:codm`, `build:fcm`,
  …) alike, since it runs at the edge independent of which `--mode` produced the
  bundle.
- **Opt-in per Vercel project, not per repo.** The gate only activates when a
  project's own `BASIC_AUTH_USER`/`BASIC_AUTH_PASSWORD` environment variables are
  set; if either is unset, every request passes through untouched. Because each
  store deploys as its own Vercel project, each one gets its own independent
  credential — e.g. `codm-webstore-prototype.vercel.app` and
  `fcm-webstore-prototype.vercel.app` can use different logins, or none.
- **Credentials never enter git.** They're read server-side from `process.env` at
  request time and are deliberately not `VITE_`-prefixed, so they can never be
  inlined into the client bundle — confirmed via `grep -r BASIC_AUTH dist/` after a
  production build.
- **Constant-time-ish credential comparison** to avoid a trivial early-exit timing
  leak on the username/password check, even though this is a lightweight prototype
  gate rather than hardened security.

## Changes

### `middleware.js` (new)

- `export default function middleware(request)` — reads `BASIC_AUTH_USER`/
  `BASIC_AUTH_PASSWORD`/`BASIC_AUTH_REALM` from `process.env`; passes through via
  `@vercel/edge`'s `next()` when unset or when the request's `Authorization: Basic`
  header matches; otherwise returns `401` with a `WWW-Authenticate: Basic` header so
  the browser shows its native login dialog.
- `export const config = { matcher: [...] }` scoped to every path except Vercel's
  own `_vercel/*` internals, so locked builds don't leak assets to an
  unauthenticated request either.

### `package.json`

- Added `@vercel/edge` (`^1.3.3`) — the framework-agnostic edge middleware runtime
  helper (`next()`), matching how `tools/cms/api/[...path].mjs` already uses
  Vercel's Node function conventions for the CMS.

### `.env.example`

- Documented the new server-only vars (`BASIC_AUTH_USER`, `BASIC_AUTH_PASSWORD`,
  `BASIC_AUTH_REALM`), following the same "server-only, not `VITE_`-prefixed" note
  already used for `VERCEL_TOKEN`/`VERCEL_TEAM_ID`.

### `docs/deploying-individual-stores.md`

- §3 "Optional: access control" rewritten to document the middleware setup
  (per-project env vars, redeploy-to-apply, `vercel dev` for local testing) in place
  of the previous Deployment-Protection-only note, which remains mentioned as a
  plan-gated alternative.

## Verification

- `npm run build` succeeds unchanged; `grep -rl BASIC_AUTH dist/` returns nothing.
- Middleware logic exercised directly in Node (real `Request`/`Response`/`atob`,
  real installed `@vercel/edge`): no env set → pass-through; env set + no header →
  `401`; wrong credentials → `401`; correct credentials → pass-through; non-Basic
  scheme → `401`. All five cases passed.
- Not exercised: a live `vercel dev`/preview-deploy run, since the Vercel CLI isn't
  installed locally — first real edge test will be on an actual Vercel deployment
  once a project's env vars are set.
