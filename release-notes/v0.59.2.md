# Release Notes — v0.59.2

**Date:** August 2026
**Milestone:** `@coda/comment-kit` and `@coda/track-kit` extracted into standalone repos

---

## Highlights

- **Both kits now live outside this repo.** `packages/comment-kit` →
  [`github.com/yiweicoda/comment-kit`](https://github.com/yiweicoda/comment-kit);
  `packages/track-kit` → [`github.com/yiweicoda/site-tracker`](https://github.com/yiweicoda/site-tracker)
  (package stays `@coda/track-kit` — the repo name and the package name don't
  need to match). Pure infra/packaging move: same features, same Supabase
  data, same UI, zero user-facing behavior change.
- **Zero import changes anywhere.** Both package names (`@coda/comment-kit`,
  `@coda/track-kit`) are unchanged, so `src/main.js`'s two `.use(...)` calls
  and every component importing `useComments`/`useTracking` need no edits —
  only *where* the dependency resolves from changed.
- **A real bug caught and fixed before it could bite a consumer.** Both
  packages' `exports` map had a leftover `"development": "./src/*"`
  condition — harmless while the (now-removed) in-repo dev-alias intercepted
  resolution first, but bundlers like Vite auto-inject that condition in dev
  mode regardless of config, and `src/` isn't shipped to installed consumers
  (filtered by the `files` field). Any real consumer's dev server would have
  failed to resolve `@coda/comment-kit/vue` / `@coda/track-kit/vue`. Both
  packages now resolve unconditionally to `dist/`, built automatically on
  install via a new `prepare` script (`npm` runs this for git dependencies).
  Caught by actually booting `npm run dev` against the extracted repo before
  deleting the local copy — a production build alone did not surface it.
- **Existing comment-kit consumers are unaffected.** The old
  `github:yiweicoda/coda-webstore-prototype#comment-kit` branch install stays
  live and frozen (deprecation notice added on top, no force-push, no
  history rewrite) — verified with a fresh `npm install` against it after
  the extraction. `scripts/publish-comment-kit.sh` and the `kit:publish`
  script are removed (built from the now-gone local folder).

## Changes

### New repos (not part of this repo's history)

- `github.com/yiweicoda/comment-kit` — `@coda/comment-kit` v0.3.0, single
  initial commit, standalone build verified (`npm install && npm run build`
  with no dependency on this repo).
- `github.com/yiweicoda/site-tracker` — `@coda/track-kit` v0.1.0, same.

### `package.json`

- `"@coda/comment-kit": "*"` → `"github:yiweicoda/comment-kit"`.
- `"@coda/track-kit": "*"` → `"github:yiweicoda/site-tracker"`.
- Removed the `kit:publish` script.

### `vite.config.js`

- Removed the four dev-aliases (`@coda/comment-kit`, `@coda/comment-kit/vue`,
  `@coda/track-kit`, `@coda/track-kit/vue`) that pointed at the local
  workspace paths. Both packages now resolve from `node_modules` normally,
  via each package's own `exports` map.

### `packages/comment-kit/`, `packages/track-kit/`, `scripts/publish-comment-kit.sh`

- Deleted — moved to their new repos.

### `src/main.js`

- Two stale comments corrected (`// lives in packages/*-kit` →
  the new repo references).

### `docs/comment-mode.md`, `docs/session-tracking.md`, `docs/README.md`

- Callouts rewritten to describe the standalone repos + `github:` install
  instructions instead of the old monorepo-subfolder pattern. `comment-mode.md`
  documents migrating off the frozen `#comment-kit` branch.

## Verification

- `npm install` in this repo resolves both packages from their new repos
  (`package-lock.json` shows `git+ssh://...#<sha>` resolutions, no stale
  workspace entries after a full `rm -rf node_modules package-lock.json &&
  npm install`).
- `npm run dev` boots cleanly — confirmed via `curl` against the running dev
  server that `@coda/comment-kit/vue` and `@coda/track-kit/vue` both resolve
  into Vite's pre-bundled deps with no import-analysis errors (this is the
  check that actually exercises the `exports` map's dev-mode condition;
  `npm run build` alone would not have caught the bug described above).
- `npm run build` (the command Vercel runs) succeeds end-to-end.
- Fresh-cloned each new repo to a temp directory and ran `npm install && npm
  run build` standalone — both succeed with zero dependency on this repo
  being present.
- Fresh `npm install github:yiweicoda/coda-webstore-prototype#comment-kit`
  (the old branch install) still succeeds unchanged, confirming existing
  external consumers are unaffected.
