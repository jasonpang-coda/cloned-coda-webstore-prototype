# Release Notes — v0.59.3

**Date:** August 2026
**Milestone:** Hotfix — Vercel builds failing after the v0.59.2 kit extraction

---

## Highlights

- **Vercel's `npm install` was failing outright** with `Permission denied
  (publickey)` on every project building this repo, immediately after
  v0.59.2's `@coda/comment-kit`/`@coda/track-kit` extraction. Root cause:
  npm/pacote **canonicalizes any recognized GitHub git dependency to a
  `git+ssh://git@github.com/...` URL when writing `package-lock.json`'s
  `resolved` field** — regardless of what protocol `package.json` specifies,
  and regardless of whether the machine that generated the lockfile even has
  working SSH access to GitHub (confirmed: it does this even when
  `ssh -T git@github.com` fails locally). A later `npm install` elsewhere
  fetches from that exact recorded URL, and Vercel's build container has no
  SSH key for either repo.
- **The fix is a git-level URL rewrite, not a package.json change.** Tried
  and ruled out first: forcing an explicit `git+https://…` URL in
  `package.json` (npm still canonicalizes to `ssh://` in the lockfile
  regardless), and embedding `${TOKEN}` directly in the dependency URL string
  (npm does not do environment-variable substitution inside dependency
  version specs — it percent-encodes the literal text and fails auth). The
  actual fix: a `git config url.insteadOf` rewrite rule, applied via each
  Vercel project's **Install Command**, that intercepts the SSH URL npm
  insists on using and silently redirects it to an authenticated HTTPS URL
  before git ever sees it — see the new **"Private git dependencies on
  Vercel"** section in
  [docs/deploying-individual-stores.md](../docs/deploying-individual-stores.md).
- **Local dev is unaffected** — a working `gh auth login` (or a real SSH key
  registered with GitHub) already resolves both dependencies fine locally;
  the rewrite is only needed where no such credential helper exists (CI/Vercel).

## Changes

### `package.json`, `package-lock.json`

- `@coda/comment-kit` and `@coda/track-kit` dependency specs changed from
  `github:owner/repo` shorthand to explicit `git+https://github.com/owner/repo.git`
  URLs — cosmetic/documents intent, but does not change npm's lockfile
  canonicalization behavior (see above); the real fix lives entirely in the
  Vercel Install Command.

### `docs/deploying-individual-stores.md`

- New **"Private git dependencies on Vercel"** subsection under §3 (Deploy to
  Vercel) documenting the required Install Command and `GH_PACKAGES_TOKEN`
  environment variable (a fine-grained PAT scoped to only the `comment-kit`
  and `site-tracker` repos, Contents: Read-only) — needed on **every** Vercel
  project building this repo, not just the ones that happen to touch
  comment/tracking code.
- §6 (adding a new store to the deploy lineup) cross-references the same
  section so a freshly created project doesn't repeat this outage.

## Verification

- Confirmed locally (via this machine's own `gh`-authenticated git credential
  helper) that a `git config url."https://github.com/".insteadOf
  "ssh://git@github.com/"` rewrite correctly redirects an `ssh://` fetch to
  `https://` and succeeds — proving the rewrite mechanism itself, then
  reverted the test config immediately.
- `npm install` (clean, no cached `node_modules`/lockfile) and `npm run
  build` both succeed with the updated dependency specs.
- **Still needed from the user:** create the `GH_PACKAGES_TOKEN` fine-grained
  PAT and add the Install Command + env var to each live Vercel project
  (`sku-card-fcm`, `sku-card-codm`, `sku-card-internal`, and any others) —
  this could not be verified end-to-end without handling that token directly,
  which is intentionally out of scope for an automated change.
