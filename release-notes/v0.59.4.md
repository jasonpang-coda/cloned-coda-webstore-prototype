# Release Notes — v0.59.4

**Date:** August 2026
**Milestone:** Hotfix — the v0.59.3 Install Command silently dropped its own SSH rewrite rule

---

## Highlights

- **The v0.59.3 fix didn't actually work** — Vercel builds still failed with
  the same `Permission denied (publickey)` error even after the Install
  Command and `GH_PACKAGES_TOKEN` were configured. Root cause: `git config
  url.<base>.insteadOf` is a **multi-valued** config key, but the documented
  Install Command called `git config --global url.X.insteadOf Y` **twice**
  without `--add` — the second call **silently overwrote** the first instead
  of adding a second value. The overwritten rule was the one that actually
  mattered: `insteadOf "ssh://git@github.com/"`, the literal URL form npm
  fetches (per v0.59.3's own diagnosis). Confirmed locally with a throwaway
  `$HOME` sandbox: two sequential `git config --global url.X.insteadOf Y`
  calls left only the *second* value in `~/.gitconfig`; adding `--add` to
  both calls correctly persisted both values, and an end-to-end `git
  ls-remote ssh://git@github.com/...` fetch then succeeded via the rewritten
  HTTPS URL.
- **Fix:** add `--add` to both `git config --global` calls in the Install
  Command. No `package.json`/dependency changes this time — purely the
  Vercel-side command string, documented in
  [docs/deploying-individual-stores.md](../docs/deploying-individual-stores.md).

## Changes

### `docs/deploying-individual-stores.md`

- Install Command in "Private git dependencies on Vercel" corrected to use
  `git config --global --add url.….insteadOf …` (both calls), with an
  explanation of why the missing `--add` silently broke the rule that
  mattered.

## Verification

- Reproduced the bug in an isolated `$HOME` sandbox: two `git config
  --global url.X.insteadOf Y` calls (no `--add`) left only one value in
  `.gitconfig`.
- Confirmed the fix in the same sandbox: two `--add` calls correctly persist
  both `insteadOf` values.
- Confirmed an actual `git ls-remote ssh://git@github.com/...` fetch is
  redirected to HTTPS and succeeds with the corrected rule set (using this
  machine's own working git credentials as the stand-in auth — the real
  `GH_PACKAGES_TOKEN` substitution was not re-verified end-to-end on Vercel
  itself, since that requires the user's live token and project settings).
