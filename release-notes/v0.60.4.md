# Release Notes — v0.60.4

**Date:** August 2026
**Milestone:** Session tracker button hidden on store-locked builds, kept reachable via `/` console

---

## Highlights

- **Session tracker no longer clutters store-locked ("isolated") builds.** The
  📊 button in the DeviceToolbar is now hidden on store-locked builds
  (`build:fcm` / `build:codm`), matching the library/inspector/screenshot
  tools that were already gated the same way. The tracker itself — viewer,
  heatmap, scroll depth, pause/resume — stays fully reachable there through
  the `/` command console, which now mounts on every build instead of being
  stripped entirely from store-locked ones.

## Changes

### `src/components/DeviceToolbar.vue`

- Session tracker button's segment now gated `v-if="!isStoreLocked"`.
- Updated stale comments describing tracking's toolbar availability and
  comment mode's role as the sole non-dev entry point on locked builds.

### `src/App.vue`

- `CommandConsole` is no longer conditionally mounted with
  `v-if="!isStoreLocked"` — it now mounts on every build. Its own command
  registry already excludes the store-locked-incompatible Tools commands
  (library, inspector, screenshot), so nothing broken is newly exposed;
  the session-tracker commands were already registered unconditionally.
- The `/` keydown listener (`onGlobalKey`) is now always registered in
  `onMounted`/`onBeforeUnmount`, instead of only when the build isn't
  store-locked or comment mode is enabled.

### Docs

- `docs/command-console.md`, `docs/component-breakdown.md`,
  `docs/session-tracking.md` updated to describe the console mounting on
  every build and the session-tracker commands' unconditional registration.

## Verification

- `vite build --mode fcm` (store-locked) builds clean; `LibraryViewer`/
  library+registry+stories chunks remain absent from the bundle, confirming
  the console's presence didn't drag in store-locked-incompatible code.
