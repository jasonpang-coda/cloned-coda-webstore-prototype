# Release Notes — v0.61.0

**Date:** August 2026
**Milestone:** Promo Code section on the payment sheet, plus device-mockup stability fixes

---

## Highlights

- **Promo Code section.** `OrderSummarySheet` (the FCM Buy Now pilot's
  payment step) gained a collapsible "Have a promo code?" section — a new
  `PromoCode.vue` component — sitting below a renamed "Total Payment" row.
  Applying the prototype demo code (`SAVE10`) adds a discount line and
  recomputes the total; an invalid code shows an inline error state; a
  success state links to a small "Promo Code Details" modal.
- **Device mockup no longer shifts during use.** Two independent causes were
  found and fixed: (1) the device-scale calculation used a fixed guess for
  the preview toolbar's height instead of its real, live height, which could
  let the toolbar+device pair exceed the browser window and force the
  *outer* page to scroll — at which point an in-app category jump
  (`scrollIntoView`) would drag the whole device mockup up behind the sticky
  toolbar; (2) on-screen keyboards shrinking `window.innerHeight` on mobile
  browsers were re-triggering the same rescale on every text-field tap.
- **Device notch/status bar now renders above sheets.** The hardware chrome
  layer was `z-index: 20`, below the sheet-overlay layer's `z-index: 40` —
  the opposite of a real phone, where the notch/status bar always sits above
  app content. Bumped to `z-index: 45`.
- **The reseller/legal disclaimer bar animates properly.** Its expand/collapse
  was a hard `display: none`/`block` snap with no transition at all — now
  uses the same grid-rows accordion technique as `ItemSummaryAccordion`.

## Changes

### `src/components/PromoCode.vue` (new)

- Collapsible mini-accordion (grid-rows height transition, matching
  `ItemSummaryAccordion`/`.osum__detail`) with idle / error / applied states
  cross-faded via `<Transition mode="out-in">` — opacity-only, matching
  `ClaimGiftSheet`'s existing `claim-footer` timing (150ms accelerate-out /
  250ms decelerate-in).
- First real consumer of `--border-input-error`, `--bg-input-error`, and
  `--border-input-success` — tokens that existed in the design system but
  had no component using them yet.
- Hardcoded demo validation (`SAVE10` → 10% discount); emits `applied` /
  `removed` / `show-terms` to the parent sheet.

### `src/components/OrderSummarySheet.vue`

- "Total" row relabeled "Total Payment" (new locale key `totalPayment`,
  added English-only — other locales fall back automatically).
- Mounts `<PromoCode>` below Total Payment; a "Promo Discount" row appears
  between Tax and Total Payment once a code is applied, and Total Payment
  recomputes to reflect it.
- New small centered `promo-modal` (scrim + frosted panel, scale+fade,
  `z-index: 5`) for the promo's "Terms and Conditions" details, rendered as
  a sibling of `.sheet__panel` so it isn't clipped by the panel's own
  `overflow: hidden`.
- Increased the Order Summary card's bottom padding.

### `src/components/MaterialIcon.vue`

- Added the `discount` icon (used by `PromoCode`'s header).

### `src/locale/commonStrings.js`

- New `checkout.*` keys for all Promo Code copy (English only).

### `src/composables/useDeviceScale.js`

- Replaced the fixed `VERTICAL_MARGIN` guess with the toolbar's live
  `--toolbar-h` custom property, so the device mockup always scales to fit
  alongside whatever the toolbar's *actual* current height is.
- Added a focus-guard (`frameRootRef`, new 3rd param): skips rescaling while
  an input inside the device frame is focused, re-checking once focus
  leaves — stops on-screen-keyboard-driven `resize` events from visibly
  shifting the mockup while typing.
- Resize/focus listeners debounced 120ms.

### `src/components/DeviceToolbar.vue`

- Its `ResizeObserver` callback now also dispatches a `window` `resize`
  event after updating `--toolbar-h`, so `useDeviceScale` re-fits
  immediately when the toolbar's own height changes (expand/collapse, row
  count) — not just on a real window resize.
- Removed the `setCollapsed(isMobile.value)` call from `setup()` (which
  re-runs on every mount and could clobber the toolbar's collapsed state);
  the seed now lives in `useToolbarCollapse` itself, at module-eval time.

### `src/composables/useToolbarCollapse.js`

- Seeds `collapsed` from `matchMedia('(pointer: coarse)...')` once, at
  module evaluation, instead of on every `DeviceToolbar` mount.

### `src/components/DeviceFrame.vue`

- `.device__island` / `.device__punch` / `.device__statusbar` bumped from
  `z-index: 20` to `45` (above `.device__overlay`'s `40`).
- `.device` gained `transition: transform` so any legitimate rescale settles
  instead of snapping; new `frameRootRef` template ref wired into
  `useDeviceScale`.

### `src/App.vue`, `src/components/CatalogNavStack.vue`

- All six `scrollIntoView()` call sites used for category/subcategory
  navigation now scroll only the phone mockup's own `.device__screen`
  container directly (new shared `scrollIntoScreen()` helper in `App.vue`,
  matching logic in `CatalogNavStack`'s `scrollToId`) — a bare
  `el.scrollIntoView()` walks up every scrollable ancestor it finds, which
  could include the outer preview page.

### `src/components/ResellerBanner.vue`

- Expand/collapse now uses `grid-template-rows: 0fr → 1fr` + an
  `overflow: hidden` inner wrapper (`--motion-accordion`) instead of a hard
  `display: none`/`block` toggle.

## Verification

  modal flow on FCM's Order Summary sheet; notch/status-bar rendering above
