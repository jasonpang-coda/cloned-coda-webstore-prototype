# Release Notes — v0.62.0

**Date:** August 2026
**Milestone:** Unified single-surface purchase flow (`BaseSheet` + `PurchaseSheet`) across every store, replacing the cross-mount sheet handoff

---

## Highlights

- **One shared sheet chrome, not five copies.** New `src/components/base/BaseSheet.vue`
  extracts the scrim, frosted panel, slide-up/responsive-modal motion,
  Escape-to-close, and bottom scroll-fade that used to be duplicated across
  `CheckoutSheet`, `OrderSummarySheet`, `ItemSummarySheet`, `ClaimGiftSheet`,
  `SignInSheet`, `RegionSelectorSheet`, and `LanguageSelectorSheet`. Every one
  of those sheets now mounts `BaseSheet` and supplies only its own content.
- **A content-descriptor seam, shaped like a future content microservice.**
  New `src/content/sheetContent.js` resolves each purchase step's copy/data
  synchronously today from the existing whitelabel stores; the function
  signature is exactly what an async `fetch('/content/' + stepId)` call would
  look like, so swapping in a real service later touches only this one file.
- **Every store's purchase flow is now ONE persistent surface.** New
  `PurchaseSheet.vue` + `usePurchaseFlow.js` replace the old two-or-three
  component cross-mount handoff (`ItemSummarySheet` ⇄ `CheckoutSheet`/
  `OrderSummarySheet`, coordinated through a captured-height singleton,
  `useSheetTransition.js`) with one `BaseSheet` instance whose body/footer
  swap in place via a resize + cross-fade engine. This directly fixes the two
  bugs reported against the old architecture: the info→payment transition
  reading as a snap/cross-fade instead of a true grow/shrink, and two sheets
  visibly overlapping in the responsive centered-modal layout (a shorter info
  card doesn't fully occlude a taller checkout card behind it) — with a
  single surface, a second overlapping card is now structurally impossible.
- **COD:M's "Item Info" back-nav** (tap the link on the checkout step → view
  the bundle breakdown → close returns to checkout) is now an in-sheet step
  override rather than a second sheet peeking through from underneath.
- **Account name is no longer hardcoded.** The signed-in/guest player name
  shown across every purchase step (info, payment, checkout) previously said
  the literal string `"codayw"` in a few templates regardless of who was
  actually signed in or which Player ID a guest looked up. Now resolved once,
  correctly, via a shared `resolveAccountName()` helper.
- **Per-store legal text, not one shared paragraph.** The payment sheet's
  Terms & Conditions body used to be a single EA-flavoured paragraph in the
  shared `common.checkout` strings dictionary, applied to every store.
  Each store now supplies its own `strings.checkout.termsBody`.
- **Terms link hides when the terms already fit on screen** — a "View Terms
  and Conditions" link is redundant once the legal bar it jumps to is
  already visible without scrolling.
- **Removed the placeholder `test` store** (`src/stores/test/`) from the
  store switcher — a CMS scaffold store with placeholder assets that had no
  real content and wasn't meant to ship.

## Changes

### `src/components/base/BaseSheet.vue` (new)

- Owns all sheet chrome: `open`/`isMobile`/`scrim`/`dismissable`/`sizeHint`
  (`'tall'`/`'full'`/`'compact'`/`'content'`/`'content-full'`)/`contentKey`/
  `duration` props; `#header`/default(body)/`#footer` (scoped:
  `{ canScrollBody }`)/`#pre-footer`/`#panel-overlay`/`#overlay` slots;
  `close`/`after-enter`/`after-leave` emits; `defineExpose({ panelEl, bodyEl })`.
- The resize + cross-fade engine: on a `contentKey` change while `open`,
  measures the old panel height, cross-fades body/footer to opacity 0,
  measures the new natural height, then animates `height` old→new while the
  new content fades in — no opacity manipulation on the panel itself, so the
  box growing/shrinking IS the entire transition (never a cross-mount fade).
- Single shared `useBottomFade` instance (was one per sheet).

### `src/content/sheetContent.js` (new)

- `fetchSheetContent(stepId, ctx)` → `infoDescriptor` / `paymentDescriptor`
  (FCM promo-code view) / `checkoutDescriptor` (every default store's 2×2
  channel grid) — each a plain serializable `{ stepId, view, title, sizeHint,
  dismissable, primaryAction, data }`.
- `resolveAccountName(ctx)` — signed-in → `useAuth().playerName`, else
  guest-verified → `useCheckout().guestPlayerName`, else `null`. Replaces
  every hardcoded `'codayw'` literal across the purchase-flow templates.

### `src/composables/usePurchaseFlow.js` (new, replaces `useSheetTransition.js`)

- `currentStep` derives from `useItemSummary().summaryOpen` /
  `useCheckout().sheetOpen`, with `usesPaymentView` (`config.checkout.buyNow
  && isEnabled('fcmPaymentSheet')`) selecting the `'payment'` vs `'checkout'`
  step view once the sheet is open.
- `stepOverride` layers COD:M's bidirectional "Item Info" back-nav on top of
  the derived step — `viewInfo()`/`viewPayment()` drive it, auto-reset on a
  fresh external flow or a full close.
- Ports the sign-in auto-reopen watcher that used to live inside
  `ItemSummarySheet.vue` (`watch(signedIn)` + `pendingReturn`).

### `src/components/PurchaseSheet.vue` (new, replaces `CheckoutSheet.vue`, `ItemSummarySheet.vue`, `OrderSummarySheet.vue`)

- Three step views rendered from `descriptor.data`, each split into a
  presentational `*StepBody.vue` + `*StepFooter.vue` pair
  (`src/components/steps/`): `InfoStepBody`/`InfoStepFooter`,
  `PaymentStepBody`/`PaymentStepFooter` (FCM), and new
  `CheckoutStepBody`/`CheckoutStepFooter` (every default store — faithful
  port of the old `CheckoutSheet.vue`'s content).
- `onBuyNow()` branches correctly for non-FCM stores now (previously only
  worked for FCM's Buy Now bar path; a plain SKU-card checkout would have
  silently no-op'd through `openPaymentSheet()`).
- Loyalty-earn banner rendered via `#pre-footer`, gated to the checkout step.

### `src/App.vue`

- Mounts `<PurchaseSheet>` unconditionally — the old `usesPurchaseSheet`
  flag branch that chose between `PurchaseSheet` and the
  `ItemSummarySheet`+`CheckoutSheet` pair is gone. `BuyNowBar` alone stays
  gated on the FCM two-gate check (`showBuyNowBar`).

### `src/components/ClaimGiftSheet.vue`

- Migrated onto `BaseSheet` — the confirm↔success body swap now uses
  `BaseSheet`'s `contentKey` engine directly instead of this component's own
  bespoke height-morph hooks.
- Upsell CTA simplified to a plain `openCheckout(upsellItem);
  closeGiftClaim()` — no more `handoffHeight` capture, since `PurchaseSheet`
  is always mounted and just opens fresh with its own entrance animation.

### `src/components/SignInSheet.vue`, `RegionSelectorSheet.vue`, `LanguageSelectorSheet.vue`

- Migrated onto `BaseSheet` (chrome-only — no step engine, no content
  descriptor). `SignInSheet` passes `:scrim="false"`; the outside-tap/Escape
  dismissal it used to implement itself now lives in `BaseSheet`.

### `src/locale/commonStrings.js`, `src/stores/{codm,fcm}/store.js`

- `common.checkout.termsBody` (a single EA-flavoured paragraph applied to
  every store) replaced with `termsBodyGeneric` (neutral fallback, no
  company name); COD:M and FCM each gained their own
  `strings.checkout.termsBody`.

### Deleted

- `src/components/CheckoutSheet.vue`, `src/components/ItemSummarySheet.vue`,
  `src/components/OrderSummarySheet.vue`, `src/composables/useSheetTransition.js`,
  `src/library/stories/CheckoutSheet.stories.js`.
- `src/stores/test/` (placeholder CMS scaffold store) and
  `src/tokens/ds/themes/test.css`.

## Verification

- `node_modules/.bin/vite build` passes throughout.
- Verified live in the Browser pane (both framed/mobile and Responsive):
  COD:M direct SKU tap → single-surface checkout; bundle child-tile tap →
  info step → BUY NOW → morphs in place into checkout; "Item Info" link from
  checkout → info step overlay → close (×) returns to checkout underneath,
  not a full cancel; no dual-sheet overlap in the responsive centered-modal
  layout; guest Player ID and a custom test ID both correctly reflected in
  the account row across all three steps (previously hardcoded `"codayw"`);
