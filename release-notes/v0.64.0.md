# Release Notes — v0.64.0

**Date:** August 2026
**Milestone:** Reconciled the token system with the latest prod structure — every DS token renamed under an `--x-` prefix, a batch of missing interactive-state/accent tokens added, and a real light-store (Codashop) rendering bug caught and fixed along the way

---

## Highlights

- **Every design token renamed with an `--x-` prefix.** Prod moved to a namespaced
  token system (`--x-sys-colour-*`, `--x-bg-*`, `--x-palette-*`, etc.) while this repo
  stayed unprefixed. Brought the two back in line: every `--ref-*`, `--palette-*`,
  `--sys-*`, `--bg-*`, `--text-*`, `--border-*`, `--pad-*`, `--gap-*`, `--radius-*`,
  `--size-*`, `--motion-*`, `--blur-*`, `--hdr-*`, and brand/extension token
  (`--fx-*`, `--shadow-*`, `--rarity-*`, `--konami-*`, `--ea-*`, etc.) now carries the
  `--x-` prefix, in both its definition and every consumer — ~5,470 occurrences across
  ~130 files. `--border-weight-*` is the one deliberate exception (kept bare, matching
  prod). One dynamic template-literal reference (`Thumbnail.vue`'s
  `` `var(--size-img-${size})` ``) needed a manual follow-up since the mechanical
  rename can't see through string interpolation. `--text-text-on-brand` was also
  renamed to `--x-text-on-brand`, dropping a doubled `text-` that prod's naming
  doesn't have.
- **New interactive-state, accent, and misc tokens** ported from prod's token
  structure: `--x-bg-action-*-hover/-pressed` for every action variant,
  `--x-border-action-hover/-focused/-pressed`, `--x-bg-sku-card-hover/-pressed/-focused`,
  `--x-bg-input-disabled`, `--x-border-input-disabled/-selected`, `--x-bg-section-alt`,
  `--x-border-popover`/`-player-card`, `--x-text-input-focused`, `--x-bg-callout-1/-2`,
  and new sys-tier accent/brand-secondary/shadow-colour roles
  (`--x-sys-surface-accent-*`, `--x-sys-border-accent`, `--x-sys-brand-secondary-*`,
  `--x-sys-shadow-color-*`). All default to values tuned for a dark surface (this
  repo's reference store, COD:M, is dark) and alias the tier directly above rather
  than bypassing to a raw palette step. Deliberately **not** ported: prod's
  `--x-haptic-*` CSS tokens — this repo's haptic feedback is JS-driven end to end
  (`src/tokens/haptics.js` + `useHaptics`), and CSS-var haptics would have had zero
  consumers.
- **Caught and fixed a real Codashop bug before it shipped.** A full per-store audit
  of how every new token resolves (`docs/token-reconcile.md`) found that Codashop —
  the one light-surfaced store — would have rendered the new
  `--bg-sku-card-hover/-pressed/-focused`, `--bg-input-disabled`, and
  `--border-input-disabled` tokens as a dark-purple smudge on its white SKU cards:
  they all resolve through `--sys-colour-neutral-subtle/-soft`, which nothing
  repoints for a light store. Fixed with a scoped override block in
  `themes/codashop.css`, matching the light-neutral values already used for that
  store's L1–L3 surface remap.
- **What's intentionally unchanged.** This repo's `--sys-colour-surface-l1/l2/l3-*`
  and status-fill tokens are a superset prod doesn't have — kept as-is. Also kept:
  one theme per store (no adoption of prod's dual `theme-preset--`/
  `theme-preset-edge--` light/dark selector model), and no palette `*-alpha-dark/
  -light-*` generating formula.

## Changes

### `src/tokens/ds/{system,semantics,space,text-styles,extensions}.css`

- Every token definition renamed under the `--x-` prefix.
- `system.css`: added `--x-sys-surface-accent-main/-inverse`, `--x-sys-border-accent`,
  `--x-sys-brand-secondary-main/-strong`, `--x-sys-shadow-color-brand/-neutral/-dark`.
- `semantics.css`: added the full interactive-state batch (action hover/pressed for
  every variant, sku-card hover/pressed/focused, input disabled/selected, border-action
  states) plus `--x-bg-section-alt`, `--x-border-popover/-player-card`,
  `--x-text-input-focused`, `--x-bg-callout-1/-2`.
- `space.css`: added `--x-states-hover/-pressed` (generic overlay-wash tokens for
  surfaces with no dedicated hover/pressed pair of their own).

### `src/tokens/ds/themes/*.css` (all 11 stores)

- Every seed/spectrum/typography/override token renamed under the `--x-` prefix.
- `codashop.css`: new override block repointing `--x-bg-sku-card-hover/-pressed/-focused`,
  `--x-bg-input-disabled`, and `--x-border-input-disabled` to light `--palette-neutral-50/
  100/200` steps (see Highlights above).

### `src/tokens/{motion,motion-sku,motion-trust,effects,keyframes}.css`

- Every `--motion-*`/`--fx-*`/`--shadow-*` token renamed under the `--x-` prefix.

### `src/components/`, `src/composables/`, `src/handoff/`, `src/library/`, `src/stores/`

- Every `var(--…)` consumer updated to the renamed `--x-…` token.
- `Thumbnail.vue`: dynamic `` `var(--size-img-${size})` `` template literal manually
  updated to `` `var(--x-size-img-${size})` `` (the static rename can't rewrite a
  string-interpolated token name).

### `docs/token-reconcile.md` (new)

- Full audit: what changed, per-store fit for every new token (all 11 stores), the
  Codashop fix, and a list of cosmetic follow-ups intentionally left open (FCM's
  sku-card hover/pressed flattening its gradient fill, MGSSE's off-brand grey,
  eFootball/Rogue Trader's flat-vs-textured seams, YGO Duel Links' inverted
  L1↔L3 convention to double-check in QA).

### `docs/color-tokens-codm.md`, `docs/design-tokens-codm.md`, `docs/design-tokens-fcm.md`, `docs/motion-tokens.md`

- Flagged with a note that token names cited in these docs predate the `--x-`
  rename — a follow-up content pass should update every reference.
