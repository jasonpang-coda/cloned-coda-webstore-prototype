# Release Notes — v0.65.0

**Date:** August 2026
**Milestone:** New light + material token system, `.fx-shimmer` made material-aware, and a small alignment fix

---

## Highlights

- **New `src/tokens/light.css`.** A single shared scene light — `--x-light-azimuth`
  (315° default, matching COD:M's own implied light), `--x-light-elevation`,
  `--x-light-angular-size` (the "hard vs soft light" axis), `--x-light-color`,
  `--x-light-ambient-color` — plus a derived `--x-light-gradient-angle`
  (`azimuth + 180deg`) that any gradient standing in for a lit surface can
  trace back to, instead of each one hand-picking its own angle. Sanity
  check: at the default azimuth this resolves to `135deg`, the exact value
  `--x-gradient-thumb-gloss` already hand-picked independently.
- **New `src/tokens/materials.css`.** Composable per-material axes — `-f0`,
  `-diffuse-albedo`, shimmer/ambient shape — for six materials: `metal-gloss`,
  `metal-matte`, `glass-clear`, `glass-frost`, `paper-coated`, `paper-uncoated`.
  Deliberately not one closed preset switch: a component overrides just the
  one axis it needs (e.g. only `-f0` for a border tint) rather than being
  forced through an opaque "apply this whole material" flag. `metal-gloss`'s
  shimmer gradient is asymmetric (long dim trailing tail, sharp leading edge —
  confirmed against `@keyframes shimmer-loop`'s actual travel direction) and
  hue-shifts from an F0-tinted core to the light colour at the rim. Matte
  metal and uncoated paper deliberately have **no** shimmer/sweep token at
  all — per the physics, neither supports a travelling highlight, and adding
  one would codify the wrong material rather than fill a gap.
- **`.fx-shimmer` materialized.** New `.fx-shimmer--metal-gloss`/`--glass`/
  `--paper-coated` modifier classes (override only the `::after` background,
  sourced from `materials.css`) and a new `.fx-ambient-swell`/`--metal-matte`
  for the non-travelling matte case (opacity breathes via the existing
  `pulse` keyframe — nothing travels across the surface). All 7 existing
  `.fx-shimmer` CTA instances — `BuyNowBar.vue`, `ClaimGiftSheet.vue` (×2),
  and the Payment/Checkout/Info step footers — migrated to
  `.fx-shimmer--metal-gloss`, each with `-shimmer-core` set to that button's
  own fill token, so the sweep now visibly tints toward each button's actual
  brand colour instead of a generic white streak.
- **Perf hygiene, bundled in:** `.fx-shimmer::after`'s base transform and the
  `shimmer-loop`/`gloss-sweep` keyframes switched `translateX` → `translate3d`
  for a guaranteed promoted compositor layer.
- **Small fix:** `InfoStepFooter.vue`'s "or" divider (between the SIGN IN
  button and "Sign in with your COD:M ID") was left-aligned inside its
  full-width flex-stretched `<span>` — added `text-align: center`.

## Changes

### `src/tokens/light.css` (new)

- `--x-light-azimuth`/`-elevation`/`-angular-size`/`-color`/`-ambient-color`
  and the derived `--x-light-gradient-angle`. `-elevation` and
  `-ambient-color` are declared with no consumer yet in this pass — reserved
  for a future shadow-system follow-up (penumbra/offset derivation), not a
  silent side effect of this change.

### `src/tokens/materials.css` (new)

- Six materials' worth of `-f0`/`-diffuse-albedo` axes, plus
  `-shimmer-angle`/`-core`/`-rim`/composed `-shimmer-gradient` for the three
  sweep-capable materials (`metal-gloss`, `glass-clear`/`glass-frost` sharing
  one mechanism, `paper-coated`) and `-ambient-color` for `metal-matte`.
  Fresnel-rim-strength and shadow-contact-hardness axes deliberately deferred
  — no component consumes them yet, so adding them now would be speculative.

### `src/tokens/effects.css`

- `.fx-shimmer--metal-gloss`/`--glass`/`--paper-coated` modifiers added.
- New `.fx-ambient-swell` base class + `--metal-matte` modifier.
- `.fx-shimmer::after`'s base `transform`: `translateX` → `translate3d`.
- `.fx-ambient-swell::after` added to the `prefers-reduced-motion` block.

### `src/tokens/keyframes.css`

- `shimmer-loop`/`gloss-sweep`: `translateX` → `translate3d`. Visual keyframe
  values (`-150%` → `150%`) unchanged.

### `src/main.js`

- New imports for `light.css`/`materials.css`, ordered after `extensions.css`
  and before the motion/keyframes/effects block.

### `src/components/BuyNowBar.vue`, `ClaimGiftSheet.vue`, `steps/PaymentStepFooter.vue`, `steps/InfoStepFooter.vue`, `steps/CheckoutStepFooter.vue`

- All 7 `.fx-shimmer` CTA instances gained the `fx-shimmer--metal-gloss`
  modifier; each button's `--x-fx-shimmer-color` override replaced with
  `--x-material-metal-gloss-shimmer-core` set to that button's own existing
  fill token (`--x-bg-action-primary` or `--x-text-hyperlink-default`,
  confirmed per-file, not assumed).
- `InfoStepFooter.vue`: `.isum__or` gained `text-align: center`.

### `.claude/skills/material-fx/codm-mapping.md`

- The `.fx-shimmer` finding marked fixed; the still-open static-gradient
  finding (`--x-gradient-bestseller-gloss`/`-metallic-shine`, untouched by
  this release) split out as its own item so it isn't conflated with the
  fixed one.

## Not done in this pass

- `MilestoneRewards.vue`'s own duplicated shimmer implementation (FCM-only,
  documented in its own comments as unable to reuse `.fx-shimmer` due to a
  z-index conflict) was not migrated.
- `--x-shadow-*`, `--x-sys-colour-surface-l1-border`, and the static
  `--x-gradient-bestseller-*`/`-thumb-gloss` gradients were not retrofitted
  to derive from `--x-light-azimuth`/`-elevation` — a real, separate,
  larger follow-up.
