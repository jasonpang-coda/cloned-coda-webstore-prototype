# Release Notes — v0.67.0

**Date:** August 2026
**Milestone:** Inspector repackaged as a pluggable `@coda/inspect-kit` workspace package, plus a new standalone states + token-contract page

---

## Highlights

- **New `@coda/inspect-kit` workspace package.** The in-repo handoff inspector
  (`InspectorOverlay.vue`, `InspectorPanel.vue`, `useInspector.js`,
  `useTokenMap.js`, `inspect.js`) is extracted into `packages/inspect-kit`,
  following the same shape as `@coda/comment-kit`/`@coda/track-kit`: a
  framework-free core (`.`) plus a Vue 3 adapter (`./vue`). Everything that
  was hardcoded to this repo — the inspection root selector, dev-chrome
  exclusion list, source-file fetch, and the "View in library" jump — is now
  an options object passed to `createInspector({...})` in `src/main.js`, so
  the package can be installed into a different repo unchanged.
- **New: standalone states + tokens page.** The panel footer's "Open
  standalone page" button opens the selected element, cloned across
  **Default / Hover / Pressed / Disabled / Focus**, next to a full **token
  contract** — every design token resolved anywhere in that element's
  subtree, deduped with use counts and grouped by family (Colour / Spacing &
  size / Radius / Typography / Motion) — plus an **untokenised values**
  table. The page is self-contained (inlined stylesheets + the active
  theme's resolved `:root` tokens), so it's shareable, printable, and
  savable on its own.
- **Fixed:** the standalone-page popup could silently fail to open. The old
  `window.open('', '_blank')` + `document.write(...)` idiom is a pattern
  some popup blockers kill even from a genuine click. `openStandalonePage()`
  now builds the full HTML first and opens it as a `blob:` URL in one
  synchronous `window.open(url, '_blank')` call — the shape every blocker
  allows — and returns `{ ok, reason }` instead of throwing, so the panel
  shows an inline "popup blocked — allow popups & retry" message instead of
  failing with no feedback at all.

## Changes

### `packages/inspect-kit` (new package)

- `src/core/inspect.js` — the framework-free DOM/CSS helpers, unchanged in
  behaviour from the old `src/utils/inspect.js`, with the inspection-root
  selector (`screenRoot`) now a parameter instead of a hardcoded
  `.device__screen` default baked into every call site. `buildHoverOverride`
  generalised to accept any pseudo-class (`hover` | `focus`) instead of only
  `hover`, so the standalone page can bake in a Focus state the same way.
- `src/core/token-map.js` — the reverse-mapping engine from the old
  `useTokenMap.js`, with the `--x-` token-prefix/tier rules moved into an
  injectable `tokenRules` option instead of being hardcoded.
- `src/core/standalone.js` (new) — builds the standalone page's HTML and
  opens it via the blob-URL pattern described above.
- `src/vue/*` — the Vue adapter: `useInspector.js` (unchanged singleton),
  `useTokenMap.js` (thin wrapper that watches the host's theme attribute via
  `MutationObserver` instead of importing the host's own theme composable),
  `InspectorOverlay.vue` / `InspectorPanel.vue` (same UI, config-driven
  instead of hardcoded), `config.js` (the option defaults), `index.js` (the
  `createInspector()` plugin).
- `dist/style.css` — the components' scoped CSS, extracted by the Vue SFC
  compiler into its own file rather than auto-injected; exposed as the
  `./vue/style.css` export and imported once from the host's `main.js`.

### `src/main.js`

- New `createInspector({...})` plugin registration: `screenRoot`,
  `chromeSelectors` (now includes the library viewer's chrome classes,
  previously hardcoded inside `InspectorOverlay.vue`), `resolveSource`
  (Vite's `/@fs<file>?raw` raw-source fetch), `libraryLink` (lazy-imports
  `library/registry.js` + `useLibrary.js`, same "stay out of isolated
  builds" behaviour as before).

### `src/App.vue`, `src/components/DeviceToolbar.vue`, `src/components/CommandConsole.vue`, `src/library/LibraryViewer.vue`

- Import `InspectorLayer` / `useInspector` / `buildHoverOverride` /
  `applyPressedState` / `applyDisabledState` from `@coda/inspect-kit` /
  `@coda/inspect-kit/vue` instead of the deleted `src/` files. No behaviour
  change.

### Deleted

- `src/utils/inspect.js`, `src/composables/useInspector.js`,
  `src/composables/useTokenMap.js`, `src/components/InspectorOverlay.vue`,
  `src/components/InspectorPanel.vue` — moved into `packages/inspect-kit`.

## Not done in this pass

- The package still ships as a `file:` workspace dependency, not extracted
  to its own git repo (the `comment-kit`/`track-kit` end state). The config
  surface is designed so that lift-and-shift is mechanical when it happens.
- The interactive layer is still Vue-only — no Lit/Web Component
  framework-agnostic core, unlike `comment-kit`/`track-kit`.
