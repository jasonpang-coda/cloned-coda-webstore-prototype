# Release Notes — v0.71.0

**Date:** August 2026
**Milestone:** COD:M milestone loyalty programme (Armory Point), gated behind a dev flag

---

## Highlights

- **COD:M gets a milestone/loyalty rewards feature, following FCM's existing
  "Milestone Rewards" implementation.** Behind a new `codmMilestoneRewards`
  dev flag (default off), COD:M's pre-wired-but-dormant Armory Point (AP)
  loyalty currency turns on across every touchpoint at once: a second navbar
  L1 tab ("Milestone Rewards"), the navbar AP icon/pill next to the sign-in
  button, and a full 10-tier AP rewards page reusing existing COD:M content
  art (CP coins, the crate, gift art, the Midnight Sun bundle).
- **A lighter L1 tab model than FCM's, on purpose.** FCM's `nav.multiLevel`
  swaps the entire page over to a category-filter/`CatalogNavStack` rendering
  model — COD:M has no category catalogue to swap to (it's a bespoke
  single-scroll page), so adopting that model wholesale would have meant
  rebuilding COD:M's storefront as a category tree just to add one tab. New
  `config.nav.milestoneFlag` names a dev flag instead; `App.vue` owns a small
  local `activeSection` ref ('store' | 'rewards') that toggles between COD:M's
  existing page-mode sections and `MilestoneRewards.vue`, with FCM's own
  `isMultiLevel` model completely untouched.
- **One flag flips on the whole feature, no scattered component edits.** New
  `checkout.loyaltyFlag` in `useStoreConfig.js` centralises the gate: when the
  named flag is off, `checkout.loyalty` is nulled out for every consumer
  (`NavBar`'s icon/pill, the checkout loyalty banner, `MilestoneRewards`'s own
  loyalty guards) in one place — the same "zero component edits" whitelabel
  guarantee the rest of this codebase relies on.
- **Two real whitelabel-discipline bugs fixed while reusing FCM's component.**
  `MilestoneRewards.vue` directly imported `../stores/fcm/milestone.js` for
  its derivation functions and read the `fcmMilestoneScenario` flag by name —
  both hard-coded to FCM, which would have broken the moment a second store
  tried to reuse the component. Moved the frontier-rule derivation into a new
  shared `src/utils/milestoneRewards.js` (parameterised by `tiers`, not tied
  to one store's data module), and made the current-points source data-driven
  (`data.scenarioFlag` for FCM's toolbar preview, `data.demoPoints` for a
  store with no scenario flag). Also found `MilestoneRewardsRail.vue`
  hardcoding a `'MP'` unit suffix on the node labels — added a `pointsUnit`
  prop (`'MP'` for FCM, `'AP'` for COD:M).
- **Navbar rewards-pill icon sized up.** `.navbar__rewards-icon` was
  `--x-size-icon-s` (16px); bumped to `--x-size-icon-m` (20px) for better
  legibility at the small pill size.

## Changes

### `src/stores/codm/milestone.js` (new)

- 10-tier Armory Point ladder (Boot Camp → Legend, 150–7,000 AP), reusing
  existing COD:M content assets for every tier's card art. Hero banner uses
  dedicated campaign art (`milestone-rewards-hero.jpg`) — the only new
  artwork introduced. `demoPoints: 1200` drives the preview (no scenario
  flag, unlike FCM).

### `src/utils/milestoneRewards.js` (new)

- `deriveRewardsState(tiers, currentPoints)` / `deriveProgressionSummary(tiers, currentPoints)`
  — the frontier-rule derivation extracted out of `fcm/milestone.js`, now
  store-agnostic.

### `src/components/MilestoneRewards.vue`

- Imports the derivation from `../utils/milestoneRewards.js` instead of
  `../stores/fcm/milestone.js`. `currentMp` → `currentPoints`, sourced from
  `data.scenarioFlag` (FCM) or `data.demoPoints` (COD:M). The 750/5,000-MP
  auto-sign-in convenience watcher now only fires when `data.scenarioFlag`
  is set.

### `src/components/MilestoneRewardsRail.vue`

- New `pointsUnit` prop (default `'MP'`); node-label suffix reads from it
  instead of a hardcoded literal.

### `src/stores/fcm/milestone.js`

- Frontier-rule functions removed (moved to the shared util); `milestone`
  object gained `tiers`, `pointsUnit: 'MP'`, `scenarioFlag: 'fcmMilestoneScenario'`.

### `src/stores/codm/store.js`

- `config.nav.milestoneFlag: 'codmMilestoneRewards'`.
- `config.checkout.loyalty` set (mirrors FCM's shape) + `loyaltyFlag:
  'codmMilestoneRewards'`.
- `config.profile.showLoyaltyPill` flipped to `true`.
- New `milestone` export wired in from `./milestone.js`.

### `src/composables/useFeatureFlags.js`

- New `codmMilestoneRewards` boolean flag (default `false`, `stores: ['codm']`).

### `src/composables/useStoreConfig.js`

- New `checkout.loyaltyFlag` convention: nulls `checkout.loyalty` out for the
  active store when the named flag is off.

### `src/App.vue`

- New `showMilestoneTab` / `activeSection` / `currentSection` computeds
  driving COD:M's lightweight L1 tab, independent of FCM's `isMultiLevel`.
  `isStoreIntentActive` now reads off the unified `currentSection` instead of
  `activeIntent` directly, so hero/story-carousel/best-seller merchandising
  hides correctly under either nav pilot.
- `NavBar`'s `intents`/`active-intent` props now resolved through
  `navBarIntents`/`navBarActiveIntent`/`onNavBarIntentChange`, covering both
  FCM's real intent tree and COD:M's two-item stand-in list.
- New `<section id="cat-rewards">` rendering `MilestoneRewards` inside the
  page-model (`!isFilter`) branch, gated on `showMilestoneTab`.

### `src/components/NavBar.vue`

- `showIntentNav` simplified to `intents.length > 1` — no longer reads
  `config.nav.multiLevel` itself; the parent decides when to pass more than
  one intent.
- `.navbar__rewards-icon` size bumped `--x-size-icon-s` → `--x-size-icon-m`.

### `docs/component-breakdown.md`, `docs/README.md`

- Milestone Rewards section updated to document the shared/store-agnostic
  refactor and COD:M's lightweight tab pilot; version footers bumped.
