# Release Notes — v0.72.0

**Date:** August 2026
**Milestone:** Tour Guide package (`@coda/tourguide-kit`) — a working guided auto-demo/walkthrough kit, replacing an unfinished "Autoflow" draft

---

## Highlights

- **New `@coda/tourguide-kit` workspace package**, mirroring the house pattern
  of `inspect-kit`/`comment-kit`/`track-kit`: a framework-agnostic core
  (state-machine engine, POI element resolver, virtual-cursor DOM event
  synthesis, client-side WebM screen recorder, flow schema) plus a Vue 3
  adapter (`TourGuideLayer`, `TourGuideModal`, `TourGuideCard`,
  `TourGuidePlayerBar`, `VirtualCursor`, `useTourGuide`, `defineTour`). Three
  demo tours ship in the host app under `src/tourguide/flows/`.
- **This replaces an earlier "Autoflow" draft that looked unimplemented but
  wasn't — it was invisible.** The kit's Vue components ship scoped styles
  that the library build extracts into `dist/style.css`, but nothing in the
  host app imported that stylesheet, so the scrim, spotlight, virtual cursor,
  and explanation card all mounted and ran — just with zero CSS, rendering
  nothing visible. Fixed with a single `import '@coda/tourguide-kit/vue/style.css'`
  in `App.vue`.
- **Most tour steps also targeted CSS selectors that didn't exist.** ~7 of 10
  steps across the three flows were guessed BEM class names that don't match
  the real components, so the cursor traveled to nothing and the click
  actions silently failed. Fixed by tagging the real target elements with
  `data-poi` attributes — the kit's most robust targeting path — across
  `BestSellerCard.vue`, `CheckoutStepBody.vue`/`CheckoutStepFooter.vue`,
  `NavBar.vue`, `RegionSelectorSheet.vue`, `MilestoneRewardsRail.vue`, and
  `MilestoneRewardCard.vue`, then repointing all three flow files at those
  keys.
- **Two flows were also functionally broken, independent of targeting.** The
  Guest Checkout tour clicked a SKU card that does nothing —
  `useCheckout().openCheckout()` no-ops for a signed-out, unverified guest —
  because the tour's `setup()` never verified one; now it calls
  `setGuestVerified(true)`/`setGuestPlayerName(...)` first. The Milestone
  Rewards tour's final "claim" step had nothing claimable at the demo's
  default 0 MP; its `setup()` now seeds the `fcmMilestoneScenario` flag to
  `'750'` so a tier is already claimable.
- **New Autoplay toggle, on by default.** `TourGuideModal.vue` gained an
  "Autoplay" checkbox next to Record/Speed. With it on (default), the engine
  auto-advances between steps as before. With it off, each step still runs
  its full spotlight → cursor travel → hold → action sequence, then pauses
  and waits for the guide card's Back/Next buttons instead of continuing on
  its own — useful for walking through a tour at your own pace or narrating
  it live.
- **Toolbar trigger icon changed** from the generic `slideshow` glyph to
  `tour` (new entry in `MaterialIcon.vue`'s icon map).
- **Found and fixed while verifying the above (not in the original ask):**
  `useTourGuide.js`'s `currentStep` was computed from the engine's plain
  (non-reactive) class fields, so Vue never re-ran it after the first access —
  the guide card's title/explanation text silently froze on step 1's content
  for the rest of the tour. Now derived from the composable's own reactive
  `activeFlow`/`currentStepIndex` refs. Also: `simulateClick()` dispatched a
  synthetic `click` event *and* called the target's native `.click()`,
  double-firing real button/link handlers — dropped the redundant native
  call. `TourGuideEngine._executeCurrentStep()` had no per-step cancellation,
  so manually stepping (Back/Next, or seeking) during active playback could
  race a still-running step and double-advance — added a per-step token
  checked at every await boundary. `TourGuideLayer.vue` rendered a plain
  full-screen scrim *and* the spotlight's own `9999px`-shadow cutout at the
  same time, double-dimming the backdrop around the highlighted element — the
  plain scrim now only renders when there's no active spotlight.

## Changes

### `packages/tourguide-kit/` (new package, renamed from an untracked `autoflow-kit` draft)

- `src/core/engine.js` — `TourGuideEngine`: registers/lists tours, drives a
  headless `idle → preparing → playing → paused → finished` state machine per
  step (`beforeStep` → locate POI → scroll into view → animate cursor →
  hold-for-explanation → fire action → `afterStep` → advance), pub/sub
  snapshot emission, transport controls (`pause/resume/next/prev/seek/stop`,
  `setSpeed`), and now `autoplay` (default `true`) gating the auto-advance
  step, plus a `_stepToken` cancellation guard.
- `src/core/poi.js` — `resolveElement`/`waitForElement`: resolves a bare
  keyword selector to `[data-poi="…"]` first, falls back to
  `querySelector`; polls up to a timeout for non-zero geometry.
- `src/core/cursor.js` — `simulateClick`/`simulateTyping`/`animateCursor`:
  realistic pointer/mouse event sequences and `requestAnimationFrame`
  cursor tweening. `simulateClick` no longer also calls native `.click()`.
- `src/core/recorder.js` — `WebmRecorder`: `getDisplayMedia` + `MediaRecorder`
  screen capture with auto `.webm` download.
- `src/core/flow.js` — `defineTour(flow)`: validates/normalizes a tour
  definition (steps, default actions, hold durations).
- `src/vue/` — `TourGuideLayer.vue` (scrim/spotlight/cursor/card/bar
  orchestrator), `TourGuideModal.vue` (tour picker + playback options),
  `TourGuideCard.vue` (explanation card with step indicator + progress bar),
  `TourGuidePlayerBar.vue` (play/pause/step/speed/record controls),
  `VirtualCursor.vue`, and `useTourGuide.js` (the Vue singleton composable).

### `src/tourguide/` (new, host-app tours — renamed from `src/autoflow/`)

- `registry.js` — discovers `./flows/*.tour.js` via `import.meta.glob`,
  exports `TOURS` + `getTour(id)`.
- `flows/guest-checkout.tour.js` — browse a best-seller SKU → item summary →
  select payment channel → confirm. `setup()` now verifies a demo guest.
- `flows/locale-switcher.tour.js` — open the region selector → browse the
  market list → pick a market.
- `flows/milestone-rewards.tour.js` — navigate to the Milestone Rewards tab →
  view the progress rail → claim a tier. `setup()` now seeds a 750 MP demo
  scenario so a tier is claimable.

### Host component changes (new `data-poi` anchors)

- `src/components/BestSellerCard.vue` — `data-poi="best-seller-card"` on
  `.bestseller__card`.
- `src/components/steps/CheckoutStepBody.vue` — `data-poi="purchase-sheet"`
  on the item banner; `data-poi="payment-channel"` on the first
  `.sheet__pc-card`.

  on the confirm/checkout button.
- `src/components/NavBar.vue` — `data-poi="region-pill"` on the region
  trigger button; `data-poi="milestone-tab"` on the Milestone Rewards L1
  intent tab.
- `src/components/RegionSelectorSheet.vue` — `data-poi="region-list"` on the
  market list; `data-poi="region-row"` on the first market row.
- `src/components/MilestoneRewardsRail.vue` — `data-poi="milestone-rail"` on
  the rail root.
- `src/components/MilestoneRewardCard.vue` — `data-poi="milestone-claim"` on
  the currently-claimable reward card.
