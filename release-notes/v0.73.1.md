# Release Notes — v0.73.1

**Date:** August 2026
**Milestone:** Three Codashop fixes to the v0.73.0 reskin/material pilot — SKU grid overflow, the material pilot not reaching parent containers, and a stray card border

---

## Highlights

- **SKU grid no longer overflows its container.** `SkuList.vue`'s grid
  forced exactly `--sku-columns` (5, for Codashop) columns once the
  container query crossed 641px, regardless of the grid's own actual
  rendered width — narrower than the full screen inside Codashop's padded
  `catalog-card`. At some widths the row overflowed past the card edge
  instead of wrapping. Now uses `auto-fill` with a `minmax()` floor: renders
  pixel-identical to the old fixed rule when there's room for `N` columns,
  and gracefully wraps to more rows (never overflows) when there isn't.
- **The SKU card material pilot now reaches every card on the page, not
  just SkuCard.vue.** `.catalog-card`, `StepCard.vue`'s panels (Enter Gamer
  ID, Select Payment, Zip Code, Enter Details), and `PcCard.vue`'s payment
  buttons all previously kept the plain default look regardless of the
  chosen material — inconsistent next to the SKU grid. Fixed by retargeting
  the shared DS tokens those containers already consume
  (`--x-bg-card-default`, `--x-border-card-default`,
  `--x-border-sku-card-default`/`-hover`) at the material tokens, scoped to
  a new `[data-sku-material]` attribute `App.vue` syncs onto `<html>`
  (mirroring `useTheme`'s own `data-theme` pattern). Every current and
  future consumer of those tokens follows the chosen material for free.
  - Along the way, found and fixed a real bug this surfaced: two of the
    material fill tokens were flat colours, and `PcCard.vue` sets its
    background via `background-image` (not `background`) — which silently
    drops a plain colour (invalid `<image>`), the exact trap the component's
    own `--bg-card-selected` comment already flags. Fixed by wrapping both
    tokens as `linear-gradient(colour, colour)`.
- **Fixed a stray-looking border down the page.** Codashop never overrode
  `--x-border-card-default` — the repo default is an *opaque* mid-lightness
  neutral, while COD:M overrides it to a translucent 8% hairline for
  exactly this reason. With several independently-bordered boxes stacked at
  the same left margin, the bright borders read as one broken vertical line
  rather than individual card edges. Fixed with the same hairline treatment
  COD:M already has.

## Changes

### `src/components/SkuList.vue`

- `.sku-list__grid`'s `@container (min-width: 641px)` rule: fixed
  `repeat(var(--sku-columns, 4), 1fr)` → `repeat(auto-fill, minmax(max(130px,
  calc((100% - (N-1)*gap)/N)), 1fr))`.

### `src/tokens/ds/themes/codashop.css`

- New `--x-border-card-default` (translucent hairline).
- New `html[data-theme="codashop"][data-sku-material="…"]` blocks retargeting
  `--x-bg-card-default`/`--x-border-card-default`/`--x-border-sku-card-*` at
  the material tokens, one per material.
- `--x-fx-plastic-fill`/`--x-fx-carbon-fill` wrapped as
  `linear-gradient(colour, colour)` instead of a flat colour literal.

### `src/App.vue`

- New `watchEffect` syncing `document.documentElement.dataset.skuMaterial`
  from the flag + capability gate, mirroring `useTheme`'s `data-theme`
  pattern.

### `.claude/skills/material-fx/codashop-mapping.md`

- Documented all three fixes and the `background-image` flat-colour gotcha.
