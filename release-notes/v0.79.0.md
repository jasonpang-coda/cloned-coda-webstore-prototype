# Release Notes — v0.79.0

**Date:** August 2026
**Milestone:** Inspector reads the real authored design token; toolbar UX/visual fixes

---

## Highlights

- **The inspector no longer guesses which token a style uses — it reads the
  real one.** Previously it reverse-matched a computed style value against
  every design token that happened to resolve to the same value, which
  could (and did) surface the wrong one — e.g. `--x-brand-google` instead
  of the actually-authored `--x-text-header-default`, since both resolve
  to pure white in a given theme. It now walks the page's own stylesheets,
  resolves the real CSS cascade winner, and reads the literal `var(--x-...)`
  text the component authored.
- **Inspect mode no longer fights the dev toolbar.** The drawer now
  auto-collapses the instant inspect mode turns on (it was blocking part
  of the Responsive frame), closing the spec panel no longer kicks you out
  of inspect mode, and `Esc` is now two-stage (close panel, then exit).
- **The toolbar notch is actually findable now** — bigger, electric blue,
  and seamlessly fused with the drawer instead of reading as two separate
  panels.
- Small token fixes on the ZZZ/Diablo Immortal shared templates (Official
  Store label, download button, SEO section).

## Changes

### `packages/inspect-kit/src/core/authored.js` (new)

- `resolveAuthored(el, cssProp, { kind })` — walks `document.styleSheets`
  (recursing `@media`/`@container`/`@supports`/`@layer`, gating `@media` on
  `matchMedia` and `@supports` on `CSS.supports`), collects every
  `CSSStyleRule` matching the element (skipping `:hover`/`:active`/
  `:disabled`-style state variants and pseudo-elements), and hand-rolls
  cascade resolution — `!important` → specificity → source order — since
  `getMatchedCSSRules()` no longer exists in browsers and no specificity
  package is installed in this repo.
- Reads the winning rule's **authored** declaration
  (`rule.style.getPropertyValue(cssProp)`), not the computed value — this
  is the literal text the component wrote, e.g. `var(--x-text-header-default)`.
- Handles the shorthand caveat: a component may only declare
  `background: var(--x-bg-sheet)` (never the longhand `background-color`),
  so a `SHORTHAND_FALLBACKS` map retries the parent shorthand when the
  longhand alone has no declaration. Box-model fields (Padding/Margin) try
  all four sides as candidates, not just one — an asymmetric
  `padding-left`-only declaration would otherwise be missed.
- Disambiguates compound multi-`var()` declarations (e.g.
  `border: var(--border-weight-default) solid var(--x-border-card-default)`)
  with a colour/length "hint" regex so a colour-kind query picks the
  colour-flavoured token and a length-kind query picks the weight one.
- Walks up `el.parentElement` for genuinely inherited properties (`color`,
  `font-*`, `line-height`, `letter-spacing`) when the element itself
  declares nothing.
- Fixed two real bugs found while building this: (1) modern browsers now
  expose a `cssRules` property on every `CSSStyleRule` (CSS Nesting spec),
  not just grouping rules — an early implementation treated every style
  rule as a grouping rule and skipped its own declaration entirely; (2)
  trying candidate property names sequentially and stopping at the first
  one with *any* hit let a low-specificity reset rule on the primary
  longhand (e.g. a `button { padding-top: 0 }` normalize) pre-empt a
  higher-specificity rule on the shorthand fallback — fixed by merging
  hits from every candidate before picking the cascade winner.

### `packages/inspect-kit/src/core/inspect.js`

- `field()` now tries `resolveAuthored()` first (`source: 'authored'`, the
  definitive answer), flags a genuine raw literal with no `var()` at all
  (`raw: true`, gated on the field's own `warnable` flag so non-warnable
  fields like Font/Weight stay quiet), and only falls back to the old
  reverse-value guess (now tagged `source: 'inferred'`) when literally no
  CSS rule declares the property anywhere in the chain.
- Typography fields (Size/Weight/Line height/Tracking/Font) now resolve
  real `--x-sys-font-*` tokens instead of only showing the `.text-style-*`
  class name.

### `packages/inspect-kit/src/vue/InspectorPanel.vue`

- Renders the authored/inferred/raw-literal distinction: a solid token
  chip for `authored`, a dashed chip with a "?" superscript for `inferred`
  (tooltip lists the other value-equal candidates), a "raw literal" badge
  for genuinely un-tokenised CSS.
- The header ✕ button now calls a local `closePanel()` (`select(null)`)
  instead of `useInspector().close()` — dismissing the panel to look at
  the page or pick a different element no longer exits inspect mode.

### `packages/inspect-kit/src/vue/InspectorOverlay.vue`

- `Esc` is now two-stage: with an element selected (spec panel open), the
  first `Esc` just deselects (closes the panel); a second `Esc` with
  nothing selected exits inspect mode entirely.

### `src/main.js`

- Added `tokenRules.tierRank` to the `createInspector({...})` call — ranks
  the semantic-tier prefixes (`--x-bg-`/`-text-`/`-border-`/`-pad-`/`-gap-`/
  `-radius-`/`-size-`, legacy `--border-weight-`, non-`sys` `--x-motion-`)
  at 0, every other `--x-*` (extensions tier) at 1, then `--x-sys-*` (2) →
  `--x-palette-*` (3) → `--x-ref-*` (4). This only improves the *inferred*
  fallback's tiebreak now that authored resolution is the primary path —
  it stops the fallback guess from surfacing further upstream than it has
  to, but it's still a guess, never the ground truth.

### `src/components/DeviceToolbar.vue`

- New `watch(inspecting, on => on && setCollapsed(true))` auto-collapses
  the drawer the instant inspect mode turns on — the 320px right-anchored
  drawer was blocking part of the Responsive frame a tester needed to
  click on to inspect it.
- Notch enlarged 22×44px → 40×72px with a bigger 24px chevron, and
  recoloured electric blue (`oklch(0.62 0.24 262 / 0.35)` fill, `0.9`
  alpha border, brighter on hover) — the original low-contrast
  dark-on-dark tab was too easy to miss entirely.
- The drawer now tints the same electric blue into its base background
  (`color-mix(in oklab, oklch(0.62 0.24 262) 18%, var(--x-toolbar-bg))`)
  and dropped its own `border-left`, so the notch and drawer read as one
  continuous seamless surface instead of two abutting panels.

### `src/components/NavBar.vue`, `src/App.vue` (ZZZ/Diablo Immortal token fixes)

- `.navbar__logo-suffix` ("Official Store" label) now uses
  `--x-text-header-default` directly — it was referencing
  `--x-text-header-soft`, a token that doesn't exist anywhere in the token
  files, silently relying on its fallback the whole time.
- The download-banner fallback pill (`.download-banner__badge span`,
  shown only when no real app-store/play-store badge SVG is wired up) now
  uses `--x-radius-control-full` (was `-control-s`), `--x-text-hyperlink-default`
  for its label, and fills with `--x-bg-action-primary` on hover.
- `.seo-content__body` now uses `--x-text-body-default` (was `-soft`).
- `.seo-benefit__icon` now uses the semantic `--x-bg-indicator-neutral-subtle`
  instead of the extensions-tier `--x-surface-ghost-2`.
