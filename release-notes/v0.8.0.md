# CODM Web Store — v0.8.0

**Design-system token adoption · 4-tier colour cascade · themed typography · whitelabel architecture** · June 2026

Full adoption of the COD:M v3 design token system. The codebase moves from ~100 ad-hoc CSS custom properties to a structured 4-tier cascade mirroring the Figma token export, with runtime store switching and a tokenised typography system.

---

## What's new

### 4-tier design token system (`src/tokens/ds/`)

Seven new CSS files imported via `main.js` replace the monolithic `:root` block in `style.css`:

```
themes/codm.css    [data-theme="codm"]   seeds + spectrums + typography + brand overrides
system.css         :root                 --sys-colour-* role ramps → alias spectrums
semantics.css      :root                 --bg-* --text-* --border-* → alias system
space.css          :root                 spacing / radius / size / elevation scale
text-styles.css    :root                 .text-style-* typographic classes
extensions.css     :root                 brand effects (shadows, scrims, gradients, rarity)
```

The cascade mirrors the Figma alias graph exactly: seeds drive spectrums, spectrums drive the system tier, the system tier drives semantics. A component references a semantic token and the full chain resolves at runtime.

### Colour pipeline — all OKLCH

All 7 seeds, all 6 × 11-step spectrum ramps, and the full 151-token semantic layer are now authored in OKLCH. Vivid seeds (primary yellow, secondary cyan, tertiary magenta, positive green) carry chroma beyond sRGB and render on P3/wide-gamut panels. The existing `@media (dynamic-range: high)` block in the theme pushes brand hues past the sRGB ceiling for HDR panels.

The neutral ramp (`--palette-neutral-1000 … 0`) is anchored to the prototype's known-correct greys — the migration is pixel-neutral.

### Theming — `[data-theme]` runtime switch

`<html data-theme="codm">` is now set in `index.html`. All theme values are scoped under `[data-theme="codm"]` so a second store can be added without touching any component:

1. Copy `themes/codm.css` → `themes/store-b.css`
2. Change the selector, retune the 7 seeds, regenerate the 6 colored ramps, set the font/condense/tracking tokens
3. Import in `main.js`, set `data-theme` on `<html>`

Zero component edits required for a full reskin.

### Tokenised typography system

A `--sys-*` typography tier replaces raw `px` / weight / tracking literals:

- `--sys-weight-{extra-bold,bold,semibold,regular}` = 800 / 700 / 600 / 400
- `--sys-size-h1…h7` = 28–14 px (Mobile mode)
- `--sys-size-body-{l,main,s,xs}` = 16–10 px
- `--sys-letter-spacing-*` in `em` (not `%` — CSS rejects `%`)
- `--sys-font-condense: 0.82` (Hitmarker horizontal squeeze, themed)
- `--sys-line-height-*` unitless (`1` / `1.2` / `1.5`)

The Hitmarker +5% tracking compensation is baked into the themed `loose` and `wide` tracking tokens (`0.00525em` / `0.0105em`) rather than being a global magic number. The `--hm-scale` alias in `extensions.css` keeps the global condense block working without changes to components.

31 `.text-style-*` classes in `text-styles.css` bundle size + weight + line-height + tracking + condense into a single class. New components apply a class; no raw font properties.

### Component migration — ad-hoc names → DS names

All 131 `var(--token)` usages across 21 components and `style.css` were audited. The 82 ad-hoc names that had DS equivalents are renamed:

| Old | New |
|---|---|
| `--pad-{xxs…xl}` | `--pad-surface-{xxs…xl}` |
| `--gap-{tight,narrow,default,loose}` | `--gap-content-{tight,narrow,default,loose}` |
| `--radius-{xxs,xs,sm,pill}` | `--radius-control-xs / --radius-container-{xs,s} / --radius-badge-full` |
| `--border-weight-press` | `--border-weight-pressed` |
| `--border-input-focus` | `--border-input-focused` |
| `--text-on-action` | `--text-text-on-brand` |
| `--border-card` | `--border-card-default` |
| `--tag-bg / --tag-text` | `--bg-tag-error / --text-error-default` |
| `--gradient-border-sku{,-hover}` | `--border-sku-card-{default,hover}` |
| `--gradient-sku-glow` | `--bg-sku-card-default` |
| `--gradient-pc-card` | `--bg-card-default` |
| `--gradient-sheet-panel` | `--bg-sheet` |
| `--gradient-snackbar-success` | `--bg-snackbar-success` |

Tailwind `colors` mappings repointed to DS semantic names. `body` baseline tokenised to `var(--sys-font-family-body)` + `var(--sys-letter-spacing-loose)`.

Tokens with no DS equivalent (composed shadows, scrims, surface ramps, rarity gradients, component-effect gradients, dev chrome) are preserved in `extensions.css` with no component changes required.
