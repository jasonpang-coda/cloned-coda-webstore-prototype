# Release Notes — v0.81.1

**Date:** August 2026
**Milestone:** Fixed two Vercel hosting-layer bugs that made the COD:M PWA non-installable in production

---

## Highlights

- **`vercel.json`'s SPA catch-all rewrite was swallowing every PWA file.**
  The rewrite only excluded `/assets/*`, but the `pwa-manifest` Vite plugin
  emits `manifest.webmanifest`, `sw.js`, and the `pwa/icon-*.png` files at
  the `dist` root — every request for them was rewritten to `index.html`
  instead of served as themselves. The manifest `<link>` tag was present in
  the page, but resolving it returned the app's HTML, not JSON, so Chrome
  never saw a valid manifest.
- **The Basic Auth Edge Middleware gated those same files too.** Even after
  fixing the rewrite, `middleware.js`'s matcher ran on every path except
  `_vercel/*` — so `manifest.webmanifest`/`sw.js`/`pwa/*` still 401'd on any
  store-locked deployment with `BASIC_AUTH_USER`/`BASIC_AUTH_PASSWORD` set
  (e.g. `codm-webstore-prototype.vercel.app`). A manifest/service-worker
  fetch that gets a 401 makes a site permanently non-installable, so these
  paths are now explicitly exempted — they aren't sensitive content, only
  the actual storefront needs the auth gate.

## Changes

### `vercel.json`

- The SPA rewrite's negative-lookahead now also excludes
  `manifest.webmanifest`, `sw.js`, and `pwa/` alongside the existing
  `assets/` exclusion.

### `middleware.js`

- Added an early exemption for `/manifest.webmanifest`, `/sw.js`, and any
  `/pwa/*` path, before the Basic Auth credential check runs — these now
  pass through via `next()` unconditionally, on every project regardless of
  whether `BASIC_AUTH_USER`/`BASIC_AUTH_PASSWORD` are set.
