# Release Notes — v0.85.0

**Date:** September 2026
**Milestone:** Agentic design harness — `@coda/harness-kit` package extraction, a CLI tool suite for token/component/story work, and story-driven spec generation

---

## Highlights

- **`StoryStage` extracted into a standalone package, `@coda/harness-kit`**,
  alongside two previously handoff-only widgets (`BeatTimeline`,
  `TokenSandbox`), so the story-stage rendering host is no longer tied to
  this repo's store composables. It takes host context (assets/config/
  strings/theme) via a prop or Vue injection instead of importing
  `useStoreAssets`/`Config`/`Strings`/`Theme` directly; `src/library/
  StoryStage.vue` is now a thin adapter that supplies that context.
- **A new `tools/*.mjs` CLI suite** lets an AI agent (or a human) search and
  resolve design tokens, slice a component's prop/emit/slot/token contract
  without reading the whole file, scaffold overlays/stories/components,
  statically lint for token/container violations, sweep every story's
  tokens across all 12 store themes, and generate Figma Code Connect
  mappings — all wired into `npm run` scripts (`token`, `vue:slice`,
  `scaffold`, `preflight`, `harness`, `pipeline`, `harness:compound`,
  `figma:prime`, `figma:sync`).
- **`handoff:export --story`** generates a per-component spec
  (`docs/Handoff/components/<id>/spec.md`) directly from a story's
  declaration — usage rules, variant/state table, and (now that stories
  declare `tokens: [...]`) a resolved-per-store token contract table.
  `handoff:verify` now does a real content comparison against the generated
  spec, so it can actually detect drift (it previously only checked that
  the file existed).
- **Three new skills**: `design-harness` (the CLI playbook + subagent
  delegation profiles), `add-feature-flag`, `add-page-or-overlay`.

## Changes

### `packages/harness-kit/` (new package, `@coda/harness-kit`)

- `src/vue/components/StoryStage.vue`, `BeatTimeline.vue`, `TokenSandbox.vue`
  (+ internal `TokenChip.vue`) and `src/vue/utils/tokens.js` — ported from
  `src/library/` and the VitePress handoff-kit template.
- Registered as a `file:` dependency (`@coda/harness-kit`) with a `prepare`
  build script, same convention as `@coda/inspect-kit`/`@coda/tourguide-kit`
  — `npm install` builds `dist/` automatically, no manual step needed.
- `vite.config.js` gained two dev aliases resolving `@coda/harness-kit` and
  `@coda/harness-kit/vue` to the package's built `dist/`.
- Fixed during this release: the extracted `StoryStage`'s remount key
  referenced `theme.value` — a binding that existed on the old host
  component but not in the extracted copy, a `ReferenceError` on every
  render. Now reads `ctx.value?.theme` from the injected/prop context.

### `tools/token-cli.mjs`, `vue-slice.mjs`, `scaffold.mjs`, `preflight.mjs`, `harness-cli.mjs`, `orchestrator.mjs`, `compound.mjs`, `figma-harness.mjs`, `figma-sync.mjs` (new)

- See Highlights above for what each does; full command reference lives in
  the new `design-harness` skill and the "Fast AI Tooling" sections added to
  `web-store-fe`/`web-store-component-token-mapping`'s `SKILL.md`.
- Fixed during this release: `vue-slice.mjs`'s `--json` contract output was
  silently capped at 15 tokens (a "compact preview" truncation applied even
  in JSON mode) while `tokensCount` reported the true total — any consumer
  reading the JSON got an incomplete token list. `--json` now returns every
  token; the human-readable printer keeps its own separate 10-token preview.
- Fixed during this release: `figma-sync.mjs`'s generated `exampleSnippet`
  interpolated the kebab-case story id directly (`<StoryStage
  :story="best-seller-cardStory" />`), producing invalid JS. Now camel-cases
  the id first.

### `scripts/export-handoff.mjs`

- New story mode (`--story [id]`) generating `docs/Handoff/components/<id>/
  spec.md` per component story, with a resolved token-contract table when
  the story declares `tokens`.
- Fixed during this release: `--verify` only checked that the spec file
  existed, so it could never report drift once a spec fell out of sync with
  its story. Now compares the file's actual content against freshly
  rendered content.
- Fixed during this release: the generated `source:` frontmatter field
  reconstructed the story filename from the kebab-case id
  (`src/library/stories/sku-tag.stories.js`), which doesn't exist — the
  real files are PascalCase (`SkuTag.stories.js`). Now threads the actual
  filename through.

### `src/library/story.js`

- `defineStory` defaults gain `tokens: []`, `motionBeats: null`,
  `figmaNodeId: null`.

### `src/library/stories/*.stories.js` (8 files)

- Each of the 8 existing stories (SkuTag, SkuCard, SkuImageCard,
  BestSellerCard, BundleSkuCard, GiftSkuCard, HeroSkuCard, NavBar) now
  declares `tokens: [...]`, derived from `npm run vue:slice contract` and
  filtered to real DS tokens (`--x-*` / `--border-weight-*`) — excluding
  JS-computed inline CSS custom properties like `--loyalty-icon-url` and
  `--safe-top`, which are per-instance runtime values, not theme tokens.

### `.claude/skills/design-harness/`, `add-feature-flag/`, `add-page-or-overlay/` (new)

- Playbooks for the CLI suite, feature-flag double-gating, and the
  page-vs-overlay decision + scaffold fast-path.

## Known-open (not fixed in this release)

- `npm run harness test all` surfaces a genuine, pre-existing cross-store
  gap: `--x-fx-{metal,plastic,carbon}-{fill,edge,sheen}` (consumed by
  `SkuCard.vue`) are defined only in `themes/codashop.css` and unresolved
  in the other 11 store themes. Predates this branch; out of scope here.
- `BeatTimeline`/`TokenSandbox` are shipped by `@coda/harness-kit` but not
  yet consumed anywhere in this repo — the duplication between
  `src/handoff/` and the VitePress handoff-kit template they exist to
  remove is still open.
