# Release Notes — v0.86.0

**Date:** September 2026
**Milestone:** New `/tokens` usage dashboard — live coverage, drift, and per-store audit of the design-token system, plus two real bugs fixed in the token cascade resolver

---

## Highlights

- **New `/tokens` dev dashboard**: a real child URL (path-routed, same
  pattern as `/handoff`) that answers "what's used, what's dead, what's
  custom, what's drifted" from the actual token CSS/`.vue` source on every
  load — replacing the hand-maintained (and admittedly stale) audit in
  `.claude/skills/web-store-component-token-mapping/`. Five tabs: Overview,
  Coverage, Drift, Custom, Stores. Every stat renders as both a count and a
  percentage (`311 / 518 · 60%`), never one without the other.
- **Four independent usage signals**, tracked separately rather than merged
  into one boolean: read directly in a `.vue`'s scoped CSS, reachable only
  through the alias chain, read dynamically from JS/template, or overridden
  by a theme with nobody consuming it.
- **A 14-rule drift catalogue** (`src/token-audit/core/rules.js`) that
  reproduces every finding in the hand-written `drift-audit.md` automatically
  — and finds real bugs that audit missed: **29 dead theme overrides**
  detected (vs. 1 documented by hand), including a previously-undiscovered
  one where `--x-hdr-glow/-hot/-bloom` overrides in `codm.css`/`tdr.css`/
  `ygodl.css` silently lose to `motion-sku.css`'s `:root` defaults.
- **Two real bugs fixed** in the token cascade resolver itself
  (`scripts/resolve-css.mjs`, now delegating to the new shared engine): the
  resolver's file list was missing `light.css`/`materials.css` (31 tokens
  were silently unresolvable), and it was merging `@media
  (dynamic-range: high)` HDR overrides into the base cascade unconditionally
  (every HDR-boosted token resolved to its out-of-gamut value instead of the
  correct SDR one). `export-handoff.mjs` needed no changes — same public API.
- **New `npm run token:audit`** CLI (`--json`, `--drift`) — same engine,
  read-only, exits non-zero only on an unallowlisted error-severity finding
  (CI-safe, mirrors `tools/cms/audit.mjs`'s conventions).
- Opens from the toolbar's Tools segment (new donut-chart icon), the `/`
  command console ("Open token usage dashboard"), or by navigating to
  `/tokens` directly. Hidden in store-locked builds — verified the whole
  engine (including its raw-source glob) tree-shakes out of
  `build:<store>` bundles into its own lazy chunk in the multi-store build.

## Changes

### `src/token-audit/` (new)

- `core/cascade.js` — the cascade/specificity engine, extracted from
  `scripts/resolve-css.mjs` and made browser-safe (no `node:fs`): parses
  every token CSS source once (store-independent), then resolves a
  cascade per store. Every declaration — winner and losers — is kept with
  provenance (`file`, `line`, `selector`, `wins`, `losesTo`), which is what
  turns a pure value-resolver into a drift detector.
- `core/consumers.js` — scans `.vue`/`.js` sources for `var()` reads,
  `getPropertyValue()`/`getToken()`/`:style` JS reads, and component-local
  custom-property declarations (classified as minted / local-override /
  layout-var).
- `core/alias-graph.js` — builds the declared-value → `var()` reference
  digraph; transitive reachability from the consumed root set, cycle
  detection (Tarjan SCC), dead-end classification.
- `core/rules.js` — the 14-rule drift catalogue (dead theme override, no
  `:root` default, read-but-undeclared, unreachable, overridden-unconsumed,
  tier violations, typography tier violations, component-minted tokens,
  namespace collisions, scale-ladder gaps, orphan theme file).
- `core/classify.js`, `core/tier.js`, `core/allowlist.js`, `core/rollup.js`,
  `core/build.js` — bucketing (prod/prototype/dev-chrome), tier ranking
  (mirrors `src/main.js`'s inspect-kit `tierRank`), the cited exception
  allowlist, the `{count, total, pct}` stat helper, and the orchestrator.
- `sources.js` — the only file using `import.meta.glob`; pulls every token
  CSS/`.vue`/`.js` file's raw text, only ever imported behind
  `!__STORE_LOCKED__`.
- `useTokenAudit.js` — path router (`/tokens`, `/tokens/<tab>`), direct port
  of `src/handoff/useHandoff.js`'s pattern.
- `TokenAuditApp.vue` + `components/{Overview,Coverage,Drift,Custom,Stores,
  StatCard}.vue` — the dashboard shell and five tabs. Dev-chrome convention
  (system font, ad-hoc dark frame) with content panels built entirely from
  the existing semantic token set — no new tokens introduced.

### `scripts/resolve-css.mjs`

- Refactored to a thin `node:fs` loader delegating to
  `src/token-audit/core/cascade.js`. Same exported API
  (`resolveTokensForStore`/`resolveTokensAcrossStores`), so
  `scripts/export-handoff.mjs` needed no changes.
- Fixed: `ROOT_TIER_FILES` now includes `light.css`/`materials.css` (missing
  before — `src/main.js` imports both, so the resolver couldn't resolve any
  token referencing them).
- Fixed: `@media (dynamic-range: high)` blocks are now parsed into a
  separate `hdr` layer and never merged into the base cascade.

### `scripts/token-audit.mjs` (new)

- `npm run token:audit` — stdout summary table; `--json` for machine output;
  `--drift` for the full finding list. Read-only, exits 1 only on an
  unallowlisted `error`-severity finding.

### `src/App.vue` / `src/components/DeviceToolbar.vue` / `CommandConsole.vue` / `MaterialIcon.vue`

- Wired `TokenAuditApp` in behind `!isStoreLocked`, alongside the library and
  handoff surfaces (lazy import, store-shell unmount while active, `/`-key
  guard).
- Toolbar: new icon button in the Tools segment (`donut_large`, newly
  registered in `MaterialIcon.vue`'s icon set).
- Command console: new `tools:tokenusage` entry ("Open token usage
  dashboard").

### `docs/token-dashboard.md` (new), `docs/README.md`

- New doc covering what "in prod" means, the four usage signals, the drift
  rule catalogue, and the architecture (isomorphic engine, two callers).
  Indexed under docs/README.md's Dev tooling list.
