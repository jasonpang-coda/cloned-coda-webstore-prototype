# Release Notes — v0.87.0

**Date:** September 2026
**Milestone:** Design harness hardening — a real render/crash gate, loud failures instead of silent no-ops, auto-derived token contracts, a durable compounding ledger, and a version-collision preflight

---

## Highlights

- **The harness can finally catch a runtime crash.** Every prior check
  (`preflight`, `vue:slice`, `harness test`, even a clean `vite build`)
  inspects source text or resolves CSS `var()` names as strings — none of
  them instantiate a component. New `npm run harness:render` SSR-renders
  every story variant **through StoryStage** (not the leaf component alone)
  via `@vue/server-renderer`, registering the same global custom directives
  (`v-ripple`/`v-haptic`) `src/main.js` does. This is the check that would
  have caught the extracted `StoryStage`'s `theme.value` `ReferenceError`
  from the v0.85.0 harness merge — verified by reintroducing that exact bug
  and confirming the gate fails, then reverting and confirming it passes.
- **Silent no-ops now fail loudly.** `export-handoff.mjs --story <id>` used
  to match zero files on a kebab/PascalCase mismatch and exit 0 having done
  nothing; `token resolve <name>` returned exit 0 for a typo'd token,
  indistinguishable from one that's genuinely declared-but-unresolved in a
  given store. Both now error with the available names / a clear
  distinction. `token search` stays informational on purpose — an empty
  search result is a legitimate answer, not a mistake.
- **Story token contracts are auto-derived, not hand-maintained.** The same
  regex-based "what tokens does this component use" logic existed three
  times, independently, with subtly different behaviour
  (`harness-cli.mjs`, `vue-slice.mjs`, `scaffold.mjs`'s placeholder). Now
  one shared module, `tools/lib/component-tokens.mjs`. `export-handoff.mjs`
  derives a story's token contract from its actual component and merges any
  explicit `tokens:` rather than trusting a hand-authored list as the sole
  source — this is exactly the gap that let the `--x-fx-metal/plastic/
  carbon-*` cross-store issue stay invisible for a whole release.
- **The "knowledge compounding" ledger is now actually durable.**
  `audits/regressions-log.json` was gitignored and write-only — a lesson
  recorded by `tools/compound.mjs` in one worktree never reached another
  worktree or a fresh clone, which is very likely why two branches
  independently built byte-identical tooling. It's now committed (with a
  `.gitignore` exception carving it out of the otherwise-local `audits/`
  directory), seeded with the four bugs this release fixes, and gains
  `--list`/`--check <Component>` read commands.
- **A version-collision check.** Two branches once both claimed `v0.84.0`
  and both wrote `release-notes/v0.84.0.md` — the collision wasn't caught
  until merge. New `scripts/check-version.mjs` (`npm run version:check --
  --version X.Y.Z`) checks a proposed version against `release-notes/*.md`
  and `git log --all` before anything is written for it.

## Changes

### `tools/harness-render.mjs` (new)

- `npm run harness:render [storyId] [--json]` — for each story variant,
  builds an SSR app (`createSSRApp`), registers `ripple`/`haptic` directives
  to mirror `src/main.js`'s real registration (a bare render with no app
  context resolves global directives to `undefined`, which crashes reading
  `.getSSRProps` off them — a false positive this gate specifically avoids),
  and renders through `@coda/harness-kit/vue`'s `StoryStage` via
  `renderToString`. Uses real COD:M store data (`src/stores/codm/store.js`'s
  plain `assets`/`config`/`strings`) as context rather than empty objects,
  falling back gracefully if that load fails. A story may opt out with
  `skipRender: true` (printed as `[SKIP]`, never silent) for a component
  that legitimately can't SSR. Sets `optimizeDeps: { force: true }` on its
  Vite SSR server for the same dep-cache-staleness reason as
  `export-handoff.mjs` (below).
- Wired into `tools/orchestrator.mjs`'s `pipeline` command as Stage 3.5,
  between the static token sweep and the preflight linter.

### `tools/lib/component-tokens.mjs` (new)

- `getComponentConsumedTokens(absPath)` / `getComponentConsumedTokenNames(absPath)`
  — the one shared "which `--x-`/`--sys-` tokens does this `.vue` file use"
  extractor, replacing independent copies previously in `harness-cli.mjs`
  and `vue-slice.mjs`.

### `scripts/export-handoff.mjs`

- Story mode's `--story <id>` now errors (with the list of available ids)
  when the requested id matches nothing, instead of silently no-op'ing —
  the substring filter itself is also normalized on both sides
  (alphanumeric-only) so a kebab-case id reliably matches its PascalCase
  filename.
- `renderStorySpecMd` auto-derives a story's token contract from its actual
  component file (resolved from the story's own `import ... from
  '@/components/X.vue'`) and unions it with any explicit `story.tokens`.
  All 7 affected component specs regenerated; `handoff:verify` confirms
  they're in sync.
- Its Vite SSR server now sets `optimizeDeps: { force: true }` — a stale
  `node_modules/.vite` dep cache could otherwise make two identical
  invocations of this script return different resolved output, which reads
  exactly like (and is expensive to rule out as) a resolver bug.

### `tools/token-cli.mjs`

- `resolve <name>` now errors when the token isn't declared in any tier at
  all, distinct from a token that's declared but unresolved in the
  requested store (which still resolves and reports normally, same as
  before — that's real harness output, not a typo).

### `tools/vue-slice.mjs`

- `contract --json` now asserts `tokens.length === tokensCount` and throws
  if they ever diverge, so a "compact preview" shortcut can never silently
  leak into the machine-readable path again (it already had once).
- Token extraction now goes through `tools/lib/component-tokens.mjs`
  instead of its own unfiltered `var(--...)` regex — the human-readable
  `contract` printer's own 15-token display truncation is unaffected.

### `tools/harness-cli.mjs`

- `getComponentConsumedTokens` (private, fallback-aware token scanner)
  replaced by the import from `tools/lib/component-tokens.mjs`; behaviour
  unchanged.

### `tools/scaffold.mjs`

- Story scaffolding seeds `tokens:` with the real tokens derived from the
  target component if it already exists (previously a fixed, made-up
  placeholder list regardless of the component); if the component doesn't
  exist yet, leaves an explicit empty array with a comment rather than a
  placeholder that reads as real.

### `tools/compound.mjs`

- New `--list` (print the whole ledger, newest first) and `--check
  <Component>` (print recorded lessons for one component) read commands —
  the ledger was previously append-only, with nothing ever reading it back.

### `.gitignore`

- `audits/` changed to `audits/*` with a `!audits/regressions-log.json`
  exception, so the compounding ledger is committed while everything else
  under `audits/` (genuinely local/one-off outputs) stays ignored.

### `scripts/check-version.mjs` (new)

- `npm run version:check` (informational — reports `package.json`'s current
  version and the highest version known) / `npm run version:check --
  --version X.Y.Z` (the real gate — errors if that version already has a
  `release-notes/` file in this checkout or a `Release vX.Y.Z` commit
  anywhere in `git log --all`).

### `audits/regressions-log.json` (new, committed)

- Seeded with four entries recording this release's own root causes (the
  `StoryStage` render crash, the `vue-slice --json` truncation, the
  `handoff:verify` no-op, and the `--story` kebab/Pascal mismatch) — the
  ledger's first real content, and the worked example of the format.

### `.claude/skills/design-harness/SKILL.md`

- New "Conventions & Gotchas" section documenting all of the above as
  house rules, each tied back to the regression that motivated it. Quick
  Reference table gained `harness:render`, `harness:compound -- --check`,
  and `version:check`. The Harness-First workflow's token-declaration step
  now describes `tokens:` as an auto-derived pin, not something to
  hand-maintain, and adds the render gate as a required step before
  mounting into `App.vue`.
