# Release Notes — v0.88.0

**Date:** September 2026
**Milestone:** PWA install + Web Push opt-in system, plus a task-gated "88 CP" reward gift tying the two together — and a sprint-retro tool for compounding session-level lessons

---

## Highlights

- **A real Web Push opt-in system, shared across every surface.** New
  `useWebPush.js` centralises `permission`/`subscribed` state behind one
  singleton every touchpoint (Gifts banner, Order Complete banner, nav
  drawer, story slide) reads and writes. `subscribed` is a real toggle
  state OR'd with the new `simulateWebPushGranted` dev flag — the same
  "real condition OR a flag" pattern `usePwaInstall.js`'s `isInstalled` /
  `pwaInstalledState` already used — so the Variants toolbar can preview
  the granted state everywhere instantly, with no click required (many
  sandboxes/browsers auto-deny `Notification.requestPermission()` with no
  real prompt ever shown, so there'd be no other way to demo it). Live
  permission tracking via the Permissions API's `onchange` event keeps
  state accurate even if the user changes the setting outside the page —
  `Notification.permission` alone is a snapshot with no change event of
  its own. No confirmation or "blocked" snackbar anywhere in the flow, on
  purpose: the browser's own permission UI is the only feedback surfaced.
- **A task-gated reward gift.** New `useTaskGiftClaim.js` +
  `TaskGiftSheet.vue`: a `GiftSkuCard` (new `taskGift` prop) whose claim is
  gated on two steps — install the PWA, then turn on notifications —
  instead of the instant-claim flow every other gift uses. The sheet's
  content is fully dynamic on `step` (`install` → `push` → `claim` →
  `claimed`); iOS "Add to Home Screen" instructions render **inline**,
  growing the one sheet via `BaseSheet`'s existing `contentKey` resize
  engine, instead of stacking a second sheet on top. The claimed view ends
  in the exact same success treatment `ClaimGiftSheet` already has: a title
  crossfade, a one-shot green success pulse (a transient `justClaimed` flag
  — deliberately not derived from the persisted `claimed`, so reopening an
  already-claimed sheet never replays the animation), and the same upsell
  handoff to `PurchaseSheet`.
- **Toggles clean up after themselves.** Every Web Push toggle now hides
  itself once the user is already subscribed — nothing left to invite —
  except the nav-drawer row, which stays the one place to turn it back
  off. The navbar bell touchpoint that was added mid-build was fully
  removed again once every other surface covered the same ground.
- **`DeviceToolbar`'s Pages dropdown works on locked builds again.** It was
  lumped in with genuinely internal-only dev tools (Inspector, Library,
  Handoff) under the same `__STORE_LOCKED__` gate, even though it
  navigates real product surfaces (Product Page / Order Complete) that a
  locked single-store build (`npm run build:codm`) actually ships. Verified
  against a real `vite build --mode codm` output — Pages and Variants both
  render, "Stores" correctly stays absent.
- **Scroll position resets on every page switch.** New `useScrollReset.js`
  (`scrollToTop`, extracted from `CommandConsole.vue`'s own command) is now
  called from every page-switch composable (`useOrderComplete`,
  `useTransactionHistory`, `useCodashopHome`), so navigating between pages
  — including via `DeviceToolbar`'s dropdown — never leaves the new page
  scrolled to wherever the previous one was left. `useCloseAllOverlays.js`
  now also closes `TaskGiftSheet`, so a page switch can't strand it open
  either.
- **A session-level compounding ledger.** New `sprint-retro` skill +
  `tools/retro.mjs` (`npm run retro`) grades a session on build quality and
  token usage and writes durable lessons to `audits/retro-ledger.json`
  (committed, alongside the existing component-level
  `audits/regressions-log.json`) — the session-level twin of
  `tools/compound.mjs`.

## Changes

### `src/composables/useWebPush.js` (new)

- `permission`/`subscribed`/`justEnabled`/`isSupported`/`isBlocked` +
  `enable()`/`disable()`/`toggle()`. `subscribed` is exposed as a computed
  overriding the raw persisted ref with `simulateWebPushGranted === 'on'`.
  Module-level Permissions-API listener (`navigator.permissions.query({
  name: 'notifications' })`) keeps `permission` in sync with out-of-page
  changes and turns `subscribed` back off if the OS/browser revokes it.

### `src/composables/useTaskGiftClaim.js` (new)

- `sheetOpen`/`claimed`/`step`/`openSheet()`/`closeSheet()`/`claim()`/
  `unclaim()`. `claimed` persists to `localStorage`
  (`webstore:taskGiftClaimed`); `step` derives from `usePwaInstall`'s
  `isInstalled` and `useWebPush`'s `subscribed`.

### `src/components/TaskGiftSheet.vue` (new)

- Instructions sheet for the 88 CP task gift. Numbered radio-style step
  markers (not a generic unchecked-donut icon); inline iOS install detour;
  claimed view fully replaces the checklist/banner content (not appended
  underneath it) with the `ClaimGiftSheet`-style success view + upsell
  offer; debug-only "Reset claim" control behind `allowGiftUnclaim`.

### `src/components/GiftSkuCard.vue`

- New `taskGift`/`readyLabel` props. CTA relabels through the task's own
  lifecycle: "Learn More" while install/push are pending, "Claim Gift"
  (reusing the existing `giftClaimCta` copy) once ready, "CLAIMED" after.
  Debug-only unclaim icon button (top-right of the art) behind
  `allowGiftUnclaim`.

### `src/composables/useFeatureFlags.js`

- New `pwaInstalledState` (enum: not-installed / installed), and
  `simulateWebPushGranted` (enum, not boolean, specifically so it gets its
  own toolbar select the way `pwaInstalledState` does — a boolean flag only
  gets a command-palette control). New `allowGiftUnclaim` (boolean, debug).

### `src/composables/usePwaInstall.js`

- `isInstalled` now OR's the real `isStandalone()` check with
  `pwaInstalledState === 'installed'`.

### `src/components/DeviceToolbar.vue`

- "Pages" segment's `v-if` no longer includes `!isStoreLocked` — only
  `pageOptions.length` gates it now.

### `src/composables/useScrollReset.js` (new)

- `scrollToTop({ smooth })` — resolves the framed device's own scroll
  container or `window`, honours `prefers-reduced-motion`. Wired into
  `useOrderComplete`/`useTransactionHistory`/`useCodashopHome`'s open/close
  functions (`smooth: false` — an instant jump, since the content
  underneath is a different page) and reused by `CommandConsole.vue`'s
  "scroll to top" command (`smooth: true`, the same default as before).

### `src/composables/useCloseAllOverlays.js`

- Now also calls `useTaskGiftClaim().closeSheet()`.

### `src/components/NavDrawer.vue`

- New Web Push row (icon + label + toggle, same "just turned on" glow
  recipe as `ClaimGiftSheet`'s success overlay) — the one surface that
  keeps the toggle once subscribed.

### `src/App.vue`

- Gifts `CategoryBanner`'s action slot: the Web Push toggle now only shows
  while installed-but-not-subscribed; nothing renders in the action slot
  once already subscribed (previously showed regardless of subscription
  state). New reward-nudge carousel slide (pre-install state) opens
  `TaskGiftSheet` via a new `ctaAction: 'gift-task'` branch in
  `onStoryCta`.

### `src/components/OrderCompletePage.vue`

- Gift banner now uses the shared "positive" info-banner tint
  (`--x-bg-info-banner-success` / `--x-border-tag-success`) instead of the
  dark-scrim default — title/description/CTA text stay the component's
  default white. Push-step action is a bare toggle (no icon, no glow
  wrapper); other steps show a compact pill CTA that opens `TaskGiftSheet`.

### `src/tokens/ds/themes/codm.css`

- `--x-category-banner-border`/`-border-bottom` and
  `--x-download-banner-border` now set (full four-edge border), same
  escape-hatch precedent as ZZZ/Diablo Immortal.

### `src/components/MaterialIcon.vue`

- New `notifications`/`notifications_active` icon registrations.

### `.claude/skills/sprint-retro/`, `tools/retro.mjs`, `audits/retro-ledger.json` (new)

- Session-level build-quality/token-usage retro tool, committed ledger
  (same rationale as `audits/regressions-log.json`), `npm run retro`.

### `docs/Handoff/pwa-web-push/` (new)

- Full agent-executable handoff spec for the PWA-install/Web-Push flow,
  including a `for-codashop-client/` production-target export.
