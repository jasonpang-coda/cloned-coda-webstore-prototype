# Release Notes — v0.91.0

**Date:** September 2026
**Milestone:** Token Usage Dashboard redesigned against the dashboard-design and ui-design skills — inverted-pyramid hierarchy, threshold-aware stat cards, colour-blind-safe status everywhere

---

## Highlights

- **A 5-second headline, finally.** The `/tokens` Overview tab used to open on 8 co-equal cards and
  a definition paragraph — nothing answered "is the token set healthy or not?" at a glance. It now
  leads with a hero coverage band (judged against an 80% health threshold) before a 4-card primary
  KPI row; the finer a/b/c/d usage-signal breakdown is demoted behind a collapsed "How 'used' is
  counted" disclosure.
- **Every status pairs an icon with its colour.** Drift severity, coverage health, signal "on"
  state, and store orphan/dead flags previously relied on colour alone (fails the ~8% colour-blind
  cue). Every `StatCard` and status badge across all 5 tabs now shows a status icon + word alongside
  the tone colour.
- **Stat cards gained a comparison layer.** `StatCard` can now render an optional `threshold`
  (target %) with a tick mark on its meter and a delta-to-target line, so a lone percentage becomes
  judgeable instead of a trivia fact. Applied to the hero, the primary KPI row, and Coverage's
  tier/family rows.
- **A real bug caught during verification:** the "Used" KPI card was hardcoded to tone `good`
  regardless of actual coverage, so it could read "Healthy" at 60.6% while the hero band correctly
  said "Needs attention" one card over. Fixed to derive tone from the same threshold as the hero.
- **Systematised chrome.** The dashboard's fixed dark shell (sidebar/topbar) previously sprinkled
  raw hex through a dozen rules; it now reads from one local `--tk-*` variable ramp. Content panels
  are unchanged — they still consume only the live `--x-*` semantic tokens they're auditing.

## Changes

### `src/token-audit/TokenAuditApp.vue`

- Chrome hex replaced with a `--tk-*` local ramp (bg/surface/border/text/accent/status colours).
- Freshness timestamp moved from a small sidebar footnote into an always-visible topbar chip.
- Loading state replaced a centred "Loading the audit…" line with a skeleton that mirrors the
  Overview layout (hero + KPI row + block placeholders).

### `src/token-audit/components/StatCard.vue`

- Added a status icon + word next to the tone colour (good/warn/bad), an optional `threshold` prop
  rendering a comparison line and meter tick, and a `hero` size variant. The `pct`-always-derived
  contract and `role="meter"` a11y are unchanged.

### `src/token-audit/components/Overview.vue`

- Rebuilt as an inverted pyramid: hero health band → 4-card primary KPI row → top drift findings →
  collapsed secondary usage-signal disclosure. Drift rows now carry a severity icon.

### `src/token-audit/components/Coverage.vue`, `Drift.vue`, `Stores.vue`

- Tier/family coverage rows gained the 80%-threshold comparison. Signal chips (a/b/c/d) show a
  filled tick instead of colour-only "on" state, with a one-line legend. Drift cards and the Stores
  orphan badge gained severity/warning icons.

### `src/components/MaterialIcon.vue`

- Added `warning` and `error` to the icon whitelist (needed by the status-icon work above).

## Verified against

Browser-checked all 5 tabs (screenshots + `read_page`) at desktop and mobile widths, console clean.
`npm run token:audit` and `npm test` both run clean of new regressions — the one pre-existing
`export-handoff --story --verify` failure (spec drift on unrelated components) was confirmed present
before this change too.
