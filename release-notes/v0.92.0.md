# Release Notes — v0.92.0

**Date:** September 2026
**Milestone:** Design harness Level 1 story coverage pushed from 53.8% to 71.7% (19 new component stories), plus a CI workflow that finally enforces the harness gates on every PR

---

## Highlights

- **CI enforces the harness, not just the ledger.** A `.github/workflows/design-harness.yml` workflow now runs `npm test`, the full cross-store token sweep (`harness test all`), and the SSR render/crash gate (`harness:render`) on every PR and push to `main`. Previously all three only ran when someone remembered to run them locally — the exact gap that let REG-RETRO02/04 quietly resurface once already.
- **19 new component stories close the biggest L1 blind spot.** A full audit found true story coverage was 57/106 (53.8%), not the 100% or 73% earlier estimates — almost the entire gap was in `home/`, `checkout/`, and `steps/` subdirectories, which prior counts missed entirely. Stories were added for `HomeCategoryCards`, `HomeFaq`, `HomeNewsletter`, `HomePromoTiles`, `HomeSteps`, `InlineCheckoutCta`, `PcCard`, `StepCard`, `StepDetails`, `StepGamerId`, `StepPayment`, `StepZipCode`, `CheckoutStepBody`, `CheckoutStepFooter`, `InfoStepBody`, `InfoStepFooter`, `PaymentStepBody`, `PaymentStepFooter`, and `PageSignInSection`, bringing coverage to 76/106 (71.7%).
- **Three real bugs surfaced by the new coverage, not injected by it.** Writing stories for components that never had one exposed genuine defects the harness is designed to catch:
  - `HomeSteps.vue` referenced `--x-wash-home-step-*` / `--x-home-step-ink-*` tokens that only existed in `codashop.css` — every other store theme would have rendered it unstyled. Fixed with fallbacks.
  - Five checkout components (`InlineCheckoutCta`, `StepDetails`, `StepGamerId`, `StepPayment`, `StepZipCode`) read `strings.*` namespaces that only exist on inline-checkout stores (Codashop, Diablo Immortal, ZZZ), unguarded — harmless in production, but crashed under the render gate's `codm` context. Fixed with optional chaining (same defect class as `REG-MTLE46R0`).
  - `useCountdown.js` started a real `setInterval` during `setup()`, a phase Vue's SSR `renderToString()` also executes (unlike `onMounted`, which SSR skips) — any story with a live countdown hung `harness:render` indefinitely. Fixed with an SSR guard; logged as `REG-MTMDWW1L`.

## Changes

### `.github/workflows/design-harness.yml` (new)

- Runs on every `pull_request` and `push` to `main`: `npm ci` → `npm test` → `npm run harness -- test all` → `npm run harness:render`. All three already exit non-zero on failure, so no new plumbing was needed to make them block a merge.

### Design harness coverage

- 19 new `.stories.js` files under `src/library/stories/`, auto-discovered via the existing `import.meta.glob` registry — no manual registration needed.
- Matching handoff specs exported to `docs/Handoff/components/<slug>/` for all 19.
- `audits/regressions-log.json` gained one new entry (`REG-MTMDWW1L`) for the SSR countdown-timer hang, so future sessions get warned via `harness:compound --check`.

### Component fixes

- `src/components/home/HomeSteps.vue` — token fallbacks for store themes that don't define the codashop-only wash/ink tokens.
- `src/components/checkout/{InlineCheckoutCta,StepDetails,StepGamerId,StepPayment,StepZipCode}.vue` — optional chaining on store-conditional string namespaces.
- `src/composables/useCountdown.js` — guard `start()` with `!import.meta.env.SSR`.
