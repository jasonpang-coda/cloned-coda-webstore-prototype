# Release Notes — v0.92.1

**Date:** September 2026
**Milestone:** COD:M download-banner App Store / Google Play badge fix and relocation

---

## Highlights

- **Badges are now content-gated.** `App.vue`'s download-banner badges previously rendered unconditionally whenever `strings.page.download` existed, falling back to a text pill when no label was supplied. They now render only when `appStoreLabel`/`googlePlayLabel` are actually present, so a store can omit either badge outright instead of getting a placeholder pill.
- **COD:M moves its badges above the banner.** A new `config.content.badgesAboveValueProps` flag (COD:M only) relocates the App Store / Google Play badges out of the download banner box and into the SEO value-prop section instead, right after the "Why Choose the COD:M Store" benefit grid. Every other store (ZZZ, Diablo Immortal) omits the flag and keeps the existing in-banner placement — zero component-level branching on store identity.

## Changes

### `src/App.vue`

- `.download-banner__badges` (in-banner) now gated on `!config.content?.badgesAboveValueProps && (appStoreLabel || googlePlayLabel)`; each `<a>` badge additionally gated on its own label so one badge can be omitted independently of the other.
- New `.download-banner__badges` block added to the SEO value-prop section (`seo-content`, right after `.seo-benefits`), gated on `config.content?.badgesAboveValueProps && (appStoreLabel || googlePlayLabel)` — reuses the existing badge markup/styling verbatim (semantic tokens, not banner-specific), so no new CSS was needed.

### `src/stores/codm/store.js`

- `config.content` gained `badgesAboveValueProps: true`.
- `strings.page.download` keeps its existing `appStoreLabel`/`googlePlayLabel`/`appStoreUrl`/`googlePlayUrl` fields, now rendering in the relocated position instead of the banner.
