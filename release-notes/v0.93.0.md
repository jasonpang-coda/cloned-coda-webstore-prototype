# Release Notes — v0.93.0

**Date:** September 2026
**Milestone:** Shared component primitives — `Button`, `AccordionHeader`/`AccordionPanel`, and `ListItem` — extracted from real, duplicated markup and migrated across ~35 consumer files

---

## Highlights

- **A real `Button` primitive, grounded in what the codebase actually does.** Six variants (`primary`, `secondary`, `tertiary`, `link`, `icon`, `chip`), each written against real usage rather than guessed — `tertiary` and `chip` in particular were rebuilt mid-migration once the first real outline/chip consumer contradicted the initial guess. Migrated: every icon-only close button, `BuyNowBar`, the checkout/payment/info step footers, `ClaimGiftSheet`/`TaskGiftSheet`'s CTAs, `SignInSheet`'s per-flow buttons, `PromoCode`'s apply/remove controls, `SkuImageCard`/`BundleSkuCard`'s info icons, and `FilterTabs`.
- **`AccordionHeader` + `AccordionPanel`.** The "sanctioned accordion pattern" — a rotating chevron plus a `grid-template-rows: 0fr→1fr` height transition — was independently duplicated identically in three places (`HomeFaq`, `ItemSummaryAccordion`, `PromoCode`'s head) before this extraction. Split into a trigger component and a panel component, composed together, matching how nothing else in the codebase couples them either.
- **`ListItem`.** A full-width selectable row primitive, grounded in the two real row families found (`LanguageSelectorSheet`'s padded/rounded/hover-bg row, `AccountPopover`'s plain leading-icon row). Migrated both `LanguageSelectorSheet` and `RegionSelectorSheet` (which turned out to have two differently-styled rows under the same class name — now genuinely unified) plus `AccountPopover`'s transaction-history link.
- **A CI workflow gap closed along the way:** `FilterTabs` was discovered to have never had a story (missed in the earlier coverage push) — added one before trusting its migration.

## Real bugs caught during migration (not introduced by it)

- `Button`'s `shimmer` prop was only adding the CSS modifier class, not the required base `.fx-shimmer` class — would have silently never animated on every hero CTA.
- A CSS cascade bug in `ClaimGiftSheet`: a shared base class's `--btn-bg` custom property would have silently overridden the `brand` prop's color on the EA/Konami sign-in buttons. Caught and fixed before shipping, verified live (EA button renders correctly on the FC Mobile theme).
- A slot-composition bug in `AccordionHeader`: passing multi-element content into the default slot would have wrapped it in a single flex-item span, breaking `ItemSummaryAccordion`'s thumb+content row layout. Added a `#content` override slot before it shipped.
- Several stale hand-pinned tokens in `.stories.js` files, left over from before the primitives existed, were cleaned up — the static token scanner can't see through a dynamically-constructed `var()` name, so the fallback now lives as a literal string inside `Button.vue` where the scanner can verify it.

## Deliberately out of scope (not gaps)

- `NavBar`'s logo/locale/avatar buttons — genuinely bespoke (`<img>`/`FlagTile` leading content), left as one-offs per explicit decision.
- `CategoryNav`'s tabs (animated underline indicator, L1/L2/L3 tiers) and `PlayerAccount`'s segmented chip group (shared borders between siblings) — both too structurally bespoke to generalize without breaking encapsulation.
- `NavDrawer`'s indented L1/L2/L3 nav rows and `ResellerBanner`'s disclosure toggle — real structural differences from the `ListItem`/`AccordionHeader` shapes, not migrated this round.

## New files

- `src/components/Button.vue`, `src/components/AccordionHeader.vue`, `src/components/AccordionPanel.vue`, `src/components/ListItem.vue`
