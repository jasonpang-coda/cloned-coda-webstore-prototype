# Release Notes — v0.96.0

**Date:** September 2026
**Milestone:** PM Ideation Sandbox (Milestone 1 / Foundation) — an on-demand exporter that stamps a self-contained, throwaway bundle of real curated components + one store's data for a PM's own agent to compose page ideas in, without touching this repo

---

## Highlights

- **`tools/sandbox/export-sandbox.mjs`** — `node tools/sandbox/export-sandbox.mjs <dest-dir> [--store <key>]` stamps a fully self-contained Vite project at `<dest-dir>`: real curated components (not mocked), the chosen store's real data + theme, the read-only design-token cascade, a ported guardrail linter, and a trimmed agent ruleset. `src/` stays the single source of truth — the exporter snapshots a fresh closure every run; nothing durable is created in this repo, and re-running with a different `--store` targets any of the 12 stores.
- **Real components, not stubs.** Unlike the existing VitePress handoff kit (`docs/Handoff/_handoff-kit/`), which hand-mocks demo components against vendored tokens, the sandbox vendors the actual `.vue` files and their full transitive composable/directive/asset closure — a page composed in the bundle uses the exact same code as production.
- **Curated + bounded scope.** `tools/sandbox/curated.manifest.mjs` declares a seed list of presentational primitives and SKU display cards (`Grid`, `Span`, `Button`, `SkuCard`, `BundleGrid`, `CategoryBanner`, home/* sections, etc.) plus a hard boundary rule: the exporter throws loud and writes nothing if any curated component's closure (or the seed list itself) reaches into checkout/payment internals, nav chrome, or overlay sheets.
- **Guardrail CLI (`npm run lint` inside a bundle).** A trimmed port of this repo's `tools/preflight.mjs` — same hardcoded-color / unknown-token / `@container`-only checks, scoped to the agent's own authored pages under a bundle's `src/`, never the vendored components.
- **`catalog.json`** — parsed straight from the existing `docs/Handoff/components/*/spec.md` files (resolved to the chosen store's column), giving the agent a machine-readable prop/variant/state/token reference with no need to read component source.
- **`AGENTS.md` + `ruleset/*.md`** — a trimmed, path-independent distillation of this repo's token/component/whitelabel discipline, scoped to what actually applies when composing a page from existing components in an isolated single-store bundle.

## Verification

Milestone plan and full QA log: `/Users/yiwei/.claude/plans/majestic-noodling-teapot.md` (9/9 QA cases passing, including an end-to-end agent-loop smoke test — an isolated subagent, scoped strictly to an exported bundle with no visibility into this repo, read `AGENTS.md`/`catalog.json`, composed a new "Flash Sale" page from real components, and self-corrected to a clean lint; independently re-verified afterward, including a byte-diff of a vendored component against the real source).

Five real bugs were found and fixed during the QA pass itself:
- Catalog generation assumed a `spec.json` sibling that doesn't exist anywhere in this repo (only `spec.md`) — rewrote to parse markdown directly.
- A regex double-escaping bug silently zeroed out every component's resolved token contract in `catalog.json`.
- The boundary rule only checked transitively-imported files, not the curated seed list itself — a component added straight to `CURATED_COMPONENTS` bypassed it entirely. Fixed, and validation now runs before any disk writes (a violation leaves nothing on disk).
- The bundle template's `package.json` was missing the `@material-symbols/svg-400` dependency `MaterialIcon.vue` needs, breaking the build.
- A `*/` inside a JS comment in the guardrail's own source closed the block comment early and crashed it at runtime.

## Out of scope (deferred to a later milestone)

A hosted/Vercel-deployable canvas, in-bundle multi-store switching, multi-artboard editing UI, npm-registry publishing, and auto-generating the ruleset from the full skill files instead of hand-authoring it.
