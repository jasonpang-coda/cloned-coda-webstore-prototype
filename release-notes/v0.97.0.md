# Release Notes — v0.97.0

**Date:** September 2026
**Milestone:** PM Ideation Sandbox — Milestone 2: multi-store bundle switching, manifest-driven ruleset auto-generation, and a git-installable `@coda/sandbox-kit` packer/publisher

---

## Highlights

- **Multi-store bundles.** `export-sandbox.mjs`'s `--store` flag now accepts a comma-separated list (`--store codm,fcm`), still defaulting to `codm` alone. A bundle vendoring more than one store gets a live runtime switcher in `CanvasHost.vue` (a plain `<select>` mirroring the real repo's own `DeviceToolbar.vue`) — verified in-browser to actually re-theme the composed page instantly, no reload, using the exact same reactive `useTheme()` propagation the real app uses. A single-store bundle is unchanged from Milestone 1 — no switcher renders.
- **Shared vendoring lib.** The closure-walk, boundary-rule, token/store-copying, and markdown-section-extraction logic that used to live inline in `export-sandbox.mjs` is now `tools/sandbox/lib/{vendor,markdown,naming}.mjs` — both the bundle exporter and the new kit packer call the same code instead of duplicating it.
- **Ruleset auto-generation.** `tools/sandbox/ruleset.manifest.mjs` names exactly which headings to pull, verbatim, from the real `web-store-tokens`/`web-store-components`/`web-store-whitelabel`/`web-store-fe` skill files; `generate-ruleset.mjs` extracts them and writes the sandbox's `ruleset/*.md` + `AGENTS.md`'s hard-rules block, so they can no longer silently drift from the source doctrine. `generate-ruleset.mjs --check` is a drift gate (non-zero exit if a doc is stale) — new npm scripts `sandbox:ruleset` / `sandbox:ruleset:check`.
- **Git-installable kit.** `pack-kit.mjs` builds an installable `@coda/sandbox-kit` package folder — the same curated component/composable/token vendoring as a bundle, but for **all** discovered stores by default and with no canvas-app scaffold (ships raw, unbundled `.vue` source for a consumer's own Vite build to compile — a new pattern in this repo; every other `packages/*` workspace member ships a pre-bundled `dist/`). `publish-kit.mjs` packs fresh content directly into a clone of a separate git remote and commits it, mirroring this repo's own established `@coda/comment-kit`/`@coda/track-kit` pattern (real separate repos installed via `git+https`, not a registry) — it stops before pushing, printing the exact `git push` command.

- `npm test` 29/29 green throughout; no changes outside `tools/sandbox/` + this package.json's three new `sandbox:*` scripts.

Five real bugs were found and fixed during the QA pass:
- The Milestone-1 `*/`-inside-a-JS-comment footgun recurred twice more in new files (`lib/markdown.mjs`, `lib/vendor.mjs`) — both crashed at runtime; reworded to avoid the literal substring.
- A markdown-extraction over-capture: pulling `web-store-tokens`' "2b" section swallowed a nested `### Authoring discipline` subsection it doesn't logically belong to (a token-*definition* concern, not the "stop and ask before consuming" rule 2b is actually about) — added a `stopBefore` truncation option.
- `pack-kit.mjs`'s `package.json` `files` field was a hand-maintained literal list that omitted `utils/`, silently breaking `stores/codm/milestone.js`'s import of it in every real install — fixed by computing `files` from what's actually on disk after vendoring, not a list that can drift.
- Packing directly into an existing git clone (for `publish-kit.mjs`) leaked `.git` itself into that same `files` computation — excluded explicitly.
