# Release Notes — v0.98.1

**Date:** September 2026
**Milestone:** Regression-test coverage for `tools/sandbox/` — converts a session's manual QA into permanent, automated coverage

---

## Highlights

- **`lib/vendor.mjs` throws instead of calling `process.exit()` directly.** `assertNotExcluded` (the boundary rule) and `copyTokens`'s missing-theme-file check now throw a plain `Error` — `export-sandbox.mjs` and `pack-kit.mjs` are the single place that catches it and turns it into a printed message + exit code, same CLI behavior as before. This is what makes the boundary rule unit-testable in-process (a test can `assert.throws()` it without killing the test runner) instead of only testable via a subprocess.
- **Five new test files**, all wired into the existing `npm test` suite:
  - `tests/sandbox-syntax.test.mjs` — runs `node --check` over every `.mjs`/`.js` file under `tools/sandbox/`. Directly locks the class of bug that shipped 3 separate times across the PM Ideation Sandbox's two milestones: a literal `*/` inside a multi-line doc comment (e.g. a prose path like `docs/Handoff/components/*/spec.md`) closes the comment early and crashes the file at runtime — this is a genuine syntax error, so Node's own parser catches the whole bug class with no custom regex needed.
  - `tests/sandbox-markdown.test.mjs` — unit tests for `section()`/`tableCells()`/`truncateBeforeHeading()`/`parseSpecMd()`, including direct regression fixtures for the double-escape bug that once silently zeroed every component's token contract, and the nested-subheading overflow that once pulled unrelated content into a ruleset doc.
  - `tests/sandbox-vendor.test.mjs` — locks the boundary-rule gap where an excluded component added directly to `CURATED_COMPONENTS` (not just reached transitively) bypassed the check entirely.
  - `tests/sandbox-export.test.mjs` — integration tests: a real `export-sandbox.mjs` run produces a complete single- and multi-store bundle with the right files and `active-stores.js` shape; an unknown store is rejected with nothing written; a non-empty destination is refused.
  - `tests/sandbox-pack-kit.test.mjs` — integration tests locking the two real packaging bugs found during Milestone 2 QA: a hand-maintained `package.json` `files` list that silently dropped `utils/` (several store modules import it), and `.git` leaking into that same list when packing directly into an existing clone (as `publish-kit.mjs` does).

## Verification

`npm test` — 46/46 passing (29 pre-existing + 17 new). Each new test file's regression fixture was spot-checked by temporarily reintroducing the actual historical bug and confirming the test fails with the expected message, then reverting.
