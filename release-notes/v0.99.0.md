# Release Notes — v0.99.0

**Date:** September 2026
**Milestone:** Sprint-retro `--actionable` field, plus reusable Figma plugin-scripting reference docs

---

## Highlights

- **`tools/retro.mjs` gains an `--actionable` field.** A retro lesson (`--lesson`) records what to *remember*; the new optional `--actionable` records what to *do about it* — a doc to write, a script to patch, a guard to add. Printed alongside the lesson and persisted in the ledger schema (`audits/retro-ledger.json` entries now carry an `actionable` key, `null` when omitted). `.claude/skills/sprint-retro/SKILL.md` updated to instruct deciding an actionable for every Improve item, and executing it inline in the same session when it's not purely a future-session reminder.
- **Two new Figma plugin-scripting reference docs**, written after importing a Button + SkuCard component pair into a Figma library via `use_figma`:
  - `docs/figma-code-connect/token-map-codashop.md` — the CSS custom property → Figma variable name cross-reference for Button (primary variant) and SkuCard, so a future component import doesn't re-derive it from source.
  - `docs/figma-code-connect/plugin-script-notes.md` — durable process notes: the `ALL_FILLS` scope-conflict gotcha, dry-running an unverified API option before a large data-driven `use_figma` call, the "published library ≠ current local state" trap (publishing needs a manual UI click, unreachable from the Plugin API), reusable `bindFill`/`text()` helper snippets, and screenshotting new component work against the store's actual page background rather than Figma's default white canvas.

## Verification

`node tools/retro.mjs --lesson "test" --category process --actionable "test actionable" --dry-run` — confirms the new field prints and serializes correctly without touching the committed ledger.
